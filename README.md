# 동구 대형폐기물 접수·수거 관리 시제품

전화 접수부터 수거·마감까지 한 흐름으로 처리합니다.

```
PC: 전화 접수 → 위치 지정 → 노선 계산·배정 → 암호화 분할 QR 표시
휴대폰: QR 수신 → 연락·방문·품목 확인·수수료 계산·사진·수거 결과 (오프라인)
휴대폰 → PC: 암호화 결과 파일(업무 메일) · 암호화 사진 파일(보안 매체)
PC: 결과 병합·충돌 검토·사진 회수 → 일일 마감
```

> **시제품입니다. 가상 자료로 시험하세요.** 실제 주민 정보로 쓰기 전에 아래 "운영 전 확인"을 마쳐야 합니다.

## 구성

| 부분 | 내용 | 실행 |
| --- | --- | --- |
| **휴대폰 앱** (`web/`) | Android·아이폰 공통 PWA. 서버에 자료를 두지 않음 | https://lanian.github.io/donggu-waste/ → 홈 화면에 추가 |
| **PC 프로그램** (`pc/`) | 접수·배정·노선·QR 전송·결과 병합·충돌함·사진 회수·마감 화면. 이 PC(127.0.0.1)에서만 열림 | `python pc/pc_tool.py serve` |
| **수수료표** (`data/`) | 공식 [별표 1] 원문 HWP와 변환본 169행 | `tools/convert_fee_hwp.py` |

휴대폰 앱은 처음 실행할 때 **PC와 연결해서 사용(권장)** 또는 **이 휴대폰만으로 사용** 중 하나를 고릅니다.

## PC 프로그램 설치·실행

```bash
pip install -r pc/requirements.txt
python pc/pc_tool.py init     # 암호화 DB와 PC 키 생성 (처음 한 번)
python pc/pc_tool.py serve    # 브라우저에서 http://127.0.0.1:8765
```

처음 열면 업무 비밀번호(10자 이상)를 정합니다. 그다음 순서는 아래와 같습니다.

1. **설정**: 휴대폰 등록(등록 QR → 기기 코드 붙여넣기 → 6자리 지문 대조), 수거팀·차량(적재 m³, 근무시간)과 휴대폰 연결, 차고지 좌표
2. **접수**: 전화 접수 등록. 같은 연락처·주소는 중복 후보로 경고(자동 병합 없음), 수정은 사유 필수·버전 보존, 취소도 사유와 함께 기록. 지도를 눌러 배출 위치 지정(주소 검색 없음)
3. **배정·노선**: 날짜·팀 선택 → [노선 계산](OR-Tools). 방문 약속 시간, 오늘 필수 포함, 우선순위, 적재 추정치, 근무시간 반영. 미배정 건은 사유 표시. 순서 바꾸기·팀 이동 후 [배정 확정]
4. **목록 전송**: [QR 표시] → 휴대폰 [오늘 목록 받기] → 휴대폰의 수신 확인 코드를 입력해야 "수신 확인"
5. **결과 가져오기**: 결과 파일(.dgr)·사진 파일(.dgp) 넣기 → 보관 종료·사진 회수 확인 코드를 휴대폰에 알려 줌. 오래된 배정·취소된 접수의 결과는 **충돌함**에서 사유와 함께 반영/거부
6. **일일 마감**: 결과 미회수·재방문 후보(약속 날짜 포함)·금액 확인 대기·수납 확인 필요·사진 미회수·충돌을 확인하고, 하차 기록(반입지·부피·중량)을 남긴 뒤 마감 기록(미처리는 이월)
7. **수납 기록**(접수 상세): 담당자가 확인한 납부·환불을 기록. 계산 금액과 납부 금액을 따로 보여 주고 미납·부족·과납 확인 필요를 표시. 정정은 지우지 않고 사유 기록
8. **QR 실측**: 기관 휴대폰으로 가상 20·50·100건, 주소 길이, 조각 크기, 오류 복원, 표시 속도별 전송 시간·인식률 측정. 휴대폰은 실측 모드로 받고 저장하지 않음
9. **설정 → 적재량 보정**: 자주 쓰는 품목의 1단위 부피 추정치 옆에 실측 보정값 입력(노선 적재 제약에 사용)

노선 계산은 25m 안의 접수를 같은 장소로 묶어 연속 방문하게 하며, 접수·수수료·완료는 건별로 유지합니다.

## 휴대폰 앱 사용

- **PC 연결 방식**: 기기 등록 → 오늘 목록 받기 → 상세(이름·연락처·주소 크게, 전화하기, 연락 결과, 통화로 약속한 재방문 날짜·시간) → 품목 확인·현장 추가(즐겨찾기·자주 쓴 품목 바로 선택)·수량·수수료 → 사진 → 수거 결과 → 결과 보내기(업무 메일) → 사진 파일 만들기(보안 매체) → 각 확인 코드 입력
- **단독 방식**: 전화 접수 등록 → 날짜별 목록·방문 순서 → 현장 처리 → **매일 암호화 백업**(24시간 지나면 경고)
- 지도: 방문 지점 핀, 배출 위치 지정. 설정에서 끌 수 있음

## 보안·개인정보

| 항목 | 방식 |
| --- | --- |
| PC 저장 | SQLCipher로 DB 파일 전체 암호화. DB 키는 운영체제 키 저장소(또는 시작 시 입력). PC 개인키도 DB 안에 보관 |
| PC 화면 | 127.0.0.1에만 열림, Host 검사, 업무 비밀번호(scrypt), 세션 쿠키(HttpOnly·SameSite=Strict, 30분), CSRF 헤더 필수, 접근 로그 미기록 |
| 휴대폰 저장 | IndexedDB 레코드별 AES-GCM, 데이터 키는 PIN(PBKDF2 60만 회)으로 감쌈, 자동 잠금, 사진은 갤러리에 남지 않음 |
| 전송 | 묶음마다 새 ECDH P-256 키 → HKDF → AES-256-GCM, ECDSA 서명. 복호화 키는 QR에 없음. 조각 누락·중복·혼합·변조·다른 기기·오래된 버전 거부. 압축 형식 v2(품목은 수수료표 ID로, 가상 20건 약 2.9KB·QR 5장) |
| 결과 파일 | 이름·연락처·주소·메모 없음, PC만 열 수 있음. 같은 이벤트는 한 번만 반영 |
| 사진 | 결과 파일과 분리, 암호화 사진 파일로 보안 매체 회수, PC가 해시 대조 후에만 회수 확인 코드 발급 → 그 뒤에만 휴대폰에서 삭제 가능 |
| 외부 통신 | 휴대폰·PC 화면 모두 바탕 지도 서버(tiles.openfreemap.org) 하나만. 이름·연락처·주소·핀 좌표는 보내지 않고 주소 검색·길찾기 API 미사용. 지도 조각은 줌 14(약 2km 단위)까지만 요청 |
| 분실 기기 | PC에서 "분실 처리" → 그 기기로 목록 전송 불가, 결과 거부. 오프라인 기기의 원격 삭제는 약속하지 않음 |

## 수수료표

- 원문: `data/source/별표1_대형폐기물_품목_및_수수료_기준.hwp` (2026-11-02 제공, sha256 `2d8b66ef…`)
- 변환: `python tools/convert_fee_hwp.py <hwp> --checked-on YYYY-MM-DD` → `data/fee_table.json` → `python tools/build_fee_js.py`
- 169행(원문 168 + 20ℓ당 각주), 부과단위 11종을 보존하고 서로 합산하지 않음
- 원문 규격이 겹치거나 단위가 불명확한 **8행은 "규격 확인 필요"** → 금액 확인 대기(최저가 자동 선택 없음): 대리석 식탁 6인용 경계, 물탱크 용적 단위(㎡), 싱크대 1짝/폭 1m, 오락기·고무통 규격 겹침
- 표에 없는 품목은 0원이 아니라 금액 확인 대기. 시행일은 원문에 없어 비어 있음

## 운영 전 확인

- 수수료표 시행일과 "규격 확인 필요" 8행의 담당 기준, 2인 대조
- 업무용 휴대폰 기종·MDM, PC 운영체제(SQLCipher·키 저장소 동작), PC에서 휴대폰 화면 QR 촬영·자료 반출입 기준
- 결과 파일을 보낼 업무 메일 경로와 사진 파일용 보안 매체(휴대폰에서 열리는지) 승인
- 외부 지도 서비스 이용 승인, 앱 코드 호스팅(기관 도메인) 승인과 배포 계정 통제
- 차량 대수·적재·근무시간, 차고지·반입지 좌표, 로컬 OSRM(실제 도로 시간) 구축 여부
- 사진·백업 보관 위치와 기간, 키·비밀번호 보관 책임자

## 알려진 제한

- 노선 이동시간은 로컬 OSRM이 없으면 **직선거리 추정**(화면에 표시). 반입지 경유·실시간 교통·현장 재최적화는 없음
- 적재 부피는 품목별 추정치에 담당자 보정값을 더한 것. 휴대폰에서 하차를 직접 기록하지는 않음(PC에서 입력)
- 수납은 담당자 확인 기록이며 온라인 결제는 없음. 계산 금액은 수납 완료를 뜻하지 않음
- 웹 앱의 키는 하드웨어 보안 영역에 묶이지 않음. 브라우저 데이터 삭제 시 휴대폰 미전송 기록 소실
