# 동구 대형폐기물 접수·수거 관리 시제품

전화 접수부터 수거·마감까지 한 흐름으로 처리합니다.

```
PC: 전화 접수 → 위치 지정 → 노선 계산·배정 → 암호화 분할 QR 표시
휴대폰: QR 수신 → 연락·방문·품목 확인·수수료 계산·사진·수거 결과 (오프라인)
휴대폰 → PC: 암호화 결과 파일(업무 메일) · 암호화 사진 파일(보안 매체)
PC: 결과 병합·충돌 검토·사진 회수 → 일일 마감
```

> **시제품입니다. 가상 자료로 시험하세요.** 실제 주민 정보로 쓰기 전에 아래 "운영 전 확인"을 마쳐야 합니다.

## 구성

| 부분 | 내용 | 실행 |
| --- | --- | --- |
| **휴대폰 앱** (`web/`) | Android·아이폰 공통 PWA. 서버에 자료를 두지 않음 | https://lanian.github.io/donggu-waste/ → 홈 화면에 추가 |
| **PC 프로그램** (`pc/`) | 접수·배정·노선·QR 전송·결과 병합·충돌함·사진 회수·마감 화면. 이 PC(127.0.0.1)에서만 열림 | `python pc/pc_tool.py serve` |
| **수수료표** (`data/`) | 공식 [별표 1] 원문 HWP와 변환본 169행 | `tools/convert_fee_hwp.py` |

휴대폰 앱은 처음 실행할 때 **PC와 연결해서 사용(권장)** 또는 **이 휴대폰만으로 사용** 중 하나를 고릅니다.

## PC 프로그램 설치·실행

```bash
pip install -r pc/requirements.txt
python pc/pc_tool.py init     # 암호화 DB와 PC 키 생성 (처음 한 번)
python pc/pc_tool.py serve    # 브라우저에서 http://127.0.0.1:8765
```

처음 열면 **운영 관리자 계정**(아이디 + 10자 이상 비밀번호)을 만듭니다. v0.5 이하의 단일 업무 비밀번호는 `admin` 계정으로 자동 이전됩니다. 첫 화면은 **오늘 현황**(완료·진행·재방문·하차 합계, 처리할 일, 팀별 진행)입니다.

| 역할 | 할 수 있는 일 |
| --- | --- |
| 운영 관리자 | 전체 + 설정·휴대폰 등록·사용자·변경 이력·백업 |
| 접수 담당자 | 접수·배정·목록 전송·결과·충돌·수납·마감 |
| 수거팀 | 조회, 결과·사진 가져오기, 하차 기록, QR 실측 |

사용자는 **사용자·이력** 화면에서 임시 비밀번호로 추가하며, 첫 로그인 때 비밀번호를 바꾸게 됩니다. 계정은 지우지 않고 중지합니다. 서버가 역할별로 API를 막고(403), 모든 변경 이력에 작업자가 남습니다.

1. **설정**: 휴대폰 등록(등록 QR → 기기 코드 붙여넣기 → 6자리 지문 대조), 수거팀·차량(적재 m³, 근무시간)과 휴대폰 연결, 차고지 좌표
2. **접수**: 전화 접수 등록. 같은 연락처·주소는 중복 후보로 경고(자동 병합 없음), 수정은 사유 필수·버전 보존, 취소도 사유와 함께 기록. 지도를 눌러 배출 위치 지정(주소 검색 없음)
3. **배정·노선**: 날짜·팀 선택 → [노선 계산](OR-Tools). 방문 약속 시간, 오늘 필수 포함, 우선순위, 적재 추정치, 근무시간 반영. 미배정 건은 사유 표시. 순서 바꾸기·팀 이동 후 [배정 확정]
4. **목록 전송**: [QR 표시] → 휴대폰 [오늘 목록 받기] → 휴대폰의 수신 확인 코드를 입력해야 "수신 확인"
5. **결과 가져오기**: 결과 파일(.dgr)·사진 파일(.dgp) 넣기 → 보관 종료·사진 회수 확인 코드를 휴대폰에 알려 줌. 오래된 배정·취소된 접수의 결과는 **충돌함**에서 사유와 함께 반영/거부. 메일이 막히면 휴대폰의 결과 QR을 PC 웹캠으로 읽기(역방향 QR)
6. **일일 마감**: 결과 미회수·재방문 후보(약속 날짜 포함)·금액 확인 대기·수납 확인 필요·사진 미회수·충돌을 확인하고, 하차 기록(반입지·부피·중량)을 남긴 뒤 마감 기록(미처리는 이월)
7. **수납 기록**(접수 상세): 담당자가 확인한 납부·환불을 기록. 계산 금액과 납부 금액을 따로 보여 주고 미납·부족·과납 확인 필요를 표시. 정정은 지우지 않고 사유 기록
8. **QR 실측**: 기관 휴대폰으로 가상 20·50·100건, 주소 길이, 조각 크기, 오류 복원, 표시 속도별 전송 시간·인식률 측정. 휴대폰은 실측 모드로 받고 저장하지 않음
9. **설정 → 적재량 보정**: 자주 쓰는 품목의 1단위 부피 추정치 옆에 실측 보정값 입력(노선 적재 제약에 사용)
10. **설정 → 반입지·종료지**: 반입지 좌표를 넣으면 적재가 찰 때 반입지에 들러 비우고 이어서 수거하는 순서를 추천(차량당 최대 횟수·하차 시간). 확정한 경유 위치는 휴대폰 목록에도 표시. 종료지를 따로 두면 그곳까지 계산
12. **설정 → 주소 위치 자료**: 행정안전부 도로명주소 위치정보요약DB를 미리보기(열 배치·표본 위치 확인) 후 가져오면 접수 화면 [주소로 위치 찾기], 배정 화면 [위치 없는 접수 주소 자료로 찾기]가 이 PC 안에서 동작(UTM-K → 위도·경도 변환, 외부 전송 없음)
13. **수수료표**: 원문 표·적용 버전·시행일·확인자·승인자, 확인 필요 8행의 확정 단가와 근거를 개정안으로 저장 → 작성자와 다른 담당자가 승인 → 시행일부터 새 접수와 휴대폰 목록에 적용(기존 접수 원본은 그대로)
11. **설정 → 백업·사진 보관**: 별도 백업 비밀번호(12자 이상)로 암호화한 백업 파일 만들기·열어 확인, 회수한 사진 보관 기간(기본 90일)이 지나고 처리가 끝난 접수의 사진 정리(해시·시각은 남김)

14. **통계·보고서**: 기간(오늘·최근 7일·이번 달·지난달) 집계 — 접수·완료율·재방문·계산 금액·납부 기록·확인 필요, 날짜별 막대(표로 보기), 많이 나온 품목, 팀별 완료율. 이름·연락처·주소 없는 **접수별·날짜별 CSV**(엑셀용)
15. **배차표 인쇄**(목록 전송 화면): 팀별 순서·신청인·품목·금액·하차 지점, 연락·수거 체크 칸. 개인정보가 들어 있어 파쇄 안내와 출력 이력 기록
16. **휴대폰 단독 방식 자료 옮기기**(결과 가져오기 화면): 단독 휴대폰의 암호화 백업(.dgb)을 백업 비밀번호로 열어 접수·수정 이력·현장 기록·사진·하차를 PC 원본으로(이미 있는 접수는 덮어쓰지 않음, 같은 파일은 한 번만)

17. **유사 품목 적용**(접수 상세 → 현장 결과): 표에 없어 확인 대기인 품목을 단가가 확정되고 부과단위가 같은 행에 연결. 적용 근거·확인자를 남기고 원래 품목 행은 그대로, 해제도 사유와 함께
18. **관할 확인**: 주소의 구 이름이 관할(설정, 기본 동구)과 다르면 접수·목록에서 경고(막지는 않음)
19. **배정 조정 사유**: 추천 순서·팀을 손으로 바꾸면 확정할 때 사유를 적고, 배정 이력에 남음

수거팀 계정은 **팀에 연결**합니다(사용자·이력 화면). 연결한 팀에 배정된 접수·배차표·하차·마감만 보이고, 그 팀 휴대폰의 결과·사진 파일만 가져올 수 있습니다.

접수 목록: 입력하는 대로 찾기, 빠른 거르기(오늘 예정·위치 없음·금액 확인 대기·미배정), 단축키 `/` 찾기 · `N` 새 접수 · `Ctrl+Enter` 저장.

접수 목록과 품목 검색은 **초성**도 됩니다(예: `ㅈㄹ` → 장롱, `ㄱㅅㅎ` → 가상하나).

### 명령

```bash
python pc/pc_tool.py backup                  # 암호화 백업 (백업 비밀번호 입력)
python pc/pc_tool.py restore <파일.dgbak>    # 업무 화면을 끄고 실행. 기존 DB는 옆에 보관
python pc/pc_tool.py reset-admin             # 관리자 비밀번호 분실 시 (DB 키가 있어야 열림)
python pc/pc_tool.py purge-photos            # 보관 기간 지난 사진 정리
python pc/pc_tool.py import-addr <파일·폴더> --region 동구 [--preview]   # 주소 위치 자료 가져오기
python pc/pc_tool.py import-solo <백업.dgb> [--crew 팀이름] [--preview] # 휴대폰 단독 방식 자료 옮기기
```

노선 계산은 25m 안의 접수를 같은 장소로 묶어 연속 방문하게 하며, 접수·수수료·완료는 건별로 유지합니다.

## 휴대폰 앱 사용

- 현장 메모 남기기, 사진을 특정 품목에 묶기(선택), 같은 품목을 다시 추가하면 "기존 행에 더하기 / 따로 한 줄 더" 선택(어느 쪽이든 기록 보존)
- 상세 화면 위에 처리 단계(연락 → 품목 → 사진 → 결과, 끝난 단계 ✓), 설정에서 **큰 글씨**
- 단독 방식: [하차 기록], 설정에서 확인 필요 품목 단가를 근거와 함께 정하기(바꾼 이력 보존), 백업 파일로 나중에 PC로 옮기기
- 반입지에서 [하차 기록](시각·부피·중량) → 결과 파일로 PC 하차 기록에 반영
- 목록 위에 오늘 진행 띠(완료/전체), 방문 순서는 노선도처럼 이어서 표시, 6곳 이상이면 이름·주소·품목 찾기(초성 가능). 상세 화면 아래에 상태·전화·다음 지점 버튼 고정
- **PC 연결 방식**: 기기 등록 → 오늘 목록 받기 → 상세(이름·연락처·주소 크게, 전화하기, 연락 결과, 통화로 약속한 재방문 날짜·시간) → 품목 확인·현장 추가(즐겨찾기·자주 쓴 품목 바로 선택)·수량·수수료 → 사진 → 수거 결과 → 결과 보내기(업무 메일) → 사진 파일 만들기(보안 매체) → 각 확인 코드 입력
- **단독 방식**: 전화 접수 등록 → 날짜별 목록·방문 순서 → 현장 처리 → **매일 암호화 백업**(24시간 지나면 경고)
- 지도: 방문 지점 핀, 배출 위치 지정. 설정에서 끌 수 있음

## 보안·개인정보

| 항목 | 방식 |
| --- | --- |
| PC 저장 | SQLCipher로 DB 파일 전체 암호화. DB 키는 운영체제 키 저장소(또는 시작 시 입력). PC 개인키도 DB 안에 보관 |
| PC 화면 | 127.0.0.1에만 열림, Host 검사, 사용자별 계정(scrypt)·역할별 API 제한, 세션 쿠키(HttpOnly·SameSite=Strict, 30분), CSRF 헤더 필수, 접근 로그 미기록 |
| 휴대폰 저장 | IndexedDB 레코드별 AES-GCM, 데이터 키는 PIN(PBKDF2 60만 회)으로 감쌈, 자동 잠금, 사진은 갤러리에 남지 않음 |
| 전송 | 묶음마다 새 ECDH P-256 키 → HKDF → AES-256-GCM, ECDSA 서명. 복호화 키는 QR에 없음. 조각 누락·중복·혼합·변조·다른 기기·오래된 버전 거부. 압축 형식 v2(품목은 수수료표 ID로, 가상 20건 약 2.9KB·QR 5장) |
| 결과 파일 | 이름·연락처·주소·메모 없음, PC만 열 수 있음. 같은 이벤트는 한 번만 반영 |
| 사진 | 결과 파일과 분리, 암호화 사진 파일로 보안 매체 회수, PC가 해시 대조 후에만 회수 확인 코드 발급 → 그 뒤에만 휴대폰에서 삭제 가능 |
| 외부 통신 | 휴대폰·PC 화면 모두 바탕 지도 서버(tiles.openfreemap.org) 하나만. 이름·연락처·주소·핀 좌표는 보내지 않고 주소 검색·길찾기 API 미사용. 지도 조각은 줌 14(약 2km 단위)까지만 요청 |
| 백업 | SQLCipher 형식, DB 키와 다른 백업 비밀번호로 암호화. 복원 시 현재 DB 키로 다시 암호화하고 기존 DB는 지우지 않음 |
| 변경 이력 | 작업자·시각·대상·작업. 내용에는 사유·건수·코드만(이름·연락처·주소 없음). 화면에서 고치거나 지울 수 없음 |
| 분실 기기 | PC에서 "분실 처리" → 그 기기로 목록 전송 불가, 결과 거부. 오프라인 기기의 원격 삭제는 약속하지 않음 |

## 수수료표

- 원문: `data/source/별표1_대형폐기물_품목_및_수수료_기준.hwp` (2026-11-02 제공, sha256 `2d8b66ef…`)
- 변환: `python tools/convert_fee_hwp.py <hwp> --checked-on YYYY-MM-DD` → `data/fee_table.json` → `python tools/build_fee_js.py`
- 169행(원문 168 + 20ℓ당 각주), 부과단위 11종을 보존하고 서로 합산하지 않음
- 원문 규격이 겹치거나 단위가 불명확한 **8행은 "규격 확인 필요"** → 금액 확인 대기(최저가 자동 선택 없음): 대리석 식탁 6인용 경계, 물탱크 용적 단위(㎡), 싱크대 1짝/폭 1m, 오락기·고무통 규격 겹침
- 표에 없는 품목은 0원이 아니라 금액 확인 대기. 시행일은 원문에 없어 비어 있음

## 화면 원칙 (v0.9 디자인 검토 반영)

- 색 규칙(휴대폰·PC 같음): 녹색 = 완료, 노랑 = 사람이 봐야 함(확인 필요·재방문), 빨강 = 막힘·거부, 파랑 = 정보(처리 중·현장 추가), 회색 = 중립(취소 포함)
- 같은 일은 같은 말: 금액 확인 대기, 수거 완료, 보류, 재방문·보류, 하차 기록, ← 목록
- 휴대폰: 누르는 곳 56px 이상, 결과 저장 전에는 아래 단추가 "결과 저장 ↓", 지금 갈 곳 표시, 통화 뒤 연락 결과를 바로 묻기, 빠른 수량 누름도 빠지지 않음
- PC: 접수 양식은 전화 순서대로(신청자 → 물건 → 일정 → 위치), 저장 줄은 화면 아래 고정, Enter로 품목 추가, 초점 표시 강화, 알림은 오른쪽 위(오류는 눌러서 닫을 때까지)

## 알려진 제한

- 노선 이동시간은 로컬 OSRM이 없으면 **직선거리 추정**(화면에 표시). 실시간 교통·음성 길안내·현장 재최적화는 계획안대로 별도 범위
- 주소 위치는 건물 출입구 좌표(위치정보요약DB 기준). 실제 행안부 파일의 열 배치는 자동 인식하지만, 처음 가져올 때 미리보기로 표본 위치를 꼭 확인
- 적재 부피는 품목별 추정치에 담당자 보정값을 더한 것
- 휴대폰 단독 방식의 단가 확정은 그 휴대폰에만 적용(PC 개정·2인 승인과 별개). PC로 옮기면 접수 당시 단가가 그대로 들어감
- 수납은 담당자 확인 기록이며 온라인 결제는 없음. 계산 금액은 수납 완료를 뜻하지 않음
- 웹 앱의 키는 하드웨어 보안 영역에 묶이지 않음. 브라우저 데이터 삭제 시 휴대폰 미전송 기록 소실
