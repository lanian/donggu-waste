# 동구 대형폐기물 접수·수거 관리 시제품

전화 접수부터 수거·마감·세입 확인까지 한 흐름으로 처리합니다.

```
PC: 전화 접수 → 행정동·위치 지정 → 노선 계산·배정 → 암호화 분할 QR 표시
휴대폰: QR 수신 → 길안내·도착·연락·스티커 확인·품목·수수료·금액 고지·사진·수거 결과 (오프라인)
휴대폰 → PC: 암호화 결과 파일(업무 메일) · 암호화 사진 파일(보안 매체)
PC: 결과 병합·충돌 검토·사진 회수 → 일일 마감(담당자 기록 → 팀장 확인) → 수납·세입 대사·환불 결재
```

> **시제품입니다. 가상 자료로 시험하세요.** 실제 주민 정보로 쓰기 전에 아래 "운영 전 확인·기관 결정 필요"를 마쳐야 합니다.

현재 버전: **PC 0.14.16 · 휴대폰 앱 0.14.16** (PC 버전은 화면 위 머리줄과 `pc_tool.py status`에 표시, DB 구조 버전은 관리자 **진단** 카드). v0.13에서 바뀐 점은 아래 ["v0.13에서 바뀐 것"](#v013에서-바뀐-것)

0.14.16 **모바일 현장 UI·저장 보호**: 홈 도구를 두 열로 묶고 화면·잠금·작업자 설정을 앞에 배치했습니다. 접수 저장 실패·연타 중복·큰 수량 증감 오류를 고치고, 완료 후 수량 변경은 결과 재확인 뒤 다음 이동·PC 전달을 진행합니다. 수량 숫자를 눌러 직접 입력하며 부분 수량 덮기 확인, 짧은 화면의 경고·재시도 접근과 잠금 중 사진 미리보기 보호를 제공합니다. 검증은 `npm run test:mobile-ui`와 `npm run test:field`입니다.

0.14.15 **자동 잠금·수거 입력 개선**: 모바일 **설정 → 잠금 → 자동 잠금**에서 무조작·다른 앱 복귀 자동 잠금을 켜고 끕니다. 수동 잠금·앱 재실행 PIN과 기존 암호화 자료를 유지하며 저장 성공 후 적용합니다. PC 수거 입력은 품목별 −/+·남은 수량 채우기·부과 단위를 제공하고, 응답 유실 후에는 동결한 요청의 저장 여부를 재확인합니다. 모바일은 큰 수량·앞선 수거분을 보호하며 실제 저장 성공과 재저장 대기를 구분합니다.

0.14.14 **빠른 수수료 계산**: PC 오늘 현황·동별 관리·왼쪽 메뉴와 모바일 첫 화면에서 여러 품목의 규격·수량을 골라 감면 전 합계를 즉시 확인합니다. 수량 변경·삭제·비우기·내용 복사를 지원하며 계산만으로 접수를 만들지 않습니다. 미확정 단가는 확인 대기와 확정 소계를 표시하고, 개·쪽·세트 등 수량 단위를 구분합니다. 모바일은 받은 PC 표·단독 확정 단가를 반영하고 오프라인에서도 계산하며, 호환되지 않는 수신 표는 업데이트 안내로 차단합니다. 검증은 `npm run test:fees`입니다.

0.14.13 **행정복지센터 차고지**: 동마다 한 개의 기존 담당팀을 연결한 뒤 **설정 → 행정동 → 행정복지센터 차고지 일괄 적용**으로 빈 차고지만 채웁니다. 공식 센터 13곳의 주소·지도 위치를 제공하며 기존 차고지·담당팀·차량 한도는 유지합니다. 팀 미연결·중복 연결·사용 중지는 미적용 내역에서 확인합니다. 개별 차고지 창에서도 센터 위치를 채울 수 있고, 일괄 적용 응답 유실 시 결과를 다시 확인한 뒤 편집을 재개합니다. 검증은 `npm run test:depots`입니다.

0.14.12 **배정·노선 개선**: 대상 확인→노선 조정→확정 흐름을 표시하고 날짜·팀 빠른 선택과 빠른/정밀 추천을 제공합니다. 순서·팀 조정 후 **순서 유지 재계산**으로 최신 시간·적재·반입지 경유를 확인하며 **조정 되돌리기**와 접수 검색을 사용할 수 있습니다. 조정안·사유는 실패 후에도 보존하며 계산 뒤 접수·휴대폰 결과·배정·설정이 바뀌면 옛 계산으로 확정하지 않습니다. 미배정 후보는 전 페이지에서 검색합니다. 거리 표시는 도로 거리가 아닌 차고지·반입지·복귀를 포함한 **직선 합계**입니다. DB 구조는 11을 유지하며 검증은 `npm run test:routes`입니다.

0.14.11 **팝업 작업 흐름 개선**: 동별 접수 등록·상세는 전용 화면으로 열고 PC 수거 입력은 화면 안에서 펼칩니다. 입력을 접었다 펼쳐도 내용을 유지하며, 목록 복귀 시 날짜·동·검색조건·초점을 복원합니다. 휴대폰 **PC 입력 도움**은 접수번호와 이번 수거 개수를 크게 보여 주는 전체 화면으로 바뀌며 검색 복귀와 화면 켜짐 유지를 지원합니다. 취소·삭제·마감 확인 및 인쇄·QR 창은 유지합니다. DB 구조는 11입니다.

0.14.10 **날짜·접수 찾기**: PC 접수의 날짜 프리셋과 **날짜·상태 제한 해제**, 동별 관리의 **전체 기간 조회**로 지난 완료·취소 접수도 찾습니다. 조회 범위를 표시하며 동별 집계·배차는 선택한 기준일을 따릅니다. 휴대폰 홈의 **날짜·접수 찾기**는 보관 중인 전체 자료에서 접수번호·예정일·목록일·상태로 찾고 상세 왕복 후 조건을 유지합니다. PC 연결 휴대폰은 받은 목록과 현장 접수만 조회하며 PC 전체 과거 자료는 PC에서 확인합니다. DB 구조는 11이며 검증은 `npm run test:dates`입니다.

0.14.9 **PC 직접 수거·휴대폰 입력 도움**: 접수 상세 또는 동별 접수 상세의 **수거 처리**에서 실제 수거일·이번 추가 수거 개수를 입력합니다. 수량에 따라 완료·일부 수거·미수거를 정하고 기존 배출표 자동 배정·월보·대장에 반영합니다. 휴대폰 상세의 **PC 입력 도움**은 접수번호와 이전·이번·남은 수량을 크게 표시하고 개인정보 없는 전달 내용을 복사합니다. PC 입력 뒤에는 휴대폰도 업데이트하고 새 목록을 받으세요. 옛 수량 기준의 결과는 충돌함에서 확인합니다. DB 구조는 11을 유지하며 검증은 `npm run test:collection`입니다.

0.14.8 **동별 차고지·전담팀 노선**: **설정 → 행정동 → 차고지 설정**에서 동별 출발 위치를 지정합니다. 행의 저장을 누르면 동별·전체 배차에 팀별 출발·복귀지와 전담팀을 적용합니다. 미지정 동은 공통 차고지를 사용하며 별도 종료지가 있으면 그곳에서 끝납니다. 차고지 변경 후에는 다시 계산해야 확정할 수 있습니다. DB 구조는 11이며 기존 동·접수·배출표를 보존합니다. [동별 관리 안내](docs/동별-관리.md), 검증은 `npm run test:depots`입니다.

0.14.7 **원본 서식 자동 작성·동별 배출표 재고**: 실제 수거일·수량으로 동별 XLSX 월보와 ODT 일일 수불대장을 작성합니다. **작업일지·월보 → 원본 서식 자동 작성**에서 동·처리일을 고른 뒤 XLSX/ODT/ZIP을 받으세요. **배출표 관리**에 실물 번호·재고 동·실제 수령일을 등록하면 해당 동의 수거 1개당 번호 1개를 자동 배정·차감합니다. 부족 재고·미확정 단가는 보완 후 출력하며, 다운로드를 반복해도 재고는 그대로입니다. DB 구조는 10입니다. [사용 안내](docs/보고서·배출표.md), 검증은 `npm run test:forms`를 참고하세요.

0.14.6 **배출표 사용 장수 자동 집계**: 휴대폰 수거 결과를 PC에 반영하면 실제 수거 1개당 1장으로 계산합니다. **배출표 관리 → 사용 장수 자동 집계**에서 접수별·전체 누적 장수를 확인하세요. 3개 수거는 3장, 3개 중 1개 수거는 1장이며 재전송·재방문을 중복 합산하지 않습니다. 번호별 원장과 수납은 별도로 유지합니다.

0.14.5 **로그인 전후 테마 유지**: 같은 브라우저에서 마지막으로 적용한 테마·글자 크기를 로그인 화면에서도 유지합니다. 업데이트 후 한 번 로그인하면 계정의 외형이 기억됩니다. 다른 계정으로 로그인하면 그 계정의 서버 설정이 우선합니다.

0.14.4 **VWorld 위치 참고**: **설정 → 주소·외부 서비스**에서 VWorld API 키·사용 여부·등록 서비스 URL을 저장하고 연결 시험을 실행하세요. **전화 접수 → 배출 위치 → VWorld 위치 참고**에서 도로명/지번으로 조회합니다. 결과는 참고 창에만 표시하며 접수·초안·QR에는 반영하지 않습니다. 키 발급과 저장·전달 조건은 확인 전이므로 실제 연결은 발급 후 확인해야 합니다.

0.14.3 **행정동 직제순**: **설정 → 행정동**의 ↑·↓로 이동하고 **순서 저장**을 누르세요. **순서 되돌리기**는 이동만 취소하고 입력 중인 다른 항목은 유지합니다. 저장한 순서는 동별 관리·접수·담당 동 선택 목록에 함께 적용됩니다.

0.14.2부터 동구 기본 행정동 13개가 처음 실행할 때 자동 등록됩니다. 기존 자료를 업데이트하면 없는 동만 추가하고 기존 담당 팀·요일·한도·코드·사용 여부·계정 연결은 보존합니다. 이후 직접 삭제한 동은 재시작해도 다시 등록되지 않습니다. 운영 조건은 **설정 → 행정동**에서 지정하세요.

## 화면 디자인

PC 웹은 화이트 상단 바·딥네이비 메뉴·로컬 SVG 아이콘으로 정리했습니다. 오늘 현황의 다음 처리를 단계 설명보다 먼저 보여주고, 접수 등록 버튼은 조회조건 위에 둡니다. 로그인은 안내/입력 영역을 나누며 작은 화면에서는 한 열로 표시합니다. 화면·테마·큰 글씨 회귀는 `npm run test:design`으로 확인합니다(가상 자료·임시 서버만 사용).

0.13.8 **오늘 현황**은 다음 처리를 네이비 영역으로 강조하고, 선택일 지표를 한 묶음으로 정리합니다. 완료율은 수치와 막대로 표시하며, 지도·처리할 일 → 동별·팀별 진행 → 운영 점검으로 이어집니다. 날짜·권한·실적 계산은 기존 기준을 사용합니다.

0.13.9 **전화 접수 등록**은 신청자·품목·일정·위치 4개 구역과 하단 금액 요약·등록 버튼으로 정리했습니다. 주소 검색과 직접 입력, 확인분 금액과 최종 부과·납부액을 구분해 안내합니다. 초안·중복 확인·예약·저장 동작과 기존 접수 수정 화면은 유지합니다.

색 규칙(휴대폰·PC 같음): 녹색 = 완료, 노랑 = 사람이 봐야 함(확인 필요·재방문), 빨강 = 막힘·거부, 파랑 = 정보(처리 중·현장 추가), 회색 = 중립(취소 포함). 같은 일은 같은 말(금액 확인 대기, 수거 완료, 보류, 하차 기록, ← 목록). 확인창은 브라우저 창이 아니라 화면 안 대화상자입니다.

## 전화접수 물건 선택 (0.14.1)

전화접수·동별 접수의 물건 선택에서 **가전제품·가구·생활용품·기타** 분류와 검색을 함께 사용합니다. 물건을 고른 뒤 규격별 단가·부과 단위를 비교하고 수량과 품목 금액을 확인해 추가합니다. 동의어(쇼파·장농)와 초성 검색을 지원하며 검색 결과를 40개로 자르지 않습니다.

규격이 여러 개면 직접 고르고, 정확히 한 규격만 검색되면 Enter로 추가합니다. 방향키로 결과를 이동할 수 있고, 수량은 1~9999로 입력하거나 ± 버튼으로 바꿉니다. 표에 없는 물건은 **금액 확인 대기**로 접수하며 0원으로 처리하지 않습니다. 이미 담은 품목·수정 단가·초안·Ctrl+Enter 등록은 유지합니다. 회귀 검증은 `npm run test:items`입니다.

## 동별 통합 관리 (0.14.0)

**동별 관리**에서 기준일·행정동을 고르고 현황 → 접수 등록·수정 → 노선 계산 → 배정 확정으로 처리합니다. 전체 계정은 모든 동 또는 한 동을 선택하고, **동 담당자** 계정은 관리자가 지정한 한 개·여러 동만 사용합니다. 사용자·이력에서 담당 동을 지정·변경합니다. 팀장은 조회만 할 수 있습니다.

조회·상세·저장·배정·집계 CSV 모두 서버에서 현재 담당 범위를 검사합니다. 지정하지 않은 동과 기존 전역 업무는 동 담당자에게 열리지 않습니다. 다른 동의 접수가 섞인 기존 팀 배정은 교체하지 않고 전체 업무 담당자의 조정을 안내합니다. [사용 안내](docs/동별-관리.md)를 참고하세요.

회귀 검증은 `npm run test:dongs`입니다. 실제 SQLCipher·HTTP 권한 시험, 원본 화면·가상 API 시험, 실제 브라우저의 등록·배정·취소 흐름을 차례로 실행합니다.

## 작업일지·월보와 숫자 배출표 (0.13.6)

PC 메뉴 **작업일지·월보**에서 날짜/월과 집계 기준을 선택해 조회하고 인쇄·CSV로 내보냅니다. 현재 누적 수거량·납부일 기준 세입·작업일 기준 하차를 구분합니다. 0.14.7부터 원본 XLSX·ODT 서식도 별도로 제공하며 별도 마감 처리는 하지 않습니다.

**배출표 관리**는 숫자 구간 입고 → 배부처 지정 → 접수 연결·사용 → 무효·이력을 제공합니다. `000001`처럼 앞자리 0을 보존하고 `001`/`1` 중복은 차단합니다. 인쇄만으로 사용 처리되지 않습니다. [사용 안내](docs/보고서·배출표.md), 회귀 검증은 `npm run test:reports`를 참고하세요.

모바일 전화 버튼의 KT 통화매니저 연결은 Android/iPhone을 함께 [공식 자료로 검토](docs/KT-모바일-전화연결-검토.md)했습니다. 외부 번호 전달 규격은 미확인으로, 자동 연결은 아직 구현하지 않았습니다.

## PC 프로그램 설치·실행

Windows 배포본 **`Donggu-PC-windows-x64.zip`을 풀고 `Donggu-PC.exe`를 실행**하세요. Python 설치나 CMD 명령이 필요하지 않습니다. `_internal`을 포함한 폴더 전체를 함께 보관하고, 실행 앱의 **[바탕화면 바로가기 만들기]**로 다음부터 아이콘만 눌러 시작할 수 있습니다.

실행 앱이 초기 준비·서버 상태·오류·다시 시도·종료를 처리합니다. 필요하면 DB 비밀번호를 마스킹 입력창에서 받습니다. 준비가 끝나면 기존 업무 화면이 브라우저에서 열립니다. 앱 창을 닫으면 이 앱이 시작한 서버만 정상 종료하며, 이미 실행 중이던 동구 서버는 재사용하고 종료하지 않습니다.

**[최소화]** 또는 제목 표시줄의 **[—]**를 누르면 트레이 아이콘으로 숨겨지며 서버는 계속 실행됩니다. 시계 옆 숨겨진 아이콘 **[^]**에서 동구 PC 아이콘을 클릭하면 실행창이 다시 열립니다. 아이콘을 오른쪽 클릭하면 **[실행창 열기]**, **[실행 앱 종료]**를 선택할 수 있습니다.

**0.13.4 실행 화면**은 현재 단계와 실제 경과시간을 보여주고, **[업무 화면 열기]**와 **[서버 종료]**를 구분합니다. 브라우저는 필요한 업무 화면만 읽습니다. 시작이 지연되면 단계·경과시간과 **[화면 다시 불러오기]**가 표시되고, 첫 조회·홈 조회·업무 화면 파일은 10초 제한 뒤 오류와 재시도를 안내합니다.

**0.13.5 시작 복구**: 장기 실행 서버의 옛 파일 허용 목록과 새 HTML이 섞여 `/start.js`404로 멈추던 문제를 기존 `/pc.js` 진입점으로 복구했습니다. 실행 앱은 API 응답뿐 아니라 실제 화면 파일도 확인한 뒤 준비 완료를 표시합니다. 다른 프로그램이 시작한 서버는 이 실행 앱에서 종료하지 않습니다.

**0.13.7 실행 앱 디자인**: 밝은 표면·딥네이비 주 버튼·둥근 상태 카드·상태별 배지로 정리했습니다. 기본 크기는 680×480이며, 작은 창·큰 글씨에서는 정보만 스크롤하고 주 버튼·종료·오류 복구 동작은 직접 표시합니다.

기본 실행 창에는 **상태·업무 화면 열기·서버 종료**를 두고 자료 폴더와 바로가기는 **[설정·상세]**에 모았습니다. 서버 종료 뒤 주 버튼은 **[업무 시작]**으로 바뀝니다. 기존 서버 사용 중에는 종료와 자료 폴더 변경을 원래 실행 프로그램에서 처리합니다.

기존 서버 연결이 끊기면 **[기존 서버 연결 확인]**으로 재연결합니다. 원래 실행 프로그램에서 서버를 다시 켠 뒤 사용하세요. 이 버튼은 새 서버나 새 DB를 만들지 않습니다.

0.14.0부터 실행 앱·CMD는 기존 서버의 버전도 확인합니다. 버전이 다르거나 확인되지 않으면 원래 실행 프로그램에서 기존 서버를 종료한 뒤 새 버전으로 시작하도록 안내합니다. 실행 중인 다른 서버를 자동 종료하지 않습니다.

**기존 자료가 있으면** 실행 앱에서 해당 `pc/state` 등 자료 폴더를 선택하세요. 배포본의 새 자료 기본 위치는 `%LOCALAPPDATA%\DongguWaste\state`이며, 프로그램 교체 시에도 남습니다. 자료는 자동 이동·삭제하지 않습니다.

소스 실행(개발·유지보수, Python 3.12 이상):

```bash
pip install -r pc/requirements.txt
python pc/desktop.py                # 실행 앱
```

기존 CLI(macOS·Linux 포함)와 `Donggu-PC.cmd`는 개발·운영 보조로 유지합니다. CMD의 최초 의존성 준비는 `.\Donggu-PC.cmd -Install`입니다.

```bash
pip install -r pc/requirements.txt   # 버전·해시 고정본
python pc/pc_tool.py init            # 암호화 DB와 PC 키 생성 (처음 한 번)
python pc/pc_tool.py serve           # 브라우저에서 http://127.0.0.1:8765
```

배포본 빌드: Windows에서 고정 빌드 도구를 `python -m pip install --require-hashes -r tools/requirements-desktop.txt`로 설치한 뒤 `python tools/build_desktop.py`. 결과는 `dist/desktop/`에 생성됩니다.

기존 배포본을 보관하며 빌드하려면 `python tools/build_desktop.py --dist-dir dist/desktop/v0.13.9`를 사용합니다. 시작 지연 회귀는 `npm run test:startup`, 실행 앱 회귀는 `npm run test:desktop`으로 확인합니다. 서버·DB 없는 디자인 미리보기는 `python tools/preview_desktop.py --state ready --size 680x480`입니다(F1~F7 상태 전환, F8 설정 접기/펼치기).

처음 열면 **운영 관리자 계정**(아이디 + 10자 이상 비밀번호)을 만듭니다. 업데이트·백그라운드 실행(서비스)·로그 위치는 [docs/배포·운영.md](docs/배포·운영.md)를 보세요.

PC **오늘 현황 → 업무 이어하기**에서 선택한 날짜의 접수·배정·전송·결과·마감 상태와 지금 처리할 일을 확인합니다. 휴대폰 홈의 **지금 할 일**은 목록 받기, 다음 수거지, 결과·사진 전달 확인으로 이어집니다. 결과 파일 생성만으로 PC 반영이 끝나지는 않으므로 기존 반영 확인 절차까지 마치세요.

### 기능

**접수**

1. **전화 접수**: 양식은 전화 순서대로(신청자 → 물건 → 일정 → 위치), 접수 경로(전화·방문·온라인·단체(공동주택)·기타), 접수 시 안내 문구 표시. 같은 연락처·주소는 중복 후보 경고(자동 병합 없음). 수정은 사유 필수·버전 보존, 취소는 **사유 코드**(관할 밖·주민 취소·중복 접수·품목 불가·기타)와 함께. 저장 뒤 상세 위에 [+ 다음 접수]·[주민 안내 문구 복사](v0.13)
2. **주소 검색**: 이 PC의 주소 위치 자료에서 도로명·**지번·건물명·초성**으로 찾고 위치·행정동 자동 채움. 못 찾으면 지도를 눌러 지정
      **행안부 도로명주소 API**(설정 → 주소·외부 서비스에 승인키): PC 서버가 대신 검색(브라우저에는 키가 가지 않음, 저장 후 끝 4자리만 표시). 이 PC 자료 결과가 먼저, 행안부 결과는 "행안부" 표시.
      행안부 결과를 고르면 **위치는 이 PC 주소 위치 자료(위치정보요약DB)에서 먼저 찾음**(외부 전송 없음): 도로명코드·지하여부·건물본번·부번이 같은 건물 → 없으면 관할 구 안에서 도로명·건물번호 → 지번(법정동·번지), 출입구가 여럿이면 출입구일련번호가 가장 작은 것. 여기에 없을 때만, 좌표 승인키를 넣었으면 행안부 좌표제공 API로 물음(건물 식별 번호 다섯 개만). **좌표 승인키는 선택** — 없으면 "이 PC 주소 위치 자료에 없는 주소 — 지도에서 지정하세요"로 안내. 검색어에 연락처 형태·8자리 이상 숫자·입력 중인 이름·저장된 주민 이름이 있으면 보내지 않음. 접속기록에는 건수만, 서버 로그에는 검색어 없음
3. **행정동 관리**(설정 → 행정동): 아래 별도 설명
4. **수거 한도·휴무일 달력**: 접수 화면에 다음 업무일 14일의 예약/한도(전체·동별 건수·m³), **[가장 빠른 가능일]**, 한도 초과·휴무일·수거 요일 아님 경고(막지는 않음). 설정 → 한도·휴무일
5. **일괄 처리**(접수 목록에서 여러 건 선택): 예정일 변경·취소(사유 코드)·동 지정·목록 인쇄·배출 표지·CSV. 건별 이력이 남음
6. **CSV 접수 가져오기**: 서식 CSV 내려받기 → 미리보기(오류·경고·중복 후보) → 오류 행은 빼고 한 번에 등록(중복 후보도 뺄 수 있음)

## 휴대폰 앱 사용

- **PC 연결 방식**: 기기 등록 → 오늘 목록 받기(다시 받으면 새로·변경·빠짐 표시) → **수신 코드(R-)**를 PC 담당자에게 → 상세 → 품목·수량·수수료 → 사진 → 수거 결과 → 결과 보내기(업무 메일) → 사진 파일 만들기(보안 매체) → **결과 반영 코드(D-)**·**사진 회수 코드(P-)** 입력. 0.13.0부터 PC가 결과·사진을 가져온 뒤 만든 목록(같은 날 갱신본이나 다음 날 목록)을 받으면 두 코드는 넣지 않아도 저절로 확인됨(위 16번). 코드 칸에 다른 종류 코드를 넣으면 맞는 칸을 알려 주고 받지 않음
  - **단독 방식에 있던 일도 PC 연결 방식에서 (v0.12)** — PC가 원본이므로 휴대폰은 바로 고치지 않고 *요청*으로 보내고 사무실이 확인합니다
    - **[+ 접수 등록 (현장·전화)]**(홈 위, 기기 등록 전에도 가능 — 보내기만 등록 뒤): 수거 중 새로 요청받거나 전화로 받은 건을 접수, 경로 현장(기본)·전화·방문 → 임시번호(현장-MMDD-N 등)로 목록에 들어가 현장 접수는 바로 처리 가능 → 결과 보내기 때 PC 원본 접수가 됨(고른 경로로). 금액은 PC 수수료표로 다시 계산, 표에 없는 품목은 확인 대기. PC [현장 접수 확인]에서 담당자가 확인
    - **보내기 전 고치기**(0.12.12): 이 휴대폰에서 받은 접수를 아직 결과 파일로 내보내지 않았으면 지점 화면 [접수 고치기 (보내기 전)]로 바로 고침(보낸 뒤에는 정정 요청)
    - **[정정 요청]**: 이름·연락처·주소·상세 위치·예정일. PC 충돌함([현장 요청] 탭)에 "지금 값 → 요청 값"으로 나오고 [반영]하면 원본을 고침(이전 내용은 버전 이력, 주소가 바뀌면 위치는 다시 지정, 날짜가 바뀌면 배정 해제). 요청한 새 연락처로 휴대폰에서 [새 번호로 전화]
    - **[취소 요청]**: 사유 코드(주민 취소·중복·품목 불가·관할 밖·기타). PC가 확인한 뒤 취소(납부가 있으면 환불 필요로)
    - **싣기 안내**(0.12.15): 목록 카드에 품목별 취급 표시(2인·세워서·유리·깨짐 등), 반입지 하차 사이 운행(회차)마다 머리글 — 실을 양(추정)과 "N번 장롱 → 앞쪽 바닥 자리 남겨 두기", "N번 유리 → 맨 위나 따로". 지점 화면에 싣기 안내(취급 방법 설명)
    - **방문 순서 바꾸기**: 이 휴대폰에서만 순서를 바꿔 다님(PC 노선·배정은 그대로, 새 목록을 받으면 PC 순서로). [PC 순서로 되돌리기]
    - 단독 방식의 **휴대폰 단가 확정**은 PC 연결 방식에 넣지 않음 — 단가는 PC 수수료표 개정(2인 승인)이 기준
- **현장 점검**(설정 → 현장 점검, 0.12.13): 자동 시험으로 확인할 수 없는 것(설치·지문·주소 검색·카카오맵/T맵/네이버 길안내·카메라 다녀오기·QR·전화/문자)을 이 휴대폰에서 [시험]으로 눌러 보고 된다/안 된다/메모를 남김. 카메라 시험 중 앱이 다시 열리면 자동으로 '안 된다'. [결과 복사]로 기기·브라우저·앱 버전과 결과를 담당자에게(주민 정보 없음)
- **설치**: 브라우저 탭에서도 그대로 동작해 설치 전에도 앱처럼 보임 → 설정에 **실행 위치**(브라우저 탭/설치한 앱)와 설치 단추·안내(0.12.2). 아이폰은 Safari와 홈 화면 앱의 자료가 따로라 설치한 앱에서 시작
- **배출 주소 확인·동 정하기**(0.12.11, 휴대폰 안 자료로만 — 주소를 밖으로 보내지 않음): 건물번호(번지) 없음, 도로명·지번 형식 아님, 관할(구) 밖·다른 시도, 주소칸의 전화번호를 알림(막지 않음 — 저장 때 한 번 보여 주고 다시 누르면 저장). 동은 주소의 행정동 이름 → 같은 도로·법정동의 이전 접수 → 법정동 줄기 후보(예: 계림동 → 계림1·2동) 순으로 추천·자동 채움, 동구 행정동 목록에 없는 이름은 오타 알림. PC 접수 화면도 주소를 바꾸면 같은 확인을 보여 줌
- **품목 담기**(전화 접수·현장 접수, 지점의 [+ 현장 품목 추가]도 같은 화면 — 0.12.6): [+ 품목 담기] → 전용 화면. **글자 없이 눌러서**: 분류 탭(자주 쓴·가전·가구·생활·기타·담음) → 품목 이름 단추 → 규격이 여럿이면 규격 고르기 창(규격마다 [+ 담기]/[− N +]), 하나면 바로 담김. 이름 검색(초성)도 가능 — 담기를 눌러도 키보드가 유지되고 검색어가 선택돼 바로 다음 품목 입력. 아래에 담은 요약과 [완료] 고정, [담음] 탭에서 수량 조정·빼기, 목록에 없는 품목은 확인 대기로
- **단독 방식**: 전화 접수 등록 → 날짜별 목록·방문 순서 → 현장 처리 → 매일 암호화 백업(24시간 지나면 경고) → 나중에 PC로 옮기기
- **현장 처리**
  - **📍 도착**: 시각과(허용 시) 휴대폰 위치·정확도 기록. 위치는 결과 파일로만 PC에 감
  - 📞 전화 → 연락 결과(통화 완료 ≠ 수거 완료), 통화로 약속한 재방문 날짜·시간
  - **✉ 문자**: 문구(설정에서 편집)를 골라 문자 앱을 엶. 이 주민의 접수번호·시각만 들어가고, 기록엔 문구 종류만 남음
  - **스티커·신고필증 확인**(품목별 확인/없음/번호 불일치). 문제가 있으면 그 품목을 수거할지 바로 정함
  - **현장 금액 고지**: 접수 때보다 금액이 늘면 주민 안내 결과(동의·거부) 기록. 거부하면 늘어난 품목은 미수거
  - **사진 필수**: 부재·배출 안 됨으로 미수거하려면 사진 1장 이상 또는 찍지 못한 이유. 사진은 촬영 시각·위치와 함께 앱 안에만 암호화 저장(갤러리에 안 남음), 특정 품목에 묶기 가능
  - 현장 메모, **현장 품목 추가**(품목 담기 화면에서 여러 개 담고 [추가 저장]으로 한 번에, ☆즐겨찾기·자주 쓴 품목), 이미 현장 추가한 품목을 또 담으면 저장 때 "기존 행에 더하기 / 따로 한 줄 더"
  - 반입지에서 **[하차 기록]**(시각·부피·중량)
- **작업자**: 설정에 이름을 넣어 두면 교대 때 PIN 없이 골라 바꾸고, 모든 기록에 작업자 이름이 남음
- **길안내**: 설정에서 고른 지도 앱(**카카오맵** 기본 / T맵 / 네이버지도 / 기본 지도 앱)을 다음 지점·반입지 좌표로 엶. 넘기는 것은 좌표와 "N번 수거지"(반입지는 "반입지")뿐. 앱이 없으면 웹 길안내(T맵은 기본 지도 앱)
- **주소 검색**(단독 방식 접수·위치 지정): 행정안전부 도로명주소 검색·좌표제공 API. 기관이 발급받은 **승인키**를 설정에 넣어야 동작하고, 없으면 직접 입력·지도 지정. 휴대폰에는 주소 위치 자료가 없으므로 위치까지 채우려면 좌표 승인키도 필요(PC는 선택). 검색어에 이름·연락처가 들어 있으면 보내지 않음. 행정동 추천
- **미전송 경고**(PC 방식): 정한 시간(1·3·6시간, 기본 3) 넘게 안 보낸 기록이 있거나 17시가 지나면 홈에 경고, **중간 결과 보내기**
- **지도**: 방문 지점 핀·배출 위치 지정, **동구 지도 미리 받기**(줌 14 이하, 최대 50MB). 설정에서 끌 수 있음
- **개인정보 자동 삭제**: PC 방식은 보관 종료 확인 코드가 들어오면 그 접수의 이름·연락처·주소를 휴대폰에서 지움(수거 기록은 남음). 단독 방식은 보관 기간(30·90·180일)이 지난 처리 끝난 접수를 확인 후 지움
- **잠금**: PIN(6자리 이상), 무조작 **잠금 시간 5·10·15분**(기본 10분). 카메라·전화·문자·길안내 앱에 다녀오는 동안은 10분까지 유예(그 밖의 앱은 2분). 잠긴 사이 찍힌 사진은 메모리에 두었다가 잠금 해제 후 저장. 0.13.0: 잠그기 전에 저장 중인 기록·사진을 끝까지 기다리고, 저장하지 못한 사진은 버리지 않고 대기열에 남김. **지문·얼굴 잠금 해제**(지원 기기만: Android Chrome·Samsung 인터넷 최신 — Google 비밀번호 관리자·Samsung Pass, 아이폰 iOS 18 이상. WebAuthn PRF로 데이터 키를 풂, PIN도 계속 사용). 업무 중 화면 켜둠
- 행정동 표시·거르기, 6곳 이상이면 이름·주소·품목 찾기(초성)

- **감면·부과번호**: PC 목록에 감면율과 부과번호가 실려 오면 상세에 부과번호, 수수료 상자에 계산 금액 → 감면(율) → **부과 금액**(원 단위 버림, PC와 같은 계산). 현장 추가 품목에도 감면 적용. 감면 사유(수급자 등)는 휴대폰에 보내지 않음

## 보안·개인정보

| 항목 | 방식 |
| --- | --- |
| PC 저장 | SQLCipher로 DB 파일 전체 암호화. DB 키는 운영체제 키 저장소(또는 시작 시 입력). PC 개인키도 DB 안에 보관. `sqlcipher3`가 없으면 평문으로 실행하지 않고 멈춤 |
| PC 화면 | 기본 127.0.0.1에만 열림, Host 검사, 사용자별 계정(scrypt)·역할별 API 제한, 세션 쿠키(HttpOnly·SameSite=Strict, 30분 무조작·로그인 뒤 10시간 만료), CSRF 헤더 필수, 계정별 로그인 잠금 + LAN 모드 접속 PC(IP)별 제한(10분에 20번 → 10분) |
| LAN 모드 | 기본 꺼짐. 켜면 HTTPS 전용(TLS 1.2 이상)·Secure 쿠키, 허용 IP 대역 밖 연결은 끊음, 모든 주소 허용 거부, Host는 서버 이름만. 정보화부서 승인 필요 |
| 서버 로그 | `server.log`: 방법·**경로 틀**(ID처럼 보이는 부분은 `:id`로 가림)·상태 코드·걸린 시간·사용자 아이디·접속 위치, 1초 넘는 요청은 "느린 요청" WARNING(경로 틀·ms). 주소 뒤 조건(query)·본문은 남기지 않음. 오류 내용은 전화번호·도로명 주소 모양을 가려서 기록 |
| 접속기록 | 개인정보를 연 기록(누가·언제·무엇을·건수·조건)을 암호화 DB에 남김. 2년 이상 보관, 팀장·관리자 월 점검 |
| 해시 체인 | 접속기록과 변경 이력은 행마다 앞 행의 해시를 이어 받음 → 무결성 검사로 수정·삭제 발견(v0.11 이전 이력은 '이전 기록'으로 검사에서 뺌) |
| 파기 | 보유기간 지난 접수는 사람을 알아볼 수 있는 값만 지우고(가명 처리) 파기 대장에 기록. **이전 백업 파일에는 남아 있으므로** 백업 보관 기간에 따라 지움 |
| 휴대폰 저장 | IndexedDB 레코드별 AES-GCM, 데이터 키는 PIN(PBKDF2 60만 회)으로 감쌈(지문·얼굴은 PRF로 추가 감쌈), 자동 잠금, 사진은 갤러리에 남지 않음 |

| 사진 | 결과 파일과 분리, 암호화 사진 파일로 보안 매체 회수, PC가 해시 대조 후에만 사진 회수 코드(P-) 발급 또는 다음 목록의 서명된 반영 정보에 그 사진 ID를 실음 → 그 뒤에만 휴대폰에서 삭제 가능 |

PC 화면(브라우저) 자체는 지도 조각 서버만 연결. **이름·연락처는 어디로도 나가지 않음.** 쿠키·Referer 안 보냄, CSP로 허용 서버만 연결 |
| 백업 | 수동: DB 키와 다른 백업 비밀번호로 암호화. 자동: 백업 공개키(X25519)로 암호화, 개인키는 PC에 없음. 복원 시 현재 DB 키로 다시 암호화하고 기존 DB는 지우지 않음. v0.13: DB 구조를 바꾸기 전 `state/pre-migration/`에 DB 파일 사본(같은 DB 키로 암호화된 그대로, 개인정보 포함, 매일 예약 작업이 정리 — 가장 새 1개는 남기고 나머지는 3개·30일 넘으면 지움) |
| 변경 이력 | 작업자·시각·대상·작업. 내용에는 사유·건수·코드만(이름·연락처·주소 없음). 화면에서 고치거나 지울 수 없음 |
| 감면·환불 | 주민등록번호·수급자 증명번호·계좌번호 저장 안 함(계좌는 확인 여부와 끝 4자리만) |
| 분실 기기 | PC에서 "분실 처리" → 그 기기로 목록 전송 불가, 결과 거부. 오프라인 기기의 원격 삭제는 약속하지 않음 |

PC 의존성은 `pc/requirements.txt`, 화면 시험 의존성은 `.github/requirements-e2e.txt`로 설치합니다. npm 스크립트가 부르는 `python3`는 해당 의존성을 설치한 가상환경의 Python이어야 합니다.

```bash
npm ci && npm test               # 수수료·현장 상태·PC↔휴대폰 상호 운용
```

## 알려진 제한

- 노선 이동시간은 로컬 OSRM이 없으면 **직선거리 추정**(화면에 표시). 실시간 교통·음성 길안내·현장 재최적화는 없음(길안내는 외부 지도 앱에 맡김)
- 휴대폰 주소 검색: 행정안전부 서버가 브라우저 요청(CORS)을 허용하는지 **실제 휴대폰에서 아직 확인 안 됨**. 막히면 검색이 실패하고 직접 입력·지도 지정으로 넘어감(PC 방식은 PC에서 주소 작업)
- 길안내 앱 주소(카카오맵·T맵·네이버지도 URL 스킴)는 **실제 기기에서 아직 확인 안 됨**. 앱이 없을 때 웹으로 넘어가는 동작도 기기마다 다를 수 있음
- Android에서 카메라 앱을 오가는 동안 브라우저가 앱을 다시 불러오면 방금 찍은 사진이 사라질 수 있음(다시 찍어야 함)
- 자동 백업 중 DB 잠금은 암호화 내보내기 동안만 잡음(파일 봉인·복사는 잠금 밖). 자료가 아주 크면 내보내는 몇 초 동안 PC 화면이 기다릴 수 있음
- Windows·macOS의 PC 로직 시험은 CI에서 참고용(경고만). 화면 시험은 Linux Chromium에서만
- 주소 위치는 건물 출입구 좌표(위치정보요약DB 기준). 처음 가져올 때 미리보기로 표본 위치 확인. 행안부가 매월 갱신하므로 월 1회 다시 가져오기(45일 넘으면 오늘 현황에 갱신 안내). 화면은 압축(.zip)을 읽지 못하니 풀어서 .txt를 넣고, 40MB 넘는 파일은 `pc_tool.py import-addr`로
- 행안부 결과를 도로명·지번 이름으로 맞추는 대체 찾기(식별 번호 없는 예전 자료)는 관할 구 이름(예: 동구)으로만 거름 — 다른 시의 같은 이름 구와 섞이지 않게 위치정보요약DB를 다시 가져와 도로명코드를 채우는 것이 좋음
- 적재 부피·무게·작업 시간은 품목별 **추정치**(실측 전, `data/item_handling.json`). 부피는 담당자 보정값이 있으면 그것을 씀. 반입지 하차 기록과 비교해 고쳐 나감. 바꾸면 `python tools/build_fee_js.py`로 휴대폰 내장본도 다시 만듦
- 휴대폰 단독 방식의 단가 확정은 그 휴대폰에만 적용(PC 개정·2인 승인과 별개)
- 수납은 담당자 확인 기록과 대사 CSV 반영이며 온라인 결제·세외수입 자동 연계는 없음. 계산 금액은 수납 완료를 뜻하지 않음
- 웹 앱의 키는 하드웨어 보안 영역에 묶이지 않음(지문·얼굴은 PRF 지원 기기만). 브라우저 데이터 삭제 시 휴대폰 미전송 기록 소실
- 파기는 이후 백업 파일까지 지우지 않음(백업 보관 기간으로 관리)
- (v0.13) 사진은 아직 **주 DB 안에** 저장됩니다(별도 사진 DB로 나누는 일은 위험이 커서 미룸). 정리한 사진 자리는 새 DB만 조금씩 돌려주므로(`auto_vacuum=INCREMENTAL`), v0.12 이하에서 만든 DB는 서버를 끄고 `python pc/pc_tool.py vacuum`을 한 번 실행해야 파일이 줄어듦. 사진이 많으면 DB·백업 파일이 커지므로 진단 카드에서 크기를 봄
- (v0.13) 팀장 **마감 확인** 뒤의 개인정보 파기·자동 백업은 예전처럼 그 요청 안에서 DB 잠금을 잡고 돎(매일 예약 작업과 별개). 파기 대상이 많거나 DB가 크면 그동안 다른 화면이 기다릴 수 있음
- (v0.13) CSV 접수 일괄 등록·세입 대사 파일의 **실제 반영**은 아직 잠금 안에서 읽고 넣음(미리보기는 잠금 밖). 2,000·5,000행 제한이라 보통 짧음
- (v0.13) 백그라운드 작업의 진행·결과는 서버 메모리에만 있음. 작업 중 서버를 다시 켜면 진행 띠의 작업은 사라지고(결과는 변경 이력·파기 대장·백업 폴더로 확인), 예약 작업은 서버가 켜져 있을 때만 돎(꺼져 있었으면 다음에 켰을 때, 이틀 넘으면 대시보드 경고)
- (v0.13) 휴대폰의 저장 대기 사진(잠김·공간 부족으로 아직 암호화 저장 못 한 것)은 **메모리에만** 있음 — 그 사이 앱을 닫거나 브라우저가 앱을 내리면 사라짐(첫 화면에 "앱을 닫지 마세요" 알림). 휴대폰 기록은 여전히 상태 하나에 통째로 암호화해 다시 씀(기록별 저장으로 나누는 일은 현장 시험 뒤)
- (v0.13) 목록의 반영 정보(rel)는 휴대폰이 **새 목록을 받을 때만** 적용됨. 목록을 받지 않는 날(마지막 근무일 등)이나 이전 PC와는 결과 반영 코드·사진 회수 코드를 넣어야 함. 휴대폰 업데이트는 바로 앞 버전 캐시까지만 남기므로 두 번 연속 업데이트하는 동안 열린 채인 아주 오래된 창은 새로 열어야 함
- (v0.13) 배정 부분 수정은 도착 예상 시각·반입지 경유를 다시 계산하지 않음. 많이 바꿨으면 [노선 계산]으로 다시 확정
