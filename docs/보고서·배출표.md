# 작업일지·월보와 배출표

0.14.9부터 **PC 접수 상세 → 수거 처리**에 입력한 실제 수거일·추가 수량도 휴대폰 확정 결과와 같은 기준으로 번호 자동 배정과 원본 서식에 반영합니다. 이전 수거량을 다시 입력하지 마세요. 재시도는 중복 차감하지 않으며, 수납 기록은 별도입니다.

PC 0.13.6부터 제공한다. 운영 관리자·접수 담당자는 기록과 조회가 가능하고, 팀장은 조회·인쇄만 할 수 있다. 수거팀 계정에는 표시되지 않는다.

## 일일 작업일지·월보

1. **정산·마감 → 작업일지·월보**에서 보고서 종류, 작업일 또는 월, 집계 기준을 고르고 **조회**한다.
2. 미리보기의 기간·기준을 확인한 뒤 **인쇄 화면 열기** 또는 **CSV 내려받기**를 누른다. 조건을 바꾸면 다시 조회해야 출력할 수 있다.
3. CSV는 Excel에서 열 수 있는 UTF-8 파일이다. 인쇄는 브라우저에서 PDF로 저장할 수도 있다. 원본 XLSX·ODT는 아래 별도 작성 기능을 사용한다.

0.13.10의 기본 보고서는 화면·인쇄에 납부 방법별 환불 건수와 기간 세입 합계를 함께 표시한다. 인쇄에는 접수 경로별·감면별 표도 포함한다. 좁은 화면에서는 세입 표 안에서 가로로 스크롤할 수 있다.

수거 예정일은 현재 예정일, 접수일은 한국시간 접수일, 완료일은 마지막 종료 결과(취소 포함)의 일자를 사용한다. 수거 수량은 선택된 접수의 **현재 누적값**으로 당일 증분이나 당시 확정 실적이 아니다. 팀은 마지막 배정 기준이다. 세입은 납부일, 하차는 작업일로 별도 집계한다. 보고서를 열거나 출력해도 마감·결재·이월을 수행하지 않는다. 집계 출력에는 주민명·전화·주소·메모·접수번호를 넣지 않는다.

## 사용 장수 자동 집계 (0.14.6)

1. 휴대폰에서 품목별 실제 수거 개수를 입력하고 수거 결과를 확정한다. **수거 1개당 배출표 1장**이다. 3개 수거는 3장, 3개 중 1개 수거는 1장, 미수거는 0장이다.
2. PC **결과 가져오기**에서 결과 파일을 반영한다. 단독 휴대폰 백업을 옮긴 결과도 자동 집계한다. 사용 장수는 별도로 등록하지 않아도 된다.
3. **배출표 관리 → 사용 장수 자동 집계**에서 전체 사용 장수·수거 접수 수와 품목별 내역을 확인한다. 접수번호·행정동 조건을 바꾼 뒤 **집계 조회**한다. 합계는 조회조건에 맞는 모든 페이지의 합계다.

전체 기간의 **마지막 확정 누적 수거 수량**을 접수별로 한 번 합산한다. 재전송은 더하지 않고, 재방문은 추가 수거를 포함한 누적값으로 갱신한다. 입력 중인 수량과 미반영 충돌은 제외하며 확정된 정정은 반영한다. 취소·재배정·개인정보 파기로 이미 수거한 사용분이 사라지지 않는다. 마지막 확정 일시는 참고값이며 일별 증감 사용량을 뜻하지 않는다.

아래 숫자 원장의 사용 건수와 합산하지 않는다. 이 표는 수거 개수 기준 누적 집계이며, 0.14.7의 번호 자동 배정 현황과 함께 확인한다. 접수 등록·인쇄·수납만으로 사용 장수가 늘지 않는다.

## 동별 번호 자동 배정 (0.14.7)

1. **번호 구간 입고**에 실물 시작·끝 번호, **재고 행정동**, **실제 수령일**을 등록한다. 공용 보관 상태는 자동 배정하지 않는다. 기존 공용 번호에는 **기존 번호 재고 동 지정**을 사용한다. 다른 동에 지정된 재고는 가져올 수 없다.
2. 수거 결과·단독 백업 반영, 충돌 결과 적용, 동별 입고·배부 시 확정 수거 1개당 해당 동의 작은 번호부터 1개씩 배정한다. 현장 추가 품목도 포함한다. 같은 결과 재전송과 재조회·파일 다운로드는 중복 차감하지 않는다.
3. **동별 번호 자동 배정**에서 미배정 장수와 동별 가용 재고를 확인한다. 재고가 부족해도 수거 결과는 반영된다. 실물 재고를 보충하면 자동으로 맞추며 **미배정 다시 배정**으로 재확인할 수 있다. 수령·배부일보다 앞선 수거분에는 배정하지 않는다.

수량 정정으로 초과된 자동 번호는 이력을 남겨 무효 처리하고 재사용하지 않는다. 기존 수동 사용 번호의 접수 연결과 사용 일시는 유지한다. 수동 초과·동 또는 일자 불일치는 별도로 표시하므로 상세 내역에서 확인한다.

## 원본 XLSX 월보·ODT 일일 대장 (0.14.7)

1. **작업일지·월보 → 원본 서식 자동 작성**에서 행정동과 처리일을 고르고 **서식 조회**한다. 월보는 선택일이 속한 달 전체, ODT는 선택일 하루의 **실제 확정 수거 증가분**을 사용한다. 예: 6월 2개, 7월 추가 1개면 각 월에 2개·1개로 기재한다.
2. 수거 수량·수거분 수수료·이월·수령·불출·잔량을 확인한다. 미배정 번호·미확정 단가·날짜/재고 오류가 있으면 보완 후 다시 조회한다. 수거분 수수료는 접수별 단가·감면·끝수 기준으로 계산하며 실제 현금 수납액과 다르다.
3. **월보 XLSX**, **일일 대장 ODT** 또는 **두 서식 ZIP**을 내려받는다. 성명·주소·연락처가 포함되므로 관리자·접수 담당자만 다운로드하며 접속기록에 남긴다. 팀장은 개인정보 없는 미리보기만 가능하다. 결재 서명·결재일은 자동 작성하지 않는다.

원본의 목록·수수료·배출표·월별 명세와 ODT 결재란/대장 구조를 유지한다. 끊어진 수식·숨김 행을 정리하고 합계·잔량·인쇄 범위를 출력 자료에 맞춘다. 원본 샘플 주민과 번호는 배포 서식에서 제거했다. 수량 정정 무효·기존 수동 사용은 수불 행에 구분해 잔량을 맞춘다. Excel·한글·Word 설치 없이 PC 실행 앱에서 파일을 만들 수 있다.

## 숫자 배출표 원장

1. **접수 업무 → 배출표 관리 → 번호 구간 입고**에서 시작·끝 번호를 입력한다. 숫자 1~30자리, 같은 자릿수, 한 번에 최대 5,000장이다. 한 장은 시작과 끝을 같게 입력한다.
2. **번호 구간 배부**에서 입고 번호와 배부처(기관·부서명)를 기록한다. 주민 개인정보는 입력하지 않는다.
3. 번호를 눌러 상세를 열고 접수를 검색·선택한다. 필요하면 품목도 선택한 뒤 **접수에 연결하고 사용 기록**을 누른다. 취소·파기 접수나 다른 접수의 품목에는 연결할 수 없다.
4. 훼손·오류는 사유와 함께 **무효 기록**한다. 무효 번호는 다시 사용할 수 없다. 반납·복원·재발급은 이번 버전에서 지원하지 않는다.

`000001`은 그대로 표시한다. 다만 `000001`과 `1`은 같은 번호로 판단하여 중복 입고를 막는다. 구간 중 일부가 중복되거나 상태가 맞지 않으면 전체 처리를 거부한다. 사용 번호를 다른 접수로 옮길 수 없다.

상세의 이력은 최근 20건을 표시하며 변경 이력 메뉴에서도 확인할 수 있다. **인쇄는 상태를 바꾸지 않는다.** 새 번호표 QR에는 숫자 번호만 담는다. 기존 접수번호 QR 표지·수납·현장 배출표 확인 기록과는 별개다.

## 업데이트·검증

0.14.7 기능은 서버와 DB 구조 10이 필요하므로 실행 앱 전체를 교체한다. UI 파일만 덮어쓰지 않는다. 실행 중인 이전 서버는 그 서버를 시작한 프로그램에서 종료한 뒤 새 실행 앱을 연다. 기존 자료 폴더를 유지하며, 구조 갱신 전 암호화 백업과 실패 시 되돌림 절차는 기존 저장소 정책을 따른다. 기존 배부처가 행정동명과 정확히 같을 때만 재고 동을 연결하고, 다른 기관명은 직접 지정하도록 남긴다.

`npm run test:reports`는 임시 SQLCipher DB, HTTP API, 가상 API 화면 회귀, 실제 브라우저 업무 흐름을 검증한다. 사용 장수만 확인할 때는 `npm run test:labels`를 사용한다. 실제 주민 자료·운영 회선·실제 KT 앱은 시험하지 않는다.

`npm run test:forms`는 날짜별 수거·배정·동 격리·마이그레이션·XLSX/ODT·HTTP·화면 경쟁을 검증한다. Windows 배포본은 `python tests/test_official_forms_e2e.py --exe dist/desktop/v0.14.7/Donggu-PC/Donggu-PC.exe`로 실제 EXE의 자동 배정과 세 형식 다운로드를 확인한다. 기존 업무 흐름은 `python tests/test_reports_labels_bundle.py --exe dist/desktop/v0.14.7/Donggu-PC/Donggu-PC.exe`로 확인한다. Playwright와 Chromium(`CHROME`)이 필요하다.
