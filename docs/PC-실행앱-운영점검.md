# PC 실행 앱 운영·접속 점검

기본 연결은 **이 PC에서만 접속**입니다. 기관·와이파이가 같은 다른 PC에서 사용할 때는 기관망 HTTPS 연결을 설정합니다. 인터넷 공개나 방화벽·공유기 자동 변경은 제공하지 않습니다.

## 실행창에서 확인하기

- **접속 주소 복사**: 브라우저에 직접 붙여 넣을 수 있습니다. 브라우저 실행 실패 때도 이 주소로 접속하세요.
- **연결 점검**: 이 PC에서 서버 정체·버전·화면 파일 응답을 확인하고, 선택 자료 폴더의 접근 권한 표시와 실제 디스크 여유 공간을 확인합니다. 자료를 저장해 보는 검사는 하지 않습니다.
- **로그 폴더**: 실행창에서 선택한 자료 폴더의 `logs/`를 엽니다. 기존 서버를 함께 쓰는 경우 그 서버의 실제 자료 위치와 다를 수 있습니다.
- **진단 보고서 저장**: 앱 버전·연결 결과 코드·디스크 용량 등을 JSON으로 저장합니다. 업무 DB·로그 원문·비밀번호·키 내용·개인 폴더 경로는 포함하지 않습니다. 연결 주소와 기기 종류는 포함됩니다.

## 같은 망의 다른 PC 연결하기

1. 서버를 실행한 원래 실행창에서 **서버 종료**를 눌러 정상 종료합니다. 다른 실행창의 기존 서버는 이 창에서 종료하거나 설정을 바꾸지 않습니다.
2. **접속 설정**에서 기관망 HTTPS, 포트, 서버 바인드 IPv4 주소, 인증서의 DNS 이름 또는 IPv4 주소, 허용 클라이언트 IP 대역, 인증서·개인키 파일을 입력합니다.
3. 인증서는 기관과 접속 PC에서 신뢰해야 하고, 접속 이름과 일치하며 유효기간이 남아 있어야 합니다. 암호화된 개인키 파일은 지원하지 않습니다. `0.0.0.0`은 서버 바인드 주소로만 사용하고 접속 주소로 입력하지 않습니다. 모든 주소 허용 대역(`/0`)은 사용할 수 없습니다.
4. **저장 후 재실행**을 누릅니다. 변경한 포트는 새 실행창에 적용됩니다. 기존 바로가기의 명시적 인자가 저장 설정보다 우선하므로 필요한 경우 새 실행창에서 바로가기를 다시 만드세요.
5. 서버 PC의 접속 주소를 복사합니다. 프로그램 폴더 전체를 다른 PC에 복사하고 **PC 접속 점검.cmd**를 실행해 주소를 입력합니다. 이 모드는 DB·키·로그인 없이 연결만 확인합니다.
6. 다른 PC에서 점검 성공 후 브라우저에서 해당 주소에 접속해 기존 업무 계정으로 로그인합니다. 업무 권한은 기존 계정 설정을 따릅니다.

서버 PC의 점검 성공은 다른 PC의 연결 성공을 증명하지 않습니다. 실제 다른 PC에서 점검해야 방화벽·망 분리·허용 IP·인증서 신뢰를 포함한 연결 여부를 확인할 수 있습니다. 인증서 오류 때 검증을 생략하거나 HTTP로 바꾸지 않습니다.

## 오류별 확인 사항

| 결과 | 확인할 내용 |
| --- | --- |
| 연결 실패 | 서버 실행, 주소·포트, 같은 망 여부, 기관 방화벽과 망 분리 |
| 인증서 오류 | 신뢰 체인, 유효기간, 접속 이름 |
| 접속 거부 | 서버의 허용 IP 대역과 접속 이름 |
| 다른 서비스 | 포트 충돌, 주소가 다른 프로그램을 가리키는지 |
| 버전 불일치 | 서버와 점검 프로그램을 같은 버전으로 맞추기 |
| 화면 파일 오류 | `_internal/`을 포함한 프로그램 폴더 전체가 있는지 |
| 저장공간 부족 | 업무 자료와 백업이 있는 디스크의 여유 공간 |

현재 설치의 `8765` 포트는 다른 프로그램이 사용하므로 기존 업무용 바로가기의 **`--port 8766`**을 유지합니다. 시험용 프로그램으로 운영 중인 서버를 종료하거나 자료를 초기화하지 마세요.

## 명령행 점검

```powershell
# 창으로 점검하기
Donggu-PC.exe --check-connection https://waste.example:8766/
# 창 없이 명시한 파일에 안전한 보고서 저장
Donggu-PC.exe --check-connection https://waste.example:8766/ --check-output .\접속점검.json
```

창 없는 점검은 성공 시 종료 코드 `0`, 연결 점검 실패 시 `1`, 보고서 저장 실패 시 `2`입니다. 실행 위치의 자료·설정 파일을 만들거나 업무 서버를 시작하지 않습니다. 개발 환경에서는 `python pc/desktop.py` 뒤에 같은 인자를 사용합니다.

설정은 사용자별 `LOCALAPPDATA/DongguWaste/desktop.json`에 저장됩니다. 인증서·개인키의 **경로**만 저장하며 파일 내용과 DB 비밀번호는 저장하지 않습니다. `--mode`, `--port` 등 명시적 실행 인자가 저장 설정보다 우선합니다. 동작 시험은 `DG_STATE`, `DG_OUT`과 `LOCALAPPDATA`를 모두 임시 경로로 분리하세요.
