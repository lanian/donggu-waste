# 보고서·숫자 배출표·KT 모바일 연결

**목표:** 일일작업일지·월보의 집계/조회/출력 기능을 만들고 서식은 이후 조정한다. 숫자 배출표는 앞자리0을 보존하는 원장으로 관리한다. 모바일 전화 버튼의 KT 앱 연결은 공식 호출 규격을 확인한다.

## 분리한 소유와 계약

- reports 담당: 기존 `pc/dgpc/reports.py`에 daily_report/monthly_report와 각각 CSV를 추가, 새 `tests/test_pc_reports.py`. 기존 stats 의미와 개인정보 제외를 유지한다.
- 배출표 담당: 새 `pc/dgpc/numbered_labels.py`, `tests/test_pc_labels.py`. 숫자문자열1~30자리·canonical number_key·입고/배부/사용/무효·최근20개 이력을 구현한다.
- UI 담당: 새 `screens/reports.js`, `screens/numbered_labels.js`, `tests/test_reports_labels_ui.py`. 기존 스타일과 읽기/쓰기 역할, 조회조건·초안·오류 재시도를 보존한다.
- root: migration7·서버/권한/라우터/인쇄·facade·통합회귀·문서·배포를 연결한다. 기존 AGENTS.md와 모든 타 작업을 보존한다.

## 보고서

보고서는 원자료 조회만 하며 마감·이월·확정·결재를 수행하지 않는다. 일일은 date, 월보는 YYYY-MM, 기준은 planned/received/completed를 선택한다. 기존 stats의 기간/총계/일자/동/품목/팀/세입을 사용하고 generated_at/source_note/하차 측정 입력건수를 더한다. 수거량은 현재 누적값이며 당일 증분이라고 표시하지 않는다. 세입은 납부일, 하차는 작업일이다. 주민명·전화·주소·메모·접수번호는 집계 보고서에 넣지 않는다. HTML 미리보기/인쇄와 CSV부터 제공하며 기관 제출 서식은 확정하지 않는다.

## 숫자 배출표

기본 범위는 번호 구간 입고→배부처 지정→접수/선택 품목 연결·사용→무효 및 이력이다. 사용자는 숫자 구성이라고 확인했고 추가 범위 질문은 대기 중이다. 구간은 같은 자릿수·1회5000장 이하로 제한한다. 원문은 TEXT로 보존하고 001/1 중복 등록 우회는 number_key 유일제약으로 막는다. 상태 AVAILABLE/DISTRIBUTED/USED/VOID, VOID는 복구하지 않는다. 같은 접수/품목으로 재사용 요청은 no-op, 다른 대상·취소/파기 접수·다른 접수 품목은 거부한다.

현재 접수번호 QR 표지 인쇄와 현장 STICKER_CHECK 과거기록은 변경하지 않는다. 새 원장은 인쇄만으로 사용 처리하지 않는다. 숫자만 담긴 표지 출력도 제공한다. 주민정보를 원장에 복제하지 않고 사유는 기존 audit_note와 request 연결을 사용한다. 쓰기는 ADMIN/INTAKE, 읽기/인쇄는 ADMIN/INTAKE/LEAD다.

## KT 모바일

사용자 의도는 수신번호 조회가 아니라 모바일 전화 연결 버튼을 KT 통화매니저 앱으로 넘기는 것이다. 공식 APP 기능과 API 안내는 확인했으며, 대상 번호를 전달하는 URI/Android intent/iOS scheme은 아직 확인되지 않았다. 확인되지 않은 scheme을 만들거나 개인 휴대폰 기본 다이얼러로 조용히 대체하지 않는다. 실제 통화·가입·로그인·외부 전송은 하지 않는다.

## 검증

각 담당 RED→GREEN 뒤 root가 임시 SQLCipher DB에서 migration6→7/실패 rollback/원자료 불변/PII 제외/역할/중복·동시성/읽기 전용과 실제 브라우저 API 연결을 확인한다. 기존 시작·업무 회귀와 버전/생성물 검사도 수행한다. 사용자 DB·8765 서버·현재 계정에는 적용하지 않는다. 커밋·원격 배포는 하지 않는다.

## 확인한 결과와 수정

- 보고서 단위 9개, 번호표 단위 14개, SQLCipher migration 3개, 실제 HTTP API 4개, 가상 API·실제 Chromium UI 30개 통과.
- root의 실제 서버/라우터 흐름에서 일지 인쇄·월보 CSV·입고·접수 연결·사용·인쇄·무효와 앞자리 0 보존을 확인했다.
- 독립 검토에서 발견한 기준별 일자표 제목, 조건 변경 뒤 늦은 CSV 저장, 연속 사용/무효 뒤 과거 조회 응답을 수정했다. 최대 30자리 표지 인쇄 잘림도 실제 화면 RED→GREEN으로 수정했다.
- 기존 전체 업무 회귀의 인위적 user_version 하향 시험은 과거 3~6단계 재실행만 하도록 분리했다. 실제 4→7/6→7 갱신 및 새 구조의 rollback 검증은 그대로 유지한다.

- 전체 Windows 배포본 `dist/desktop/v0.13.6/Donggu-PC-windows-x64.zip` 생성 완료. SHA256 `6d3c954cbb2412d1ba11809faadcee4798af1e42ad3a23f3ee4011adc7b4f6df`. 이전 버전은 보관했다.
