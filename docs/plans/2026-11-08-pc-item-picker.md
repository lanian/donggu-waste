# PC Item Picker Implementation Plan

**Goal:** 전화접수와 동별 접수에서 버릴 물건을 분류 또는 검색으로 찾고, 규격·수량·금액을 확인해 추가한다.

**Architecture:** 기존 `itemPicker(onAdd, {usagePath})`의 콜백과 수수료표·등록 payload를 유지한다. 공통 위젯 안에 분류별 물건 이름, 규격별 선택, 선택 요약과 수량 조절을 둔다. 스타일은 `.waste-picker`에 한정하며 서버·DB·수수료 자료와 이미 담은 품목의 단가는 변경하지 않는다.

**Tech Stack:** 기존 ES modules, CSS, Pretendard GOV, Python/Playwright, PyInstaller. 추가 의존성 없음.

## 설계와 범위

- 검색만 다듬으면 이름을 모르는 물건을 찾기 어렵고, 분류만 사용하면 이름을 아는 담당자가 느려진다. 분류와 검색을 함께 두고 별도 선택창 없이 현재 접수 양식 안에서 처리한다.
- 첫 화면부터 빠른 선택과 공식 분류 4개를 제공한다. 분류에서 물건명을 누르면 해당 규격을 비교한다. 검색은 기존 동의어·초성·규격 검색을 그대로 사용한다.
- 규격·부과 단위·단가를 분리해 보여주고 선택 표시를 명확히 한다. 선택한 물건, 수량 조절, 해당 품목의 확인분 금액과 추가 버튼을 함께 배치한다.
- 규격이 여러 개인 검색은 Enter만으로 첫 규격을 임의 추가하지 않는다. 방향키/Enter로 선택한 뒤 추가하며, 결과가 한 개인 정확한 검색은 빠르게 추가한다. 추가 후에는 검색에 초점을 돌리고 완료 안내를 표시한다.
- 표에 없는 물건은 기존 확인 대기 경로를 유지한다. 미확정 금액을 0원·무료로 표시하지 않는다. DONG 계정의 `usagePath:null`을 유지해 전역 사용 빈도 API를 호출하지 않는다.
- 기존 접수·수정·초안·중복·수량 단위·동 범위·부과 계산과 이미 담은 품목의 단가는 유지한다. 수량은 양의 정수만 추가한다.

## Task 1: 실제 위젯 회귀와 실패 확인

**Files:** 새 `tests/test_pc_item_picker.py`.

1. 실제 ES 모듈과 내장 수수료표를 Chromium으로 실행한다. API는 사용 빈도만 가상 응답으로 제어한다.
2. 첫 화면 분류, 이름→규격, 검색/초성, 선택 요약, 수량·미확정·사용 빈도 차단·키보드 사례를 작성한다.
3. 기존 위젯에서 새 요구가 실패하는지 먼저 확인하고 화면을 남긴다.

## Task 2: 위젯 구현

**Files:** `pc/ui/widgets.js`, `pc/ui/pc.css`의 전용 범위.

1. 분류·검색과 이름/규격 표시를 추가하고 기존 `fee_rate_id,qty,_row` 및 확인 대기 콜백을 유지한다.
2. 선택 요약·수량 증감·유효성·다음 품목 입력 초점을 구현한다. 느린 사용 빈도 응답이 현재 선택을 초기화하지 않게 한다.
3. 1440/980/390px, 밝게/어둡게·큰 글씨에서 줄바꿈·스크롤·버튼 위치를 확인한다.

## Task 3: 실제 접수 연결과 회귀

**Files:** `pc/ui/screens/dongs.js`, `tests/test_dong_work_ui.py`, `tests/e2e_pc.py`, `tests/test_dong_work_e2e.py`의 필요한 선택 조작만.

1. 동별 화면의 첫 규격 강제 선택 workaround를 제거해 위젯의 명시 선택 정책을 사용한다.
2. DOM 위치에 의존한 수량/Enter 조작을 실제 선택 절차와 접근 가능한 라벨로 바꾼다. 기존 금액·서버 결과 검사는 약화하지 않는다.
3. `npm test`, 새 위젯 시험, PC E2E, 동별 UI/실HTTP E2E, 버전·생성물 검사를 실행한다.

## Task 4: 실행 파일과 반영

**Files:** 버전 3곳, npm·CI 시험 연결, README.

1. PC/PWA를 0.14.1로 맞추고 전용 회귀를 CI에 포함한다.
2. 새 폴더에 실행 파일을 만들고 실제 EXE의 접수/품목 선택·저장·정상 종료를 임시 DB로 검증한다. 기존 배포본·실자료·서버는 보존한다.
3. 확인한 변경을 커밋·원격 CI로 검증한 뒤 메인 반영과 바로가기를 갱신하고 작업 브랜치를 정리한다.

개발과 검증은 별도 작업 폴더에서 순차 진행한다. 시험별 임시 폴더를 사용하고 전체 스크립트에 같은 `DG_TEST_DIR`을 공유하지 않는다.

## 검증 기록

- 기존 위젯에 새 시험 9개를 먼저 적용해 8실패·오류 0·기존 콜백 정상 대조 1개를 확인했다. 검색 결과의 40개 제한과 Enter 경계도 실제 Chromium에서 재현했다.
- 현재 위젯 회귀는 13개 통과(8.853초). 분류·규격, 모든 검색 결과, 동의어, 수량·부과 단위, 미확정·승인 단가, 키보드/IME/Ctrl+Enter, 지연 사용 빈도 응답과 DONG의 전역 호출 차단을 포함한다.
- 독립 검토에서 수량 라벨이 감소 버튼을 활성화하는 문제와 서버 상한 9999 누락을 재현했다. 전용 input label과 상한 검사로 수정하고 공식 실패→통과 및 독립 재검증을 마쳤다.
- 실제 SQLCipher/HTTP 전화접수에서 분류와 검색으로 4품목을 추가하고 화면 이동 후 초안을 복구해 Ctrl+Enter로 저장했다. 선택만 하고 담지 않은 5번째 품목은 저장되지 않으며 확인 대기와 개/쪽 단위를 보존한다.
- 밝게 15px/어둡게 17px × 1440/980/390px의 6화면을 검사했다. 980px에서 등록 바가 품목 추가를 가리는 실패를 먼저 확인하고 선택 영역의 스크롤 여백으로 보완했다.
- 기존 수수료 43개·상호운용 130개, PC 업무 E2E 114개, 동별 UI 59개와 동별 실제 HTTP E2E가 통과했다. 버전·생성물·JavaScript 구문·diff 검사를 통과했다.

실제 EXE와 원격 CI 결과는 실행 파일을 묶은 뒤 확인한다. 실제 사용자 자료·서버는 이 시험에 사용하지 않는다.
