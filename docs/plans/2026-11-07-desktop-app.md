# Windows 실행 앱 구현 계획

**목표:** 사용자가 CMD·Python 설치·서버 명령 없이 PC 업무를 시작하고 종료한다.

**구조:** Python/Tk 실행 창과 숨김 서버 자식을 한 배포 폴더에 묶는다. 실행 창은 준비·오류·재시도·업무 화면 열기·종료를 담당하고 기존 브라우저 업무 화면과 데이터·전송 규격은 유지한다. PyInstaller windowed 배포에 Python·SQLCipher·OR-Tools·키링·화면 자산을 포함한다.

## 작업 1 — 실행 앱

- `pc/desktop.py`, `pc/desktop_runtime.py`, `tests/test_desktop_app.py` 추가.
- 임시 DB로 최초 초기화·준비·재사용·충돌·오류·자신이 시작한 서버만 종료하는 회귀를 먼저 실패시킨다.
- 비밀번호는 마스킹 입력창에서 받아 자식 표준입력으로만 전달한다. 인자·설정·로그에 남기지 않는다.
- 사용자에게 자료 폴더를 표시하고 기존 자료 폴더를 선택할 수 있게 한다. 명시한 DG_STATE와 소스의 기존 자료 위치를 보존하며, 배포판 기본은 LocalAppData 아래 영구 폴더다. 자료를 자동 이동·삭제하지 않는다.
- 창 종료는 자신이 시작한 서버를 정상 종료한다. 이미 실행 중인 다른 서버는 재사용하되 종료하지 않는다.
- 바로가기 생성은 사용자의 명시적 앱 버튼으로 한다. 자동 시작·서비스는 등록하지 않는다.

## 작업 2 — 배포 구성

- `pc/dgpc/paths.py`에 frozen 자산 경로를 통일하고 기존 원본 실행 경로는 유지한다.
- 필요한 읽기 전용 JSON·PC UI·공유 web 모듈만 명시적으로 포함한다. DB·키·백업·로그·시험 자료는 포함하지 않는다.
- 버전·해시 고정 빌드 의존성, PyInstaller spec, Windows 빌드 명령과 경로 회귀시험을 추가한다.
- 실제 Windows EXE와 압축 배포본을 생성한다. 프로그램 파일과 사용자 업무 자료의 위치를 분리한다.

## 작업 3 — 통합 확인

- 소스 회귀와 생성된 EXE에서 각각 임시 SQLCipher DB·정적 화면 자산·API·노선 계산을 확인한다.
- 실제 GUI의 시작·오류·마스킹 입력·종료와 콘솔 없는 EXE 형식을 확인한다.
- 실행 파일을 가리키는 바로가기와 자료 폴더 영구성, 외부 서버 보존을 검증한다.
- 문서의 일반 사용자 경로를 실행 앱 중심으로 고친다. CMD는 개발·운영 보조로 표시한다.
- 기존 미커밋 수정·AGENTS.md를 보존하고 커밋·배포는 하지 않는다.

## 검증 기록

구현과 실제 실행 결과를 확인한 뒤 기록한다. 이전 CMD 시험의 성공을 새 앱의 성공으로 대신하지 않는다.

## 적용 결과

- 일반 사용자 시작점을 `Donggu-PC.exe`로 변경했다. 배포 폴더에 Python·SQLCipher·OR-Tools·Tk와 공개 화면 자산을 함께 담았다. CMD는 소스 운영 보조로 남겼다.
- 실행 앱은 상태·마스킹 비밀번호·다시 시도·자료 폴더 선택·바탕화면 바로가기·정상 종료를 담당한다. 바로가기는 자료 위치와 포트를 기억한다.
- 자식의 준비 표식과 실제 API를 함께 확인하며, Windows 관리형 서버는 포트를 독점한다. 다른 앱·기존 동구 서버는 종료하지 않는다.
- 관리형 종료는 수락한 요청·예약 작업·백그라운드 작업을 기다린다. idle·미완성 HTTP 연결은 읽기 대기 제한으로 무한 종료 지연을 막는다. CLI 서버의 기존 기본값은 유지한다.
- 새 자료는 LocalAppData 아래 영구 폴더를 사용하고 기존 자료 폴더를 선택할 수 있다. 키는 마스킹 창에서 자식 표준입력으로 전달하며 인자·설정·로그에 저장하지 않는다.

## 확인 한계

실제 EXE로 만든 가상 GUI 창과 서버 시작은 확인했다. Windows 화면 자동화는 `window capture timed out` 및 `failed to activate captured window`로 실패해 버튼의 직접 조작·렌더링 검증을 완료하지 못했다. 바로가기는 사용자 바탕화면 대신 임시 `.lnk`를 실제 생성하고 COM 메타데이터를 확인했으며, frozen 경로를 주입한 계약 시험이다. 이 증거를 실제 GUI 버튼 시험으로 보지 않는다.

실제 주민 자료·기존 사용자 DB·기본 바탕화면을 변경하지 않았다. 가상 GUI QA 프로세스는 종료했고 자식의 EOF 정상 종료·포트 해제를 확인했다. 기존 AGENTS.md와 미커밋 변경을 보존했으며 커밋·원격 배포는 하지 않았다. 기존 초기 모듈 간헐 연결 거절의 근본 원인은 별도 조사 항목이다.
