# 행정동 직제순 변경 구현 계획

**목표:** 설정 → 행정동에서 ↑·↓로 동을 옮긴 뒤 ‘순서 저장’으로 직제순을 바꾼다. 사용자가 이 방식을 선택했다.

**구조:** 기존 `dong.sort`를 사용하며 DB 구조 9는 유지한다. 관리자 전용 순서 저장 API가 전체 동 ID 목록과 읽었을 때의 순서를 검사하고 하나의 트랜잭션으로 반영한다. 모든 동 목록은 기존 공통 `area.list_dongs()` 정렬을 따른다.

**기술:** 기존 Python/SQLCipher·ES modules·HTML 표·버튼. 새 의존성과 공용 CSS 변경 없음.

## 동작과 보존 조건

- 사용 중지한 동까지 포함해 전체 동의 순서를 편집한다. 맨 위/아래 버튼은 비활성화하고 이동한 행으로 키보드 초점을 돌려준다.
- 순서 변경은 저장 전까지 화면에만 반영한다. 되돌리기는 순서만 복원한다. 입력 중인 동 이름·코드·요일·한도·판별 낱말은 유지한다.
- 순서 변경 중에는 행의 추가·저장·삭제를 잠그고 순서 저장 또는 되돌리기를 안내한다. 저장 중 반복 클릭과 이동은 막는다. 실패하면 입력/배치를 유지하고 재시도할 수 있다.
- 순서 저장은 ID·이름·담당 팀·사용 여부·접수·계정 연결을 바꾸지 않는다. 변경 이력은 한 건 남긴다. 같은 요청의 재시도는 중복 이력을 만들지 않는다.
- 다른 창에서 목록/순서를 바꿨으면 409로 알리고 자동으로 덮어쓰지 않는다. 접수 담당자·팀장·동 담당자는 정렬을 조회만 할 수 있다.
- 일반 행 저장에 순서가 없으면 현재 순서를 보존한다. 새 동의 순서가 없으면 맨 끝에 추가한다. 기존 API의 명시적인 `sort` 입력은 유지한다.
- 저장한 순서는 동별 관리·접수·사용자 담당 동 선택에 함께 적용한다. 기본 13개 자동 등록과 트레이 기능은 유지한다.

## 순서

1. `tests/test_dong_order.py`에 실제 SQLCipher/HTTP 회귀를 작성하고 미구현 실패를 확인한다.
2. `area.py`에 원자적 순서 저장과 일반 저장의 순서 보존을 구현하고 `server.py`에 관리자 API를 등록한다. `docs/routes.md`를 생성한다.
3. `settings.js`의 행 DOM을 유지하며 이동/저장/되돌리기와 대기·실패 상태를 추가한다. `tests/test_dong_order_ui.py`로 실제 HTTP/브라우저 입력 보존·재시도·목록 전파를 검증한다.
4. 새 회귀를 npm/CI에 연결하고 사용 안내를 갱신한다. 기존 동별·PC 업무 회귀와 버전/생성물 검사를 실행한다.
5. 버전을 0.14.3으로 맞춰 새 EXE 폴더에 빌드하고 실제 EXE에서 순서 저장·재시작 보존·권한을 확인한다. 마지막에 프로젝트 바로가기를 연결한다. 기존 배포본과 사용자 자료는 보존한다.

## 검증 결과

- 실제 SQLCipher/HTTP 회귀 7개 통과. 미구현 API의 404 실패를 먼저 확인했고, 관리자 권한·다른 역할의 403·누락/중복/잘못된 ID·다른 창과의 409·원자적 저장·연결/설정 보존·한 건의 변경 이력·재시도·일반 수정의 순서 보존·신규 동 맨 끝 추가를 확인했다.
- 실제 HTTP/Chromium 화면 회귀 15개 통과. 이동/되돌리기/저장 중 필드 초안과 초점 유지, 실패 후 재시도, 중복 클릭 차단, 일반 행 저장의 조회 완료 전 잠금, 목록 세 곳 전파, 새로고침 후 순서 유지와 화면 이동 뒤 늦은 응답 처리를 확인했다. 이전 저장의 응답이 더 최근 순서를 덮어쓰는 문제는 회귀 실패를 재현한 뒤 요청 세대 검사로 수정했다.
- PC 업무 로직 688개, 기본 동 10개, 기존 동별 업무 로직 23개, 원본 화면/가상 API 59개와 동별 실제 HTTP/브라우저 E2E 통과. PC 전체 화면 E2E 115개 통과.
- 버전 일치·생성물 대조·Python/JS 구문·`git diff --check` 통과. 새 관리자 API를 기존 권한 스냅샷 확장에 명시했다.
- 0.14.2 EXE에서 새 순서 API가 없어 실패하는 것을 확인했다. 새 0.14.3 EXE는 신규 자료 13개 동과 이전 8단계 자료의 8→9 보충/기존 설정 보존을 각각 통과했다. 두 경우 모두 실제 EXE에서 순서 저장 후 같은 자료로 프로세스를 다시 시작해 순서를 확인했고, Python 없는 PATH·공백 경로·자산·암호화 DB·실제 노선 계산·정상 종료를 검증했다. 실제 사용자 DB는 직접 열거나 변경하지 않았다.
- 배포 EXE: `dist/desktop/v0.14.3/Donggu-PC/Donggu-PC.exe`. ZIP SHA256: `a0eca078970fb8bc2b89356c39d60b0d4b0a397c78010be1d87fe96f52ccce08`.
- 프로젝트 `동구 PC 실행.lnk`의 기존 인자를 보존한 채 0.14.3 EXE로 연결하고 다시 읽어 확인했다. 기존 앱을 정상 종료한 뒤 바로가기를 다시 실행하면 새 버전을 사용한다. 기존 배포본·자료·트레이 기능·`AGENTS.md`를 보존했다.

- 화면은 Chromium 1440px 한 크기로 확인했다. 로컬 Python 3.14.3/Tk 8.6/Node 24 환경이며 Python 3.12 CI·전체 휴대폰 E2E·실제 EXE 트레이 메뉴 클릭은 이번에 실행하지 않았다. 커밋·원격 배포는 하지 않았다.
