# VWorld Reference Lookup Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** VWorld 키를 설정하고 전화 접수 중 위치를 참고 조회하되 결과를 접수·초안·QR에 저장하지 않는다.

**Architecture:** 사용자는 2026-11-11 진행을 요청했고 키/저장 조건은 아직 확인 전이라고 답했다. 기존 검토안의 PC 서버 호출 구조를 사용하며 이번 범위는 화면 참고 조회로 한정한다. 기본은 꺼짐. 관리자 설정과 접수 담당자 조회를 제공하고 외부 대기 중 DB 쓰기 잠금을 해제한다. 결과를 접수에 적용하는 기능은 만들지 않는다.

**Tech Stack:** 기존 Python/SQLCipher, urllib, ES modules, 기존 대화 상자·지도, unittest/실제 HTTP/Chromium.

---

## 승인된 범위와 보존 조건

- 기존 로컬/행안부 검색, 행정동·직제순·계정 범위·지도 핀·초안·QR 계약을 유지한다.
- VWorld는 별도 조회 버튼으로 명시적으로 실행한다. 이름·전화·메모를 전송하지 않고 건물 주소까지만 정리한다. 결과는 참고 상자에 표시하며 접수 필드에 대입하지 않는다.
- 키는 기존 암호화 비밀 설정으로 관리한다. 등록 서비스 URL은 관리자가 입력한 값만 사용한다. 다른 사이트의 Referer를 가장하지 않는다.
- 미등록·비활성·잘못된 주소·이름/전화 포함 입력은 외부 호출 전에 차단한다. 오류에는 공급자 원문, 주소, 키를 반환하지 않는다.
- 공급자 결과의 DB/브라우저 저장소/멱등 캐시 저장·접속기록 본문 기록·QR 반영을 하지 않는다. 성공 결과 출처는 브이월드(국토교통부)로 표시한다.
- 다른 화면으로 이동하거나 상자를 닫은 뒤 응답이 오면 폐기한다. 조회 중에도 닫기·취소가 가능하며 닫은 뒤 초점을 돌린다.

## Task 1: HTTP 계약과 회귀

**Files:** `tests/vworld_fixture.py`, `tests/test_vworld.py`.

1. 임시 SQLCipher/PC HTTP 서버와 루프백 공급자 서버로 설정·권한·요청 최소화·결과 비저장·오류·지연/세션 변경 검사를 작성한다.
2. `.venv/Scripts/python.exe tests/test_vworld.py`로 미구현 404/설정 누락 실패를 확인한다.

## Task 2: PC 서버 연결

**Files:** `pc/dgpc/vworld.py`, `settings.py`, `config.py`, `server.py`.

1. 비밀 키, 사용 여부, 등록 서비스 URL을 등록한다. 키 삭제 시 사용도 끈다. 기본은 꺼짐이다.
2. VWorld Geocoder 2.0 HTTPS 호출과 도로명/지번 건물 주소 정리, WGS84/유효 범위 검사, 고정 오류 문구를 구현한다.
3. `POST vworld/locate`를 ADMIN/INTAKE에만 허용한다. 느린 본문 뒤와 외부 조회 뒤 세션·현재 설정을 재검사한다. 네트워크 대기·결과 직렬화는 쓰기 잠금 밖에서 수행한다.
4. Task 1을 통과시킨다.

## Task 3: 참고 조회 화면

**Files:** `pc/ui/screens/vworld.js`, `settings.js`, `request.js`, `tests/test_vworld_ui.py`.

1. 기존 흰색/네이비 설정 양식과 동일한 입력·버튼·안내 구조를 사용한다. 공용 CSS와 공용 modal 계약은 바꾸지 않는다.
2. 미등록/실패/재시도/중복 조회 방지/닫기·초점 복귀/늦은 응답/접수와 초안 비반영 검사를 먼저 작성한다.
3. 설정 키·사용 여부·서비스 URL·고정 공공주소 연결 시험, 전화 접수의 참고 조회 상자, 독립 지도 미리보기를 구현한다. 조회 결과를 접수에 넣는 버튼은 제공하지 않는다.
4. 실제 PC HTTP/Chromium 회귀를 통과시키고 화면을 확인한다.

## Task 4: 통합·배포 검증

**Files:** `package.json`, `.github/workflows/ci.yml`, `tests/test_pc.py`, `docs/settings.md`, `docs/routes.md`, 운영 안내와 버전 3곳.

1. 새 회귀를 npm/CI에 연결하고 권한 표의 새 경로를 명시한다. 설정/경로 문서는 생성기로 갱신한다.
2. 새 회귀·PC 로직·기존 동별/접수 E2E와 버전/생성물/구문 검사를 수행한다. 결과와 환경 한계를 기록한다.
3. 검토 후 0.14.4 EXE를 별도 폴더에 빌드한다. 기존 EXE/자료를 보존하며 새 자산·설정·참고 조회 경로를 임시 자료로 검증한 뒤 프로젝트 바로가기를 연결한다.
4. 실제 키/등록 도메인/기관망은 사용자가 확인한 뒤 프로그램 설정에서 시험한다. 실서비스 성공으로 주장하지 않는다. 기존 혼합 변경 때문에 자동 커밋·푸시는 하지 않는다.

## 근거

- [국토교통부 지오코더 API 안내](https://www.data.go.kr/data/15101106/openapi.do): 저장 제한 문구를 2026-11-11 다시 확인했다.
- [VWorld 공식 QGIS 지오코더 클라이언트](https://github.com/V-world/V-QGIS/blob/main/utils/api_client.py): `/req/address`, `getcoord`, `service=address`, `crs`, `type=road` 요청 구조. 상세 웹 레퍼런스는 이 환경에서 응답 오류가 있었으며 실제 키 검증은 미실시다.

## 구현·검증 결과

- 실제 SQLCipher/PC HTTP/루프백 공급자 회귀 17개 통과. 키 미등록/기본 꺼짐, 키 가림·삭제 시 해제, 도로명/지번 건물 주소 정리, 이름/전화/비주소 접두부 차단, 위경도·응답 검사, 오류 원문 비노출, 외부 대기 중 DB 잠금 해제, 느린 본문/조회 응답 뒤 세션 재검사와 설정 변경 시 결과 폐기를 확인했다.
- 동일 `client_req_id`를 보내도 매번 공급자를 조회하며, 조회 전후 모든 DB 표가 동일하다. 로그에 주소·키·결과 좌표가 남지 않는 회귀도 통과했다. 초기 새 경로/설정 누락 실패를 확인한 뒤 구현했다.
- 실제 PC HTTP/Chromium UI 9개 통과. 설정/고정 공공주소 연결 시험, 미등록 안내, 실패 후 재시도, 접수 입력/초안 비반영, 조회 중 중복 실행 방지, 취소·닫기·초점 복귀·화면 이동과 늦은 응답 폐기를 확인했다. 지도 바탕의 네트워크 품질이나 실제 VWorld 좌표 정확도를 증명하는 검사는 아니다.
- 코드 검토에서 연결 시험의 인증/설정 재검사 누락과 주소 앞/중간의 비주소 문구 전송을 발견했다. 각각 실제 HTTP 실패 2개와 접두부 4사례 전송 실패를 재현해 수정했다. 표준/약칭/읍면/세종/숫자 가동 주소 양성 사례를 추가했다. 후속 읽기 전용 검토에서 추가 Critical/Important 문제는 발견되지 않았다.
