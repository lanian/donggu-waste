# VWorld 연동 검토

검토일: 2026-11-10. 대상: PC 0.14.3 소스. 상태: 구현 전 검토안.

후속 진행(2026-11-11): 사용자가 키/저장 조건 확인 전의 참고 조회를 선택했다. PC 0.14.4에 결과 비저장 조회를 구현했으며 [구현 범위와 검증 결과](2026-11-11-vworld-reference.md)를 참고한다. 아래 저장·전달 조건의 확인 필요 사항은 유지한다.

## 판단

기술적으로 연동할 수 있다. 이 프로그램에는 **기존 로컬 자료·행안부 검색을 유지하고 VWorld를 위치 조회의 보완 수단으로 추가하는 방식**이 적합하다. 다만 결과 좌표를 접수 DB에 저장하고 QR로 휴대폰에 전달하는 용도가 허용되는지 먼저 확인해야 한다. 현재 단계에서 운영 적용 가능으로 확정하지 않는다.

국토교통부의 [공공데이터포털 지오코더 API 안내](https://www.data.go.kr/data/15101106/openapi.do)는 무료·일일 최대 40,000건을 설명하면서, 결과를 별도 저장장치나 DB에 저장할 수 없다는 조건도 기재한다. 같은 페이지의 일반적인 이용허락범위 표시만으로 이 조건을 제외할 수 없다. 대상 API 버전과 승인 유형에 이 조건이 어떻게 적용되는지 제공기관 확인이 필요하다. 호출량 역시 발급받은 키의 실제 승인 조건을 따른다.

## 현재 구현에서 확인한 내용

- `pc/dgpc/addrsearch.py`: 로컬 도로명·지번·건물명 검색과 행안부 검색. 행안부 결과의 위치는 로컬 건물 식별 자료를 먼저 조회하고, 없을 때 좌표 승인키로 조회한다.
- `pc/dgpc/external.py`: PC 서버가 외부 API를 호출한다. 검색어의 이름·전화번호 검사, 5초 제한, 키/검색어가 없는 오류 메시지가 있다.
- `pc/dgpc/settings.py`, `config.py`, `pc/ui/screens/settings.js`: 등록 가능한 비밀 키는 행안부 검색·좌표와 카카오모빌리티 키뿐이다. VWorld 설정과 호출 코드는 없다.
- `pc/dgpc/intake.py:125`: 접수의 주소·위도·경도를 DB에 저장한다. 현재 저장 계약의 위치 출처는 `MANUAL`/`ADDR`이며, 화면은 `ADDR`를 건물 출입구로 설명한다. VWorld 결과를 같은 의미로 처리해서는 안 된다.
- `pc/dgpc/dong_work.py:155`: 동 담당자의 위치 찾기는 선택 동 권한을 확인한 뒤 로컬 자료만 조회한다. 일반 접수에 외부 조회를 추가해도 이 화면에 자동 적용되지는 않는다.

## 적용안 비교

| 방식 | 기대 효과 | 판단 |
| --- | --- | --- |
| 좌표 조회 보완 | 로컬 위치 자료에 없는 주소의 위치 확인 | 1차 권장. 저장 조건 확인 후 적용 범위를 확정 |
| 주소·건물 검색 확대 | 기존 검색에서 찾지 못한 후보 추가 | 2차. 후보 중복 제거·오래된 응답 차단·출처 표시 필요. 검색 API 자체의 저장 조건도 별도 확인 |
| 배경지도·항공사진 추가 | 배출 장소의 주변 확인 | 별도 과제. 주소 조회 연동에 지도 교체는 필요하지 않음 |

VWorld의 [주소 검색 공식 예제](https://github.com/V-world/V-world_API_sample/blob/master/%5B%EA%B2%80%EC%83%89%2C%20DATA%5D%20%EC%A3%BC%EC%86%8C%20%EA%B2%80%EC%83%89%20%ED%9B%84%20%ED%95%84%EC%A7%80%20%ED%91%9C%EC%B6%9C.html)는 도로명/지번 검색, 주소와 좌표 응답을 보여준다. 예제에 포함된 공개 키나 JSONP 방식을 제품에 복사하지 않고, 현재 PC 서버의 HTTPS 호출 구조를 사용한다.

## 권장 동작

1. 기존 로컬 자료와 행안부 조회를 우선한다. VWorld 조회는 관리자가 키를 등록하고 사용을 켠 경우에 제공한다. 외부 조회 대상은 사용자가 선택한 건물 주소로 제한하고, 이름·연락처·상세 동호수·접수 메모는 보내지 않는다. 주소 자체가 외부로 전송된다는 점은 설정과 조회 동작에서 알린다.
2. 조회 결과에는 공급자, 표준 주소, 위도/경도, 후보의 확실성 정보를 구분한다. `EPSG:4326`을 사용하고 경도/위도 순서, 국내·관할 범위, 숫자 유효성을 검사한다. 모호한 결과는 자동 확정하지 않는다. 대표 좌표를 건물 출입구나 실제 배출 위치라고 표시하지 않는다.
3. 순서 변경 기능과 기본 13개 동은 그대로 사용한다. 법정동 이름이나 검색의 구역 이름을 운영상 행정동으로 바로 확정하지 않는다. 현재 로컬 `dong_h` 자료를 우선하고, 확인이 안 되면 담당자가 고른다. 행정동/법정동은 별도 코드 체계이며 행안부도 [각 코드와 관할 연계 자료를 구분해 제공](https://www.mois.go.kr/frt/bbs/type001/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000052&nttId=117627)한다.
4. 키 미등록·인증 실패·한도 초과·시간 초과에는 기존 입력·지도 핀·선택 동을 유지하고 재시도 또는 지도 지정으로 이어진다. 기존 접수의 좌표를 일괄 덮어쓰지 않는다.
5. 동 담당자 화면은 담당 범위와 반환 필드 제한을 별도로 검토한다. 현재 `dong-work/geocode`의 쓰기 잠금 안에 외부 대기 시간을 추가하지 않도록 권한 검사·외부 호출·저장 단계를 설계한다.

## 실제 도입 전에 확인할 항목

- 대상 API의 결과 좌표/주소를 접수 DB·백업·QR·오프라인 휴대폰에 저장하거나 전달할 수 있는 범위. 불허 시 저장 가능한 공식 주소 위치 자료를 사용하는 방식을 유지한다. 사용자 확인이나 핀 이동만으로 저장 조건이 해소된다고 가정하지 않는다.
- PC 서버 호출에 필요한 키 유형과 등록 URL/도메인: 현재 `http://127.0.0.1:8765`, `localhost`, 사용자 변경 포트에 대한 허용 여부. 다른 사이트의 도메인/Referer를 가장하지 않는다.
- 기관망 HTTPS 접속, 프록시, 실제 승인 한도와 기간. 키는 기존 암호화 DB의 비밀 설정으로 관리하고 화면·로그에는 원문을 반환하지 않는다.
- 가상 자료·공공 건물 주소로 도로명/지번/검색 실패/좌표 범위/권한/시간 초과/실패 재시도/화면 이동 뒤 응답을 검증한다. 저장이 허용되면 위치 출처와 QR·휴대폰·백업 계약도 함께 검증한다.

## 검토의 한계

코드와 공식 공개 자료를 읽은 결과다. VWorld 상세 레퍼런스 페이지는 이 환경의 웹 조회에서 시간 초과가 발생했다. 키를 사용한 실제 API 응답, 인증 조건, 좌표 품질은 확인하지 않았다. 이번 작업은 이 검토 문서만 추가했으며 제품 코드·키·사용자 DB·실행 중인 앱은 변경하지 않았다.
