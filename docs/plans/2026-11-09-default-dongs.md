# 기본 행정동 자동 등록 구현 계획

**목표:** 새 자료와 기존 자료의 첫 업데이트에서 동구 기본 행정동을 자동 등록한다. 사용자가 승인한 범위는 행정동 자동 등록이며 VWorld 연동은 제외한다.

**구조:** DB 이전 9단계에서 공식 행정복지센터 목록의 13개 동 중 없는 이름만 추가한다. 같은 이름과 공백 차이만 있는 기존 이름은 그대로 둔다. 매번 접속할 때 보충하는 방식과 달리, 이후 사용자가 삭제한 동을 재시작 때 되살리지 않는다. 이전 전 암호화 사본과 실패 시 전체 롤백은 기존 이전 체계를 사용한다.

**기술:** Python, SQLCipher, 기존 DB 이전 체계. 새 의존성·외부 API 호출 없음.

## 데이터 계약

- 출처: [동구청 공식 누리집의 우리동네 행정복지센터](https://app.donggu.kr/index.es?sid=a1), 2026-11-09 확인.
- 충장동, 동명동, 계림1동, 계림2동, 산수1동, 산수2동, 지산1동, 지산2동, 서남동, 학동, 학운동, 지원1동, 지원2동.
- 기존 행의 ID·사용 여부·담당 팀·요일·한도·판별 낱말·코드·정렬과 접수/계정 연결은 변경하지 않는다.
- 새 동은 사용 상태로 등록한다. 담당 팀·한도·부과번호용 코드는 비우고, 요일·판별 낱말은 기존 빈 값 기본 규칙을 사용한다. 기관별 운영 조건과 법정동→행정동 관계를 임의 추정하지 않는다.
- 조회 전용 연결에서는 등록하지 않는다. 새 실행 앱이 기존 서버를 재사용하지 않도록 앱 버전은 0.14.2로 맞춘다.

## 구현·검증 순서

1. `tests/test_default_dongs.py`: 새 DB, 이전 8→9, 기존 설정·ID·접수·계정·키 보존, 공백 중복, 반복 실행, 삭제 유지, 읽기 전용, 롤백, 사전 사본과 주소 판별을 임시 암호화 DB로 재현한다. 미구현 실패를 먼저 확인한다.
2. `pc/dgpc/dong_defaults.py`에 공식 기준 목록과 누락 행 추가를 구현하고 `store.py`의 9단계에서 호출한다. `area.py`의 기존 주석을 갱신한다.
3. 이전 시험의 최신 단계 기대값을 갱신하고 새 회귀를 npm과 CI에 연결한다. README·동별 관리·운영 안내를 자동 등록 방식에 맞춘다.
4. 기본 동 회귀, PC 로직, 동별 권한/화면, 실행 앱 회귀와 버전·생성물 검사를 수행한다. 기존 트레이 변경은 유지한다.
5. `dist/desktop/v0.14.2/`에 새 실행 앱을 빌드하고 임시 자료로 새 등록과 8단계 자료 업데이트를 검증한다. 최종 확인 뒤 기존 프로젝트 바로가기만 새 EXE로 연결한다. 실제 사용자 DB는 직접 열거나 변경하지 않는다.

## 검증 결과

- 기본 동 회귀 10개: 수정 전 10개 실패, 수정 후 통과. 새 암호화 DB의 13개 동, 8→9 보충과 원래 동의 모든 열/접수/계정 연결/키/이력 보존, 공백 이름 중복 방지, 재시작 시 쓰기 없음, 삭제 유지, 조회 전용, 실패 롤백·재시도, 사전 사본을 확인했다.
- `test:pc` 구성 파일 전체를 로컬 `.venv/Scripts/python.exe`로 수행했다. PC 업무 로직 688개, 동별 권한 23개, 기존 배출표 이전 3개와 나머지 서버/세션/개인정보/기기/바인딩/실행기/보고서/배출표 검사 모두 통과했다. 기존 이전 시험의 최신 단계 기대값을 9로 갱신했다.
- 동별 화면 59개(원본 모듈·가상 API)와 실제 SQLCipher/HTTP/브라우저 동별 업무 종단 흐름 통과. PC 전체 E2E는 115개 통과했다. 기본 동 13개와 새 동 추가 행을 확인하고, 기존의 빈 동 목록 가정에 의존한 시험을 접근성 이름으로 고쳐 기존 등록·주소 판별·필터 흐름을 유지했다.
- 기존 실행 앱/서버 소유권 56개와 트레이 12개 통과. 버전 일치·생성물 대조·Python/JS 구문·`git diff --check` 통과.
- 옛 0.14.1-tray EXE는 새 등록 기준에서 실패하는 것을 확인했다. 최종 0.14.2 EXE에서는 신규 자료 13개 자동 등록과 기존 8단계 자료의 누락분 보충·기존 설정/ID/사용 여부 보존을 각각 통과했다. 두 경우 모두 Python 없는 PATH·공백 경로·자산·SQLCipher·실제 노선 계산·정상 종료를 확인했다. `--legacy-dongs` 검사도 Windows CI에 연결했다.
- 코드 검토에서 제품의 등록/보존/일회성 이전에 Critical/Important 문제는 발견되지 않았다. 지적된 기존 배출표 이전 시험의 8단계 기대값은 수정 전 실패 2개, 수정 후 전체 3개 통과로 확인했다.
- 배포 EXE: `dist/desktop/v0.14.2/Donggu-PC/Donggu-PC.exe`. ZIP SHA256: `6e83e1b12e0e5c63c7ace9bf7fd7fdf72a8079f31108ac8ab40f306df1a20a9c`.
- 프로젝트 `동구 PC 실행.lnk`를 새 EXE에 연결하고 기존 인자를 보존했다. 기존 실행 앱을 정상 종료한 뒤 다시 실행하면 선택한 자료 폴더에서 업데이트가 수행된다. 실제 사용자 DB는 이번 검증에서 직접 열거나 변경하지 않았다. 이전 배포본과 트레이 변경, `AGENTS.md`는 유지했다.
- 로컬은 Python 3.14.3/Tk 8.6/Node 24 환경이다. Python 3.12 CI·전체 휴대폰 E2E·실제 EXE 트레이 메뉴 클릭 검증은 이번에 실행하지 않았다. 커밋·원격 배포는 하지 않았다.
