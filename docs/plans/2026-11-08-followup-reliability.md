# 보고서 출력 일관성과 PC 실행 후속 점검

**목표:** 기본 보고서의 화면·인쇄 누락을 바로잡고, 기본 포트의 서버 시작·정상 종료를 재검증한다.

**구조:** `reports.py`의 기존 집계값을 화면과 인쇄에 그대로 표시한다. 집계식·API·DB 구조는 변경하지 않는다. 화면은 보고서 DOM에 한정하고, 인쇄 스타일은 `.report h2`의 페이지 연결 규칙만 추가한다. 기관 지정 서식은 현재 보류 상태다.

**환경:** Python/SQLCipher, ES modules, Chromium/Playwright, Windows 배포 EXE.

## 작업과 검증 기준

1. `pc/ui/screens/reports.js`: 보류를 포함하는 팀별 열을 ‘재방문·보류’로 정정한다. 세입 표에 기존 `refund_n`과 서버 `revenue.totals` 합계를 표시한다.
2. `pc/dgpc/operation_print.py`: 같은 세입 열·합계를 사용하고 기존 접수 경로별·감면별 집계를 출력한다. HTML 이스케이프와 개인정보 제외를 유지한다.
   `pc/ui/doc.css`의 보고서 제목에만 `break-after: avoid`를 적용해 제목과 표가 다른 페이지로 갈리는 것을 방지한다. 인라인 스타일을 허용하도록 CSP를 완화하지 않는다.
3. 보고서 전용 fixture 회귀로 누락을 먼저 재현하고 수정 후 통과를 확인한다. 기존 보고서 단위/API/UI/브라우저 흐름을 재검증하고 좁은 화면의 가로 넘침을 확인한다.
4. 새 배포본은 기존 버전과 별도 폴더에 만든다. 실제 EXE의 화면 자산·SQLCipher·인쇄·CSV·정상 종료를 임시 자료로 확인한 뒤 바로가기를 갱신한다.

## 기본 포트 점검 결과

- 점검 시작 시 8765 포트에 리스너가 없었고 실행 앱 프로세스도 없었다. 닫힌 포트의 HTTP 요청은 시간 초과로 끝났다. 이 현상만으로 방화벽이나 서버 내부 결함을 단정하지 않는다.
- 0.13.9 배포 EXE를 기본 포트 8765에서 임시 암호화 DB로 3회 시작·종료했다. Python 없는 PATH, 키링 비활성, 프록시 비활성 조건이다.
- 신규 DB의 API 준비는 5.628초, 같은 DB 재사용은 0.918초와 0.951초였다. 정상 종료는 0.575~0.593초였다.
- 매회 `/api/state`, `/`, `start.js`, `pc.js`, `core.js`가 HTTP 200을 반환했다. 종료 후 리스너가 없고 암호화 DB가 유지됐다.
- 증거: `D:/Temp/dg-default-port-fixture-tzp1pq8p/report.json`. 실제 사용자 자료에서 과거의 간헐적 연결 문제가 해결됐음을 뜻하지 않는다.

## 확인이 필요한 입력

- 사용자는 기관 지정 서식이 있음을 확인한 뒤 서식 확인 요청에 ‘우선보류’로 답했다. 기관 서식 맞춤은 보류하고 기본 보고서 표시 보완만 진행한다. 재개할 때 일일작업일지·월보 원본의 파일 경로 또는 문서명이 필요하다. 결재란·항목·페이지 구성은 추정하지 않는다.
- 기존 DB는 개발 폴더 `pc/state`와 실행 앱 기본 폴더 `%LOCALAPPDATA%/DongguWaste/state` 두 곳에 있다. 사용자가 현재 개발 단계임을 확인했다. 이번 작업은 운영 자료 연결을 진행하지 않고 임시 개발 자료로만 검증하며 기존 DB는 열거나 갱신하지 않는다.
- KT 모바일 앱 번호 전달은 공개된 공식 호출 규격이 미확인이다. `docs/KT-모바일-전화연결-검토.md`의 규격 확인 항목을 유지하며 추측한 딥링크를 배포하지 않는다.

## 완료 결과

- 기본 보고서 표시 9개 시험, 기존 집계 9개 시험, HTTP API 4개 시험, 보고서·배출표 UI 30개 확인이 root 재실행에서 모두 통과했다.
- 독립 코드 검토에서 변경 범위의 추가 결함은 발견되지 않았다. 기간 세입과 접수별 누적 납부의 구분, HTML 이스케이프, 빈 집계와 비영 환불을 확인했다.
- 실제 EXE의 390px 화면에서 동 미지정 행이 동·팀 표의 최소 폭을 늘려 본문 416px 넘침을 만들었다. 같은 자료로 회귀를 재현한 뒤 보고서 카드의 `min-width:0`으로 수정했고 동·팀의 2열 배치는 유지했다.
- A4에서 품목 분류 제목과 첫 행이 서로 다른 페이지에 놓이는 문제를 재현했다. 인쇄 HTML의 인라인 스타일은 CSP에 의해 차단되어 제외하고, 외부 인쇄 CSS의 보고서 전용 규칙으로 옮겼다. CSP가 있는 HTTP 문서에서 계산된 스타일을 검사하는 회귀를 RED→GREEN으로 추가했다.

- 실제 토큰 인쇄 응답에서 모든 보고서 제목의 계산된 `breakAfter`가 `avoid`임을 확인했다. 일지·월보 A4 PDF 각 2페이지를 렌더링해 4페이지 모두 확인했고, 품목 분류 제목과 첫 행이 같은 페이지에 있으며 필수 항목·문자 경계·개인정보 제외 검사를 통과했다. 증거: `D:/Temp/dg-report-release-433jytd2/report.json`, `pdf-review.json`과 같은 폴더의 PNG/PDF.
