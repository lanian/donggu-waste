## macOS 원인 확인과 후속 검증

작업 브랜치 CI `42476249146`에서 Windows 로직·실제 EXE 빌드와 시험은 통과했다. macOS는 시작 로그 이후 10초 스택에서 `socket.getfqdn → HTTPServer.server_bind`에 정지했다. 종료 대기 자체가 아니라 로컬 서버 생성의 역방향 이름 조회였다.

공통 Server는 `TCPServer.server_bind`로 주소를 바인딩하고 HTTP 메타데이터를 실제 숫자 주소·포트로 설정한다. `getfqdn`이 실패해도 Server/DesktopServer가 만들어지는 회귀는 수정 전 두 하위 사례 실패, 수정 후 바인딩 전체 4개 통과했다. 같은 DNS 의존을 가진 실행 앱 시험의 가상 HTTP 서버에도 숫자 바인딩을 사용하며, 이름 조회 실패 조건에서 실제 자산 준비 검사를 수행한다. 로컬 Windows에서 종료 수명 시험과 실행 앱 49확인은 통과했다. 네이티브 macOS 결과는 새 원격 실행에서 확인해야 한다.

새 개인정보·기기·바인딩 회귀는 PC 로직과 양 OS 참고 시험에, 배정·초안 회귀는 필수 화면 CI와 `test:e2e`에 포함했다. 독립 검토에서 확인한 과거 개인정보 충돌 판단 사유 단독 잔존과 배정 확정 중 재계산의 두 추가 경계는 별도 회귀로 보완한다.

후속 CI `42477150464`의 macOS 로직 작업은 통과했다. 역방향 DNS 회귀 2개 통과(Windows 전용 2개 제외), 실제 시작·작업 완료 대기·미완성 연결·정상 종료·DB 보존과 실행 앱 31확인이 포함된다.
