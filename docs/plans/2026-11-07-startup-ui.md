# 실행 앱 UI와 브라우저 시작 지연 개선

**목표:** 실행 창에서 실제 현재 단계와 주요 행동을 쉽게 찾고, 브라우저 첫 화면이 관계없는 화면 코드나 무응답 조회를 끝없이 기다리지 않게 한다.

## 확인한 원인과 범위

- 사용자가 지연 위치를 브라우저 업무 화면으로 확인했다.
- 기존 pc.js는 로그인 전에 18개 업무 화면을 포함한 27개 모듈을 정적으로 읽는다. 통계 모듈 하나를 보류한 실제 브라우저 시험에서 연결 오류 없이 로그인까지 멈추는 것을 재현했다.
- 첫 state를 로그인 화면에서 다시 읽고, 첫 API 및 홈 읽기에 제한 시간이 없어 모듈 오류와 응답 대기가 같은 초기 문구로 남는다.
- 실행 앱은 실제 키 입력 대기를 제외하면 시험 환경에서 약2.4~4.6초에 서버를 준비했다. 브라우저 렌더 완료와 서버 준비를 구분한다. 기존 queue 추측 조정은 하지 않는다.

## 구현

1. pc.js를 요청한 화면만 import하는 라우터로 바꾼다. 기존 역할·날짜·필터·초안·로그아웃 초기화와 늦은 응답 방어를 보존한다.
2. 첫 state/설정·홈 GET 읽기에만 명시적인 예산을 적용하고 응답 본문까지 포함한다. 변경 요청은 기존 계약을 유지하고 재로그인 입력 대기는 예산에서 분리한다.
3. 초기 화면에 단계별 안내와 실제 경과시간, 지연 시 사용자 재시도를 제공한다. 자동 새로고침·가짜 진행률을 넣지 않는다.
4. 실행 창을 별도 DesktopView로 분리해 남색/흰색·초록 주 버튼, 큰 상태·단계·경과시간, 긴 경로·오류, 하단 종료로 구성한다. runtime은 optional phase 콜백만 추가한다.
5. 새 EXE/ZIP을 빌드하고 실제 배포본에서 브라우저 첫 화면·SQLCipher·노선·정상 종료를 다시 확인한다.

## 검증

사용하지 않은 모듈 보류, API 헤더/본문 보류, 수동 재시도, 로그인 state 중복, 기존 역할·날짜·초안 회귀, 실제 Tk 상태·경계·큰 글씨·콜백을 확인한다. 브라우저/실행 시간과 화면 증거의 범위를 구분해 결과를 기록한다. 사용자 DB와 기존 AGENTS.md는 보존하고 모든 실행은 임시 자료·별도 포트로 한다.

## 구현·검증 결과 (2026-11-07)

- 로그인에서 읽는 모듈이 27개에서 5개로 줄었다. 비방문 통계 파일을 보류해도 로그인·오늘 현황을 표시한다. 최종 소스 시험 로그인은 약0.4~0.5초, 최종 EXE 브라우저 시험은 0.199초였다. 서버가 준비된 임시 환경의 표본이며 PC 전체 실행 시간이나 운영 자료 성능을 보장하지 않는다.
- 업무 화면 import 대기에 10초 제한을 적용했다. 첫 화면 파일 실패는 독립 시작 안내로 전달하고 이후 화면 실패는 기존 메뉴와 수동 재시도를 유지한다. 늦은 import는 캐시만 채우며 현재 화면을 덮지 않는다.
- 첫 state를 로그인 화면에 재사용한다. 명시한 GET만 헤더·본문을 포함해 제한하고 재로그인 입력 대기는 제외한다. 변경 요청의 재시도 계약은 유지했다.
- 지연 로딩 후 접수 화면에 재진입할 때 hashchange 리스너 등록 순서 때문에 조회가 시작되지 않는 회귀를 발견해 RED→GREEN으로 수정했다. routeEpoch를 eager core에 두고 기존 mount·경로·조회 순서 검사를 유지했다. 첫 비밀번호 변경 뒤 날짜 조건도 보존한다.
- 실행 앱은 단계·실제 경과시간, 큰 업무 열기, 별도 종료, 복사 가능한 경로·오류를 표시한다. 종료 대기 뒤 정상 exit0을 오류로 표시하던 분기도 종료 의도로 구분했다.
