# 전체 검토·개선 기록 (0.13.2)

**목표:** 현행 업무·전송 규격을 유지하며 기록 소실, 파기 정보 재유입, 배정 변경 오류와 인증 경쟁을 재현 시험으로 막는다.

**기준:** `f758cda`, 작업 브랜치 `fix/project-review-20261106`. PC/PWA는 빌드 없는 ES 모듈, PC 저장소는 SQLCipher다. 기존 `AGENTS.md`와 생성물은 직접 수정하지 않는다.

## 1. 기준 검증

- 버전·생성물 대조, 수수료·상호 운용, PC 로직, 두 화면 시험을 실행한다.
- 기존 결과: 버전·생성물 정상, 수수료 43개·상호 운용 130개·PC 로직 656개 통과.
- 화면 시험의 초기 로딩 실패는 별도로 재현하여 제품 결함과 시험 실행 환경 문제를 구분한다.

## 2. 백업·로그인

- `store.py`: 백업·복원에 `user_version`과 `auto_vacuum`을 보존한다. 미래 버전 백업은 현재 DB를 교체하기 전에 거부한다.
- `users.py`, `server.py`: 비밀번호 계산은 잠금 밖에서 수행한다. 검증한 자격의 유효성 확인, 현재 권한 조회, 세션 생성은 같은 DB 잠금 안에서 처리한다.
- `tests/test_review_server.py`: 실제 암호화 DB의 왕복과 Event로 제어한 계정 중지·암호 초기화·팀 변경 경쟁을 검사한다.

## 3. 결과·사진

- `results.py`, `photos.py`: 파기 후 늦은 파일이나 충돌 반영, 단독 백업이 개인정보를 되살리지 못하게 한다. 정상 순번·수신 확인·중복 처리와 익명 업무 값은 보존한다.
- 충돌함의 일반 기록 반영이 과거 수거 결과를 다시 적용하여 새 재방문 배정을 지우지 못하게 한다.
- 새 위치 기록이 적용될 때만 좌표를 갱신하여 주소 정정 뒤 옛 좌표가 복원되지 않게 한다.
- `tests/test_pc.py`: 각 순서를 독립적으로 재현하고 먼저 실패하는지 확인한다.

## 4. 저장 실패·재시도

- `web/store.js`, `web/core.js`: 저장 실패 상태를 암호문으로 임시 보존한다. 잠금 시 평문·키를 비우고 인증 후 복구하며, 자료 삭제·키 교체 시 폐기한다.
- 복구의 기준 디스크와 현재 디스크 비교·쓰기를 한 IndexedDB 트랜잭션으로 처리한다. 다른 창에서 바뀌었으면 덮어쓰지 않고 양쪽 기록을 유지하며 미저장 기록의 내보내기를 안내한다.
- `pc/ui/core.js`: 불확실한 요청은 경로·본문·요청 번호를 함께 고정한다. 본문을 고친 요청에 과거 성공 응답을 재사용하지 않는다.
- 24시간이 지나 서버의 멱등 응답 보관 기간이 끝난 불확실 요청은 다시 전송하지 않는다.
- `web/screens/export.js`: 공유 권한 거절 시 이미 만든 같은 암호화 파일을 다운로드로 전달한다. 사용자가 공유를 취소한 경우는 취소로 유지한다.
- `tests/test_review_ui.py`: 실제 브라우저·IndexedDB·PIN 경로와 응답 유실 후 재시도를 검사한다.
- `pc/ui/screens/requests.js`: 늦은 이전 조회가 최신 목록·쪽 번호를 바꾸지 못하게 하고, 로딩 중 이전 목록의 일괄 선택을 막는다. 기존 조회조건·선택 상태는 유지한다.

## 5. 통합·완료 조건

- 새 회귀시험을 기존 npm/CI 실행 경로에 연결한다.
- 각 결함의 RED→GREEN을 확인한 뒤 기존 전체 시험을 실행한다.
- 앱·서비스 워커·PC 버전과 운영 문서를 함께 갱신하고 생성물·차이를 검사한다.
- 변경 내용을 다시 리뷰하고 미해결 범위와 실행 환경을 결과 문서에 남긴다. 커밋·배포는 별도 수행하지 않는다.

## 6. 백업 성능 확인

SQLCipher 내보내기와 메타 변경을 하나의 저장점으로 묶었다. 오류 시 해당 저장점만 되돌리며 호출자가 열어 둔 트랜잭션은 보존한다.

실패한 PC 화면 시험 DB의 동일 복사본(581,632바이트, 접수 4건), 조회 연결 4개, 실제 작업 큐·DB 잠금을 사용한 같은 PC 비교다.

| 측정 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| SQLCipher 내보내기 | 53.094초 | 0.186초 |
| 전체 백업 작업 | 56.036초 | 0.805초 |

수정 후 백업은 정상 열림, 접수 4건, 구조 버전 6·`auto_vacuum=2`를 유지했다. 위 시간은 해당 시험 DB의 측정값이다.

## 7. 검증 범위

- 로컬 환경: Windows·PowerShell, Python 3.14.3, Node.js 24.20.0, Playwright Chromium. CI 설정은 Python 3.12·Node.js 22다.
- 가상 주민 자료와 임시 DB로 실제 SQLCipher·WebCrypto·IndexedDB·HTTP 서버 경로를 검사했다. 화면 시험의 카메라·주소 API는 시험 입력을 사용한다.
- 실제 Android/iOS 기기, 기관 서비스·업무 메일의 실제 전달, 운영 자료는 검증하지 않았다.
- 저장 실패의 임시 복구는 같은 창의 잠금·해제에 적용된다. 저장 공간 부족이나 다른 창과의 충돌이 남으면 안내에 따라 기록을 결과·암호화 백업으로 먼저 내보낸다.

## 9. 남은 조사 항목

PC 화면 자동 시험에서 모듈 요청이 간헐적으로 `ERR_CONNECTION_REFUSED`로 실패하고 초기 로딩에 머무는 사례가 있었다. 같은 환경에서 전체 PC 화면 시험 114개는 완료됐으며, 별도 기본 연결 대기열 5의 40회 재로딩·새 서버와 Chrome 6세트의 18회 로드, 대기열 128의 80회 재로딩에서는 재현되지 않았다. 연결 대기열을 원인으로 단정할 근거가 없어 해당 제품 설정은 변경하지 않았다. 요청 실패·콘솔·미완료 요청 진단을 시험에 추가했다. 실패 시점의 서버·TCP 상태를 추가로 확보하는 것이 남은 조사다.
