# Login Appearance Consistency Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 같은 브라우저에서 마지막으로 적용한 테마·글자 크기를 로그인 화면에서도 유지한다.

**Architecture:** 현재 `pc.js`는 로그인 후에만 `applyPrefs(boot.me.prefs)`를 호출한다. 로그아웃 직후에는 DOM 설정이 남지만 페이지를 다시 열면 사라져 시스템 기본 테마로 돌아간다. 기존 진입점에서 외형 값 두 개만 브라우저에 기억하고 로그인 화면의 모듈을 읽기 전에 복원한다. 로그인한 계정의 DB 설정이 항상 우선하며 다른 계정에 값을 복사하지 않는다.

**Tech Stack:** 기존 classic `pc.js`, ES module `core.js`, localStorage, Python 임시 서버/Chromium.

---

## 보존 조건

- 저장 범위는 `{theme, font}`뿐이다. 사용자 ID·이름·비밀번호·주민 자료·접수 초안은 추가 저장하지 않는다.
- 계정별 서버 설정과 `prefs` API는 유지한다. 새 브라우저의 첫 방문은 기존처럼 시스템 테마/보통 크기로 시작한다.
- 밝게/어둡게/자동과 글자 크기 14~17을 검증한다. 잘못된/깨진 저장값이나 저장소 차단은 로그인과 업무 시작을 막지 않는다.
- 시작 안내·화면 지연 처리·옛 정적 파일 허용 목록과 호환한다. 새로운 필수 시작 파일이나 공용 CSS 변경을 추가하지 않는다.
- 인증 세대는 로그인 화면 진입·새 로그인 요청 전·로그아웃·재인증 취소에서 바꾸고, 같은 계정의 정상 설정 재조회/재인증에서는 유지한다. 외형 저장을 같은 세대에서 순서대로 전송하고, 조회 시작 뒤 저장한 외형을 이전 bootstrap 응답으로 되돌리지 않는다.

## Task 1: 재현과 회귀

**Files:** `tests/test_pc_theme.py`, `tests/test_pc_theme_races.py`.

1. 실제 임시 서버에서 로그인 → 어둡게/아주 크게 → 로그아웃 → 새로고침 시 시스템 밝게/보통으로 돌아가는 실패를 먼저 재현한다.
2. 로그인 모듈이 준비되기 전 복원, 같은 계정 재로그인, 반대 시스템 테마, 자동 모드, 다른 계정 우선, 잘못된 값/저장소 차단을 검사한다.
3. `.venv/Scripts/python.exe tests/test_pc_theme.py`를 실행해 실패를 확인한다.

## Task 2: 외형 복원

**Files:** `pc/ui/pc.js`, `pc/ui/core.js`, `pc/ui/screens/login.js`.

1. `pc.js`의 기존 시작 순서에서 정규화한 외형 값을 복원하고, 이후 `applyPrefs`가 성공적으로 적용한 값만 기억한다.
2. `core.js`는 진입점의 공통 적용 함수를 사용하고, 단독 모듈/옛 진입점에서는 기존 동작으로 이어진다.
3. Task 1을 통과시키고 로그인·업무 화면을 실제 Chromium으로 확인한다.

## Task 3: 통합과 실행 파일

**Files:** npm/CI, 운영 안내, 버전 3곳.

1. 새 회귀를 연결하고 기존 시작 검사와 대표 테마/글자 크기 검사, 접수 화면 E2E를 수행한다.
2. 변경 파일 구문·버전/생성물·diff 검사를 수행하고 검토받는다.
3. 0.14.5 EXE를 별도 폴더에 빌드하고 실제 EXE 임시 자료/브라우저에서 로그인 전후 테마 보존을 확인한다. 기존 배포본·자료·바로가기 인자를 보존한 채 바로가기를 갱신한다. 실제 사용자 DB와 실행 중인 서버는 건드리지 않는다.

## 구현·검증 결과

- 실제 임시 SQLCipher/HTTP/Chromium에서 로그아웃 후 새로고침 시 외형이 바뀌는 원래 실패를 재현한 뒤 수정했다. 메인 회귀 14개 통과: 어둡게/밝게/자동, 글자 크기, 모듈 대기 중 복원, 같은 계정 재로그인, 다른 계정 우선, 잘못된 JSON/객체 타입, 저장소 차단을 확인했다.
- 초기 로그인 초점 예약이 빠르게 입력 중인 비밀번호 칸에서 아이디 칸으로 초점을 옮기는 기존 문제를 발견했다. 30ms 예약을 제어한 실제 브라우저 실패를 확인하고, 이미 로그인 입력/버튼에 초점이 있으면 이동하지 않게 수정했다. 위 14개에 해당 회귀가 포함된다.
- 경합 회귀 7개 통과: 이전 계정의 늦은 200/401, 테마·글자 크기 저장 순서, 같은 계정 재인증, 정상 bootstrap 재조회 중 큐 보존, 늦은 bootstrap 외형 폐기, 로그인 쿠키 적용/JSON 본문 대기 중 이전 대기 저장 차단을 확인했다. 각각의 지적 경계는 수정 전 실제 HTTP/브라우저 실패를 확인한 뒤 수정했다.
- 코드 검토에서 잘못된 font 객체의 변환 예외, 다른 계정으로의 늦은 응답/401 재전송, 정상 설정 재조회와 인증 세대 혼동, 로그인 응답 쿠키/본문 사이의 대기 저장 문제를 확인했다. 후속 읽기 전용 검토에서 추가 Critical/Important 문제는 발견되지 않았다.
- 기존 시작 회귀 묶음 5개 스크립트 통과(옛 진입점, 탐색 세대 6개, 지연 화면 모듈, 조회 예산 35개, 시작 단계/재시도). 로컬 첫 실행의 Chromium 경로 누락은 `CHROME`을 실제 설치 경로로 지정해 해결했다. 제품 코드 수정으로 숨기지 않았다.
- 대표 화면 검사 14개에서 레이아웃 관찰 0개·브라우저 오류 0개. 기존 동별 화면 59개와 실제 HTTP/브라우저 동별 E2E도 통과했다. 로그인/업무의 어두운 테마·큰 글씨는 1440px 화면에서 직접 확인했다.
