# 지연 요청의 세션 취소와 모바일 작업 정리 경합

**목표:** 계정 권한 취소 뒤 늦은 저장과 모바일 사진 준비 중 작업 정리로 생길 수 있는 손실을 실제 회귀시험으로 확인하고 수정한다.

**구조:** PC는 느린 본문을 DB 잠금 밖에서 읽는 동작을 유지하며, 저장 시작 시 현재 세션을 재확인한다. 모바일은 기존 결과·사진 확인 절차와 전송 규격을 유지하며 정리 직전에 현재 상태를 재검사한다. 기관 지정 서식과 KT 앱 호출 방식은 변경하지 않는다.

## 소유와 순서

1. PC 담당은 `pc/dgpc/server.py`와 `tests/test_pc_session_revocation.py`만 담당한다. 실제 임시 SQLCipher/HTTP에서 일부 본문 대기 → 계정 중지·암호 재설정·로그아웃 → 나머지 본문 전송을 재현한다. 취소된 세션은 401과 DB 불변, 유효한 세션은 저장 성공이어야 한다. 오류 응답 전송도 DB 잠금 밖에서 유지한다.
2. 모바일 담당은 `web/screens/export.js`와 `tests/test_mobile_cleanup.py`만 담당한다. 사진 준비, 정리 확인 대기 중 새 기록, 화면 이탈을 이벤트로 동기화해 재현한다. 새 기록과 사진은 보존하고 조건을 충족한 정상 정리는 성공해야 한다.
3. 각 담당은 실패를 먼저 확인한 뒤 최소 수정과 같은 시험의 통과를 기록한다. root는 독립 검토, 기존 시작·업무·상호운용 시험, 검증 명령 등록과 배포를 담당한다.

## 병합과 자료 보호

- 시작 시 HEAD는 `d4ef92a`, MERGE_HEAD는 `cb190f1`이며 `store.py`, `test_pc.py`가 인덱스 미해결 상태였다. 실제 파일에는 충돌 표식이 없고 문법 검사를 통과했다. 기존 병합·다른 작업창 변경을 되돌리거나 커밋하지 않는다.
- 본선에서 들어온 느린 본문/응답의 잠금 분리와 복원 보호를 유지한다. 이미 추가된 `Handler.setup()`의 DesktopServer 짧은 시간 제한 보존도 유지한다.
- 같은 저장소의 다른 시험 프로세스를 확인해 작업창 병행 여부를 사용자에게 물었다. 공유 서버 파일 수정은 확인까지 대기하며 독립 재현과 검증을 진행한다.
- 이후 다른 작업창의 병합 커밋 `593d52d`와 MERGE_HEAD 제거, 미해결 인덱스 해소, 별도 PC 시험 프로세스 종료를 확인했다. 서버 파일은 최초 해시와 같아 보류했던 최소 수정을 재개했다. root가 병합 커밋이나 인덱스 정리를 수행한 것은 아니다.
- 사용자는 다른 창에서도 진행 중임을 확인한 뒤 ‘다른곳 중지할게’로 답했다. 이 창에서 후속 수정·검증을 이어가며 다른 창의 프로세스를 자동 종료하지 않는다.
- 사용자 DB·계정·키링·기존 서버는 사용하지 않는다. 임시 암호화 DB와 가상 모바일 자료만 사용한다.
