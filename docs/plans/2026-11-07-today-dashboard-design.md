# Today Dashboard Design Implementation Plan

**Goal:** 오늘 현황에서 다음 처리와 선택일 주요 수치를 먼저 파악하고, 배차·처리할 일·팀/동별 진행을 쉽게 확인하도록 개선한다.

**Architecture:** 기존 화이트·딥네이비와 Pretendard GOV, ES module, API/권한/날짜 계약을 유지한다. 표시 마크업은 `screens/home.js`, 스타일은 `.today-dashboard` 범위에서만 바꾼다. 다른 업무 화면의 공통 스타일·서버·DB는 변경하지 않는다.

**Tech Stack:** 기존 HTML/CSS/JavaScript, Playwright, PyInstaller. 새 라이브러리·외부 자산 없음.

## 설계

기존 사용자 선택인 단정한 화이트·딥네이비 업무형을 적용한다. 색상만 바꾸는 안, 업무 우선 계층을 다듬는 안, 그래프 중심으로 재구성하는 안 중 두 번째를 선택했다. 다음 처리 → 주요 수치 → 배차·처리할 일 → 팀/동별 진행 → 운영 점검의 순서다. 근거 없는 추세·증감·실시간 수치는 추가하지 않는다.

주 동작과 5단계는 유지하며 다음 처리 영역을 네이비로 강조한다. 지표는 한 묶음으로 정리하고 숫자·단위를 분리한다. 완료율은 기존 계산값을 문자·진행 막대로 함께 표시한다. 관리자 준비 점검은 운영 점검 영역으로 옮긴다. 지도 아래 빈 공간과 긴 오른쪽 목록을 줄이도록 팀/동별 진행을 독립된 두 열로 배치한다.

## 구현과 검증

1. `pc/ui/screens/home.js`: 표시 블록 분리·재배치·단위·완료율 접근성. 기존 링크/필터 콜백/5단계/권한/미회수 시점/10초 제한/필수·선택 조회/지도 노드는 보존한다.
2. `pc/ui/pc.css`: 오늘 현황 하위에만 카드·버튼·표·상태·간격·반응형 스타일을 추가한다. 밝게/어둡게·큰 글씨·키보드 포커스를 유지한다.
3. 기존 `tests/test_workflow_pc.py` 순서 기대를 제목 → 업무 우선 → 지표 → 운영 점검으로 조정한다. 실제 역할/날짜/재전송/이동 회귀는 그대로 둔다.
4. `test_pc_design.py`: 1440/1280/980/390px와 밝게/어둡게·15/17px 실제 임시 SQLCipher 서버 캡처·가로 넘침·주 버튼·키보드 및 접수 동작 검증. 변경 전 대표 14화면은 레이아웃 문제/브라우저 오류 0개, `D:/Temp/dg-design-vkqks42c`에 기록했다.
5. 별도 역할·날짜 업무 회귀, 버전/생성물/구문 검증 후 새 배포본으로 만들고 바로가기를 연결한다. 사용자 서버·DB·계정과 기존 배포본은 보존하고 원격 배포·커밋은 하지 않는다.

참고: [Fluent 2 Typography](https://fluent2.microsoft.design/typography). 수치는 기존 PC 반영 자료 기준이며 휴대폰 미전송 결과를 실시간으로 표현하지 않는다.
