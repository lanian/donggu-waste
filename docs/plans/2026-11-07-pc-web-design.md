# PC 업무 웹 디자인 개선

**목표:** 사용자가 선택한 화이트·딥네이비 업무형을 적용하고 핵심 처리 흐름을 빠르게 찾게 한다.

## 팀과 범위

- 시각 디자인: 로그인·공통 shell 마크업·일관된 SVG 아이콘. `pc/ui/pc.js`의 표시 부분과 `screens/login.js`만 수정한다.
- 업무 UX: `screens/home.js`에서 실제 다음 처리 CTA를 단계 설명보다 먼저 배치하고 선택일 처리할 일을 우선한다. 판단·수치·권한·날짜·초안은 유지한다.
- 접근성 QA: `tests/test_pc_design.py`, 가상 자료·임시 서버의 실제 Chromium에서 화면·주요 동작·키보드·크기·테마를 확인한다.
- 통합: 공통 `pc.css`의 토큰·shell·폼·표·로그인·현황 반응형을 정리하고 기존 회귀·배포 검증을 수행한다.

## 디자인 기준

밝은 상단 바, 딥네이비 sidebar, 회백색 작업 배경, 화이트 카드, 작은 청록 강조를 사용한다. 현재 로컬 Pretendard GOV와 상태 색 의미를 유지한다. sidebar·button·input·table의 선·간격·크기를 통일하며 본문과 표가 지나치게 커지지 않게 한다. 그림자와 모션은 절제하고 동작 축소 설정을 지킨다.

로그인은 브랜드 안내와 입력 영역을 두 열로 정리하고 작은 화면에서 한 열로 바꾼다. 실제 서버 상태를 추측하거나 가짜 지표를 넣지 않는다. 기존 로그인 라벨·Enter·오류·초기 설정·비밀번호 변경을 보존한다.

오늘 현황은 제목/기준일 → 다음 처리 → 5단계 → 준비·경고 → KPI → 지도/처리할 일 순서로 정리한다. 날짜·수치·상태·권한·배지·각 링크는 그대로 유지하고 위험 안내를 장식 때문에 숨기지 않는다.

## 실행·검증

1. 현재 파일·대표 화면 before를 보존한다. 기존 AGENTS.md와 모든 타 작업을 덮어쓰지 않는다.
2. 표시 구조와 공통 스타일을 병렬 구현하되 파일 소유를 분리한다. API/backend/데이터 구조는 변경하지 않는다.
3. 1440/1280/980/390 너비, light/dark, 큰 글씨의 실제 화면·overflow·주요 액션·focus·오류를 확인한다. 인위적으로 잘라낸 텍스트나 숨긴 문제로 통과시키지 않는다.
4. 시작/역할·날짜·초안/접수 stale 회귀와 PC 업무 E2E를 확인한다. 새 프레임워크·CDN·이미지 요청은 추가하지 않는다.
5. 적용 후 캡처와 별도 배포본을 제공한다. 실행 중 사용자 서버·실제 계정/DB·다른 프로그램은 수정하지 않는다. 커밋·원격 배포는 하지 않는다.

접근성 기준은 W3C WCAG 2.2의 텍스트 대비·명확한 focus, 동작 축소는 MDN의 prefers-reduced-motion 지침을 참고한다. 전수 WCAG 인증으로 표현하지 않는다.

## 구현 결과

- 변경한 UI 파일은 `pc.css`, `pc.js`의 표시 부분, `screens/home.js`, `screens/login.js`, `screens/requests.js`다. 새 자산 주소·CDN·폰트·라이브러리 요청을 추가하지 않았다.
- 공통 shell은 화이트 상단/딥네이비 sidebar, 일관된 SVG, 아바타/이름 묶음으로 바꿨다. 밝게/어둡게/자동과 글자 설정을 유지한다.
- 실제 다음 처리 CTA를 5단계 앞에 두고 기준일 라벨을 표시했다. 선택일 처리할 일을 전체기간 밀린 일보다 먼저 보여준다. 기존 판단·수치·경고·권한·href·콜백은 유지했다.
- 접수 생성 버튼을 필터 아래에서 제목 옆으로 옮겨980/390 너비에서 보이게 했다. 날짜 입력 셀의 wrapping과 예약 날짜 카드 폭을 고쳐 텍스트 겹침·잘림을 없앴다.
- 시각 담당의 빠른 조회 행 정렬과 dark 검색 버튼 hover 대비 지적2개를 수정했다. CSS 이외의 상태 로직은 바꾸지 않았다.
