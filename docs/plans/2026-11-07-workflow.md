# 앱 업무 흐름·PC 간편 실행 개선

**목표:** PC와 휴대폰에서 다음 업무를 찾아 바로 이어가고, Windows PC 프로그램을 파일 하나로 실행한다.

사용자가 PC·휴대폰 전체 흐름을 선택하고 PC 구동 간편화를 추가 요청했다. 기존 미커밋 안정성 수정과 업무 데이터·전송 규격은 보존한다.

## PC 업무 이어하기

- 오늘 현황 상단에 접수 → 배정 → 목록 전달 → 결과 확인 → 마감 순서를 표시한다.
- 현재 역할·선택 날짜의 실제 상태로 주요 행동 하나를 제안한다. 미배정은 기존 조회 API의 정확한 건수를 사용하고, 목록 전달은 현재 배차의 최신 전송만 본다.
- 관리자·접수 담당자·팀장·수거팀의 권한에 맞는 이동만 제공한다. 저장·배정 확정·마감·승인을 자동 실행하지 않는다.
- 선택한 날짜는 배정·목록 전송·마감 화면에 전달한다. 기존 계산·편집 초안은 날짜와 함께 보존한다.

## 휴대폰 지금 할 일

- 기존 안전 경고·수신 코드 안내 뒤에 주요 행동 카드 하나를 둔다.
- 기기 등록, 현재 날짜의 수거 이어가기, 지난 결과 전달, PC 반영 확인, 사진 회수와 정리를 구분한다.
- 연락 기록이 생길 때마다 전송을 강요하지 않는다. 파일을 만들었다는 이유로 PC 반영·사진 회수 완료로 표시하지 않는다.
- 단독 모드는 접수·수거·암호화 백업으로 안내한다. 검색·필터·방문 순서와 기존 버튼을 유지한다.

## Windows PC 실행

- 루트 실행 파일에서 환경 확인 → 필요한 초기화 → 서버 준비 확인 → 브라우저 열기를 진행한다.
- 이미 실행 중인 앱은 재사용하고 다른 프로그램의 포트는 건드리지 않는다.
- 첫 설치는 고정 의존성만 사용한다. 비밀번호 입력이 필요하면 현재 콘솔에서 받으며 숨김 서버가 입력을 기다리게 두지 않는다.
- 시험은 임시 암호화 DB·별도 포트·브라우저 비활성 옵션으로 수행한다.
- 초기 화면 모듈이 연결 오류로 실패하면 오류 안내와 사용자가 누르는 다시 불러오기 버튼을 제공한다. 연결 원인 조사와 구분하며 자동 재시도는 하지 않는다.

## 검증

각 상태·권한·날짜 연결·실행 재사용을 실제 브라우저/HTTP 경로에서 먼저 실패하는 시험으로 확인하고 구현한다. 화면 배치와 좁은 폭은 캡처로 확인한다. 버전·생성물·구문과 변경 검사를 실행하고 결과를 아래에 기록한다.

## 적용·검증 결과 (2026-11-07)

PC·휴대폰 버전을 0.13.3으로 맞췄다. `Donggu-PC.cmd`와 `tools/start_pc.ps1`, 초기 화면 오류 안내, PC·휴대폰 다음 행동, 날짜 연결을 적용했다. 새 시험을 npm·CI에 연결하고 README·운영 문서를 갱신했다. 기존 AGENTS.md와 이전 안정성 수정은 보존했다. 커밋·배포는 하지 않았다.

| 확인 | 결과 |
| --- | --- |
| `python tests/test_workflow.py` | 46개 통과: 초기 로딩 3 + 날짜·초안 5 + PC 13 + 휴대폰 25 |
| `python tests/test_pc_launcher.py` | 19개 통과: 실제 SQLCipher·공백 경로·동시 실행·기존 서버 재사용·포트 충돌·키 오류·의존성 안내 |

| 버전·생성물·JS/PowerShell 구문·`git diff --check` | 통과 |

가상 자료와 임시 DB·PIN·IndexedDB를 사용했다. PC 1440/980px, 휴대폰 390px 일반·야외 고대비, 초기 오류 화면을 캡처로 확인했다. OS 키 저장소를 쓰지 않는 시험 환경에서는 실제 콘솔 비밀번호 입력 → 준비 API 확인 → Ctrl+C → 리스너 종료·DB 보존까지 확인했다. 실제 휴대폰 하드웨어와 기본 브라우저 자동 열기는 별도 수동 확인 범위다.

## 남은 조사와 증거 한계

Windows에서 초기 JS 일부가 간헐적으로 `ERR_CONNECTION_REFUSED`가 되는 현상을 재현했다. 오류 직후에도 같은 서버의 `/api/state`는 200이고 해당 PID의 포트는 LISTEN이었다. 대기열 5/128 교대 비교만으로 원인을 확정하지 못해 서버 대기열은 바꾸지 않았다. 초기 로더는 이 실패에 안내·수동 다시 불러오기를 제공하며 연결 오류 자체를 해결했다고 보지 않는다.

중간 시험에서 이전 Home DOM을 대상으로 키를 누르는 fixture 경합도 별도로 확인했다. 시험이 실제 render 완료를 기다리도록 동기화했으며 임의 sleep이나 네트워크 자동 재시도는 넣지 않았다. 마지막 통합 실행은 기본 서버 설정으로 46개 통과했으나, 이 결과만으로 간헐 연결 문제가 사라졌다고 판단하지 않는다.
