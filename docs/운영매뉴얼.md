# 동구 대형폐기물 접수·수거 관리 — 설치·운영 매뉴얼 (v0.7.0)

이 매뉴얼은 PC 프로그램과 휴대폰 앱을 처음 설치하는 운영 담당자, 매일 쓰는 접수 담당자·수거팀을 위한 것입니다. 시제품 단계이므로 실제 주민 정보로 운영하기 전에 마지막 장의 "운영 전 확인"을 마쳐야 합니다.

## 1. 구성과 준비물

| 구성 | 설명 |
| --- | --- |
| PC 프로그램 | 접수·배정·노선·QR 전송·결과 병합·마감. 이 PC(127.0.0.1)에서만 열리고 자료는 암호화 DB 한 파일에 저장 |
| 휴대폰 앱 | Android·아이폰 공통 웹 앱. 앱 코드만 인터넷에서 받고, 업무 자료는 휴대폰 안에만 암호화 저장 |
| 수수료표 | 동구 [별표 1] 원문 HWP와 변환본 169행. 확인 필요 8행은 PC에서 개정·승인으로 확정 |
| 주소 위치 자료 | 행정안전부 도로명주소 위치정보요약DB(선택). 넣으면 주소로 위치를 찾음 |

준비물: Windows 10/11 또는 macOS PC(웹캠 있으면 결과 QR 회수 가능), Python 3.12, 업무용 휴대폰(Android 10+ Chrome, iOS 16.4+ Safari), 승인된 업무 메일, 사진 회수용 보안 매체.

## 2. PC 설치 (운영 담당자)

1. Python 3.12 설치 후 명령 창에서 `pip install -r pc/requirements.txt`
2. `python pc/pc_tool.py init` — 암호화 DB와 PC 키 생성. DB 키는 운영체제 키 저장소에 보관되며, 키 저장소를 쓸 수 없으면 12자 이상 DB 비밀번호를 정합니다. **DB 키 보관 책임자를 정하고 봉인 보관**하세요(잃으면 DB와 백업을 열 수 없음).
3. `python pc/pc_tool.py serve` → 브라우저에서 `http://127.0.0.1:8765`
4. 운영 관리자 계정 만들기(아이디, 10자 이상 비밀번호)
5. 설정
   - 휴대폰 등록: 휴대폰 앱 [기기 등록]으로 등록 QR을 비추고, 휴대폰의 기기 코드를 붙여 넣은 뒤 양쪽 6자리 지문이 같은지 확인
   - 수거팀·차량: 팀 이름, 연결 휴대폰, 적재 용량(m³), 근무시간
   - 노선 계산: 차고지 좌표, 반입지 좌표(적재가 차면 들러 비움), 종료지(비우면 차고지), 지점당 작업시간, 로컬 OSRM 주소(있으면)
   - 주소 위치 자료: 위치정보요약DB 파일 → [미리보기]로 열 배치와 표본 위치 확인 → [이대로 가져오기]. 큰 파일은 `python pc/pc_tool.py import-addr <파일·폴더> --region 동구 --preview` 후 `--preview` 없이 실행
   - 백업 폴더, 사진 보관 기간(기본 90일)
6. 사용자·이력: 접수 담당자·수거팀 계정을 임시 비밀번호로 추가(첫 로그인 때 변경)
7. 수수료표: 시행일·확인자 입력, 확인 필요 8행 중 확정된 행의 단가와 근거 입력 → [개정안 저장] → **다른 담당자**가 원문과 대조해 [승인]. 승인 전·시행일 전에는 적용되지 않습니다.

## 3. 휴대폰 설치 (수거팀)

1. 업무 휴대폰 브라우저로 `https://lanian.github.io/donggu-waste/` 열기 → 공유 메뉴 → **홈 화면에 추가**
2. 앱 PIN(숫자 6자리 이상) 정하기. 5분 동안 조작하지 않거나 다른 앱(전화 등)에 2분 넘게 있으면 잠깁니다.
3. 사용 방식: **PC와 연결해서 사용**(권장) → [기기 등록] (2장 5번)
4. 앱 새 버전이 나오면 상단에 "새 버전이 있습니다 [업데이트]"가 뜹니다. 미전송 결과를 보낸 뒤 누르세요.

## 4. 하루 업무

### 접수 담당자 (PC)

1. **접수**: [+ 전화 접수 등록] → 이름·연락처·배출 주소·상세 위치·품목(이름·규격·초성 검색)·수량·예정일·방문 약속. [주소로 위치 찾기] 또는 지도를 눌러 배출 위치 지정. 같은 연락처·주소는 중복 후보로 경고(자동 병합 없음)
2. 수정은 사유 필수(이전 내용은 버전으로 보존), 취소도 사유와 함께
3. **배정·노선**: 날짜·팀 선택 → [노선 계산] → 미배정 사유 확인(위치 없음은 [주소 자료로 찾기] 또는 위치 지정) → 순서 조정 → [배정 확정]
4. **목록 전송**: [QR 표시] → 수거팀 휴대폰 [오늘 목록 받기] → 휴대폰의 수신 확인 코드 8자리 입력
5. 전송 뒤 접수를 고치면 "재전송 필요"가 뜹니다. 급한 변경은 전화로 먼저 알리고 QR을 다시 표시하세요.

### 수거팀 (휴대폰)

1. 오늘 목록: 진행 띠, 노선도형 순서, 반입지 하차 지점 표시, 이름·주소·품목 찾기
2. 상세: [📞 전화] → 연락 결과 기록(통화 완료가 수거 완료로 바뀌지 않음), 통화로 약속한 재방문 날짜·시간 기록
3. 품목: 접수 수량·현장 확인·실제 수거를 각각 기록, 남은 품목은 미수거 사유 선택. [+ 현장 품목 추가]
4. 사진(수거 전·후)은 앱 안에만 암호화 저장, 갤러리에 남지 않음
5. 수거 결과: 완료 / 일부 수거 / 미수거 / 확인 대기
6. 반입지에서: [하차 기록] — 시각·부피·중량
7. 업무 끝: [결과 보내기] → 결과 파일(.dgr)을 **승인된 업무 메일**로 전송. 메일이 안 되면 [PC 화면 카메라로 보내기 (QR)] → PC [결과 가져오기]의 [웹캠으로 읽기]
8. PC 담당자가 알려 준 **보관 종료 확인 코드** 입력 → 반영 확인
9. [사진 파일 만들기](.dgp) → 보안 매체로 PC에 전달 → **사진 회수 확인 코드** 입력 → 그 뒤에만 사진 삭제 가능

### 접수 담당자 (PC, 오후)

1. **결과 가져오기**: 결과 파일·사진 파일 넣기 → 확인 코드를 수거팀에 알려 줌
2. **충돌함**: 오래된 목록·다른 팀·취소된 접수의 결과는 사유를 보고 반영 또는 거부
3. **접수 상세 → 수납 기록**: 담당자가 확인한 납부·환불 기록(계산 금액 ≠ 수납 완료)
4. **일일 마감**: 결과 미회수·재방문 후보·금액 확인 대기·수납 확인 필요·사진 미회수·충돌 확인, 하차 기록 확인 → [마감 기록](미처리는 이월)

### 운영 관리자

- 매일: 오늘 현황 확인, 백업(설정 → 지금 백업, 별도 백업 비밀번호)
- 매주: 사용자·변경 이력 점검(로그인 실패, 취소·수정 사유), 기간 지난 사진 정리
- 수수료표가 바뀌면: 원문 HWP를 받아 `tools/convert_fee_hwp.py`로 변환 → 앱 새 버전 배포 → PC 수수료표 화면에서 시행일·확인 필요 행 개정·승인

## 5. 예외 처리

| 상황 | 처리 |
| --- | --- |
| 휴대폰 분실 | 설정 → 등록된 휴대폰 → [분실 처리]. 그 기기로는 목록을 보내지 않고 결과도 받지 않음. 오프라인 기기 원격 삭제는 불가 → 보안 담당 보고 |
| 휴대폰 고장·교체 | 새 휴대폰 등록 → 팀 연결 변경 → 목록 재전송. 옛 휴대폰의 미전송 결과는 복구 불가하므로 매일 결과를 보내야 함 |
| 결과 파일 "검증 실패" | 다른 PC용·변조·손상 파일. 아무것도 반영되지 않음 → 휴대폰에서 다시 만들기 |
| 같은 파일 두 번 | "이미 가져온 파일" 표시, 중복 반영 없음 |
| 충돌 | 충돌함에서 사유와 함께 반영/거부. 거부해도 원 기록은 남음 |
| 금액 확인 대기 | 0원으로 확정하지 않음. 수수료표 개정·승인 후 새 접수부터 확정 단가 적용, 기존 건은 담당자가 확인해 수납 기록 |
| 위치를 못 찾음 | 도로명·건물번호 확인, 지도에서 직접 지정. 주소 자료 위치는 건물 출입구 기준이므로 배출 위치와 다르면 지도로 보정 |
| 관리자 비밀번호 분실 | DB 키를 가진 사람이 `python pc/pc_tool.py reset-admin` |
| 지도가 안 뜸 | 인터넷 연결 확인. 지도 없이도 접수·노선(직선거리)·전송은 됨 |

## 6. 백업과 복구

- 백업: 설정 → 백업 비밀번호(12자 이상, DB 키와 다르게) → [지금 백업] → [열어 확인]. 명령은 `python pc/pc_tool.py backup`
- 백업 파일(.dgbak)은 승인된 보안 매체에 보관. 백업 비밀번호는 DB 키와 다른 사람이 보관 권장
- 복구: PC 업무 화면을 끄고 `python pc/pc_tool.py restore <파일.dgbak>` → 기존 DB는 `pc.db.before-restore-날짜`로 옆에 남음
- 휴대폰 단독 방식은 휴대폰 [백업·복원]으로 매일 백업(24시간 지나면 경고)

## 7. 보안 수칙

- PC 화면은 이 PC 안에서만 열립니다. 원격 접속·공유 폴더에 DB를 두지 마세요.
- 개인정보가 담긴 파일은 결과·사진 파일(암호화)뿐이며, 승인된 경로(업무 메일·보안 매체)로만 옮깁니다. 개인 메일·메신저·공용 클라우드 금지.
- 메모·하차 메모·충돌 사유에 주민 이름·연락처를 적지 마세요(변경 이력에 남음).
- 계정은 사람마다 따로, 공유 금지. 퇴직·전보 시 즉시 [중지].
- 외부로 나가는 요청은 바탕 지도 서버(넓은 범위 지도 조각) 하나뿐이며 이름·연락처·주소·핀 좌표는 보내지 않습니다.

## 8. 인수 검증 체크리스트 (계획안 9장 대응)

| 기준 | 확인 방법 | 자동 시험 |
| --- | --- | --- |
| 휴대폰에서 이름·연락처·주소 정확히 조회 | QR 수신 후 상세 화면 | 휴대폰 화면 시험 |
| 통신 없이 검색·계산·사진·결과 저장 | 비행기 모드에서 처리 | 오프라인 시험 |
| 단가 버전·부과단위 연결, 미확인 단가 0원 확정 안 함 | 확인 필요 품목 접수 → 금액 확인 대기 | 수수료·PC 로직 시험 |
| 현장 추가·부분 수거가 원본 훼손 없이 남은 수량 유지 | 일부 수거 후 재방문 목록 | PC 로직 시험 |
| QR 누락·중복·변조·혼합·다른 기기 검출 | 잘못된 QR 비추기 | 상호 운용 시험 |
| 중복 가져오기·재시작 후 기록 유지, 버전 충돌 별도 표시 | 같은 파일 두 번, 앱 재시작 | PC 로직·휴대폰 시험 |
| 통화·수거·계산·수납·회수 상태 분리 | 통화 완료 후 수거 상태 확인 | 수수료·PC 로직 시험 |
| 회수 결과가 접수와 연결, 회수 전 자료 삭제 안 함 | 확인 코드 전 삭제 시도 | 휴대폰 화면 시험 |
| 실제 도로·차량 제약 검토 | 수거팀이 배정 화면 순서 검토(로컬 OSRM 권장) | 노선 시험 |

자동 시험: `npm test`, `python tests/test_pc.py`, `python tests/e2e.py`, `python tests/e2e_pc.py`

## 9. 운영 전 확인

- 수수료표 시행일과 확인 필요 8행의 담당 기준 → PC 수수료표 개정·승인
- 업무용 휴대폰 기종·MDM, PC 운영체제(SQLCipher·키 저장소 동작), 화면 QR 촬영·자료 반출입 기준
- 기관 휴대폰으로 QR 실측(PC [QR 실측] 화면, 같은 조건 10회)
- 결과 파일 업무 메일 경로, 사진 파일 보안 매체(휴대폰에서 열리는지) 승인
- 외부 바탕 지도 서비스 이용 승인, 앱 코드 호스팅(기관 도메인 권장)과 배포 계정 통제
- 차량 대수·적재·근무시간, 차고지·반입지·종료지 좌표, 로컬 OSRM 구축 여부
- 주소 위치 자료 최신본 갱신 주기(월 1회 권장)
- 사진·백업 보관 위치와 기간, DB 키·백업 비밀번호 보관 책임자
- 시범 운영: 1개 팀 2주, 기존 방식과 누락·처리 시간 비교
