# 동구 대형폐기물 접수·수거 관리 — 설치·운영 매뉴얼 (PC 0.14.18 · 휴대폰 0.14.18)



이 매뉴얼은 PC 프로그램과 휴대폰 앱을 처음 설치하는 운영 관리자, 매일 쓰는 접수 담당자·팀장·수거팀을 위한 것입니다. 시제품 단계이므로 실제 주민 정보로 운영하기 전에 마지막 장의 "운영 전 확인"을 마쳐야 합니다. 업데이트·서비스 실행·로그·배포는 [배포·운영 안내](배포·운영.md)를 보세요.

## 1. 구성과 준비물

**모바일 수거 목록(0.14.18)**: 첫 화면의 **수거 목록 바로 보기**로 목록에 이동합니다. 카드에서 접수번호·주소·실제 확정 품목·현장 추가 품목과 처리 상태를 확인하세요. 남은 수량은 단위별로 표시합니다. 수량만 입력한 건은 **결과 미저장**, 결과 저장 후 수량을 바꾼 건은 **결과 재확인**으로 표시합니다. 상세에서 목록으로 돌아오면 검색 조건과 보던 카드 위치를 유지합니다. 단독 모드의 방문 순서는 검색·동 필터가 없는 오늘·내일 목록에서 변경합니다.

**날짜 때문에 접수가 보이지 않을 때(0.14.10)**: PC 접수에서 **날짜·상태 제한 해제**를 누르면 기간·처리 상태·빠른 조회 조건을 풀고 지난 완료·취소 접수까지 찾습니다. 검색어·행정동·수거팀·수납·접수 경로 조건은 유지되므로 표시된 조회조건도 확인하세요. 어제·오늘·이번 달·전체 기간 버튼으로 기간을 고를 수 있습니다. 동별 관리에서는 **전체 기간 조회**를 누릅니다. 집계와 노선은 별도로 표시된 **집계·배차 기준일**을 따르며 이전날·오늘·다음날로 이동합니다. 날짜는 조회조건이며, 접수 일정 수정은 접수 상세에서 처리합니다.

휴대폰 홈의 **날짜·접수 찾기**는 전체 기간·모든 상태가 기본입니다. 접수번호·이름·연락처(전체 번호 또는 뒷자리)·주소·품목, 날짜 없음, 완료·취소 등으로 좁혀 보세요. 하이픈 유무와 관계없이 번호로 찾을 수 있고 초성·여러 낱말 검색도 함께 사용할 수 있습니다. 개인정보가 정리된 접수의 연락처는 검색하지 않습니다. 받은 PC 목록은 **목록일**, 단독·현장 접수는 **예정일**로 찾습니다. 휴대폰에 보관 중인 자료만 표시되며 PC의 전체 과거 내역은 PC에서 조회합니다. 상세나 품목 추가 화면을 다녀와 목록으로 돌아오면 찾기 조건을 유지합니다. 검색창은 접수가 적어도 표시합니다.

| 구성 | 설명 |
| --- | --- |
| PC 프로그램 | 접수·행정동·배정·노선·QR 전송·결과 병합·마감·수납·세입·환불·통계·개인정보 관리. 기본은 이 PC(127.0.0.1)에서만 열리고 자료는 암호화 DB 한 파일에 저장 |
| 휴대폰 앱 | Android·아이폰 공통 웹 앱. 앱 코드만 인터넷에서 받고, 업무 자료는 휴대폰 안에만 암호화 저장 |
| 수수료표 | 동구 [별표 1] 원문 HWP와 변환본 169행. 확인 필요 8행은 PC에서 개정·승인으로 확정 |
| 주소 위치 자료 | 행정안전부 도로명주소 위치정보요약DB(선택). 넣으면 PC에서 도로명·지번·건물명·초성으로 주소를 찾고 행정동을 추천 |

준비물: Windows 10/11 또는 macOS PC(웹캠 있으면 결과 QR 회수 가능), Python 3.12, 업무용 휴대폰(Android 10+ Chrome, iOS 16.4+ Safari), 승인된 업무 메일, 사진 회수용 보안 매체, 자동 백업 개인키를 보관할 오프라인 매체.

## 2. PC 설치 (운영 관리자)

**Windows 실행 앱**: 배포 ZIP을 풀고 **Donggu-PC.exe**를 실행합니다. Python·CMD 없이 초기 준비와 서버 시작이 진행되고 업무 화면이 브라우저에서 열립니다. [바탕화면 바로가기 만들기]를 누르면 이후 아이콘으로 시작할 수 있습니다. DB 비밀번호가 필요하면 앱의 마스킹 입력창에 넣습니다. 앱 창을 닫으면 자신이 시작한 서버만 정상 종료합니다.

**트레이 최소화**: [최소화] 또는 제목 표시줄의 [—]를 누르면 창만 트레이로 숨겨지고 서버는 계속 실행됩니다. 시계 옆 숨겨진 아이콘 [^]에서 동구 PC 아이콘을 클릭하거나 오른쪽 클릭 → [실행창 열기]로 복원합니다. 트레이 메뉴의 [실행 앱 종료]는 기존 창 닫기와 같이 자신이 시작한 서버만 정상 종료합니다.

실행 창의 **PC 서버 준비 완료**는 브라우저가 접속할 준비가 됐다는 뜻입니다. **[업무 화면 열기]**로 다시 열 수 있습니다. 브라우저는 필요한 화면만 읽으며 시작 단계와 실제 경과시간을 표시합니다. 지연 안내가 나오면 **[화면 다시 불러오기]**, 업무 화면 안 조회 오류에는 **[다시 시도]**를 사용합니다. 종료할 때는 실행 창 아래 **[서버 종료]**를 누르고 작업 완료를 기다립니다.

자료 위치와 바로가기는 **[설정·상세]**를 열어 확인합니다. 기존 자료를 계속 쓰려면 서버가 종료된 상태에서 [자료 폴더 선택]으로 기존 `pc/state` 등 암호화 DB가 있는 폴더를 고릅니다. 새 배포본의 기본 자료 위치는 `%LOCALAPPDATA%\DongguWaste\state`입니다. 프로그램 파일·`_internal`은 함께 보관하며, 버전을 교체할 때 업무 자료 폴더는 그대로 둡니다. 이미 실행 중인 다른 동구 서버를 재사용한 경우 종료와 자료 위치 변경은 원래 실행 프로그램에서 처리합니다. 실행 창을 닫아도 그 기존 서버는 종료되지 않습니다.

기존 서버 연결이 끊기면 원래 실행 프로그램에서 서버를 다시 켠 뒤 **[기존 서버 연결 확인]**을 누릅니다. 이 동작은 재연결만 하며 다른 자료 폴더에 서버나 DB를 새로 만들지 않습니다.

아래는 개발·유지보수용 소스 설치·실행 절차입니다.

1. Python 3.12 설치 후 `pip install -r pc/requirements.txt`
2. `python pc/pc_tool.py init` — 암호화 DB와 PC 키 생성. DB 키는 운영체제 키 저장소에 보관되며, 키 저장소를 쓸 수 없으면 12자 이상 DB 비밀번호를 정합니다. DB 키는 이 PC의 키 저장소에만 있고(Windows는 이 PC에만 저장, 로밍 안 함) 밖으로 꺼내는 명령은 없습니다. **복구 수단은 백업 비밀번호와 자동 백업 개인키**입니다 — 이 둘의 보관 책임자를 정하세요(DB 키가 달라도 백업은 새 PC에서 복원됨). 이 PC의 업무용 Windows 계정은 **담당자 전용**으로 두세요: 그 계정에 로그인한 사람은 `reset-admin`으로 관리자 비밀번호를 다시 정할 수 있습니다.
3. `python pc/pc_tool.py serve` → 브라우저에서 `http://127.0.0.1:8765`
4. 운영 관리자 계정 만들기(아이디, 10자 이상 비밀번호)
5. **설정** (탭별)
   - **기본**: 관할 구, 접수증 문의처·배출 장소 안내·**납부 안내**(납부 방법·기한, 300자 — 접수증과 [안내 문구 복사]에 들어감), **감면액 끝수**(1원 = 원 미만 버림(기본) / 10원 = 10원 미만 버림, 새로 감면하는 접수부터 적용), 월보 제목, 노선 계산(차고지·반입지·종료지 좌표 — [지도에서 고르기]·[주소로 찾기]로 채울 수 있음, 지점당 작업시간, 로컬 OSRM 주소)
   - **수거팀**: 팀 이름, 연결 휴대폰, 적재 용량(m³), 최대 적재 중량(kg), 근무시간. 아래 **적재량 보정**(품목별 부피 보정값, 추정치 ↔ 하차 기록 비교)
   - **기기**: 휴대폰 앱 [기기 등록]으로 등록 QR을 비춤 → 휴대폰에 나온 **기기 코드 QR**을 PC [휴대폰 QR 웹캠으로 읽기]로 웹캠에 비추면 바로 등록 → 양쪽 **9자리 지문**이 같은지 확인하고 기기 목록에서 **[지문 같음 · 사용 시작]**(누르기 전에는 그 휴대폰으로 목록을 보낼 수 없음) → 이어서 뜨는 "어느 팀에 연결할까요?"에서 팀을 고르거나 새 팀을 만듦([나중에]도 가능). 분실·중지 처리한 기기는 같은 코드로 다시 등록되지 않음. PC에 웹캠이 없으면 휴대폰 [코드 복사] → 승인된 경로로 옮겨 [웹캠이 없을 때: 기기 코드 붙여 넣기]
   - **행정동**: 기본 13개 동은 처음 실행 또는 0.14.2 이상으로 업데이트할 때 없는 동만 자동 등록됩니다. 기존 설정은 보존하며 이후 삭제한 동을 재시작 때 다시 넣지 않습니다. ↑·↓로 직제순을 맞추고 **순서 저장**을 누르세요. **순서 되돌리기**는 순서만 복원합니다. 저장한 순서는 모든 동 선택 목록에 적용됩니다. 코드(부과번호용 1~4자), 기본 담당 팀, 수거 요일, 일일 한도(건·m³), 주소 판별 낱말(법정동·도로명)을 확인하세요. 접수가 있는 동은 지우지 말고 '사용'을 끕니다
   - **한도**: 전체 일일 한도(건·m³), 쉬는 요일 / **휴무일**: 공휴일·임시 휴무
   - **수수료·감면**: 감면 사유·감면율(기본 예시는 "조례 확인 필요" — 조례 확인 후 고침)
   - **주소·외부 서비스** — 주소 위치 자료(이것이 없고 행안부 승인키도 없으면 접수 화면의 주소 찾기에서 아무것도 나오지 않습니다 — 접수 화면에 노란 안내가 뜸): 아래 [2.1](#21-주소-위치-자료위치정보요약db-받기넣기갱신) 순서로 위치정보요약DB를 넣습니다. 행안부 주소 검색 승인키는 넣으면 이 PC 자료에 없는 주소도 검색됩니다. **좌표 승인키는 선택**입니다 — 행안부 검색 결과를 고르면 위치를 이 PC 주소 위치 자료에서 먼저 찾고, 좌표 승인키는 그 자료에 없는 주소까지 좌표로 받고 싶을 때만 넣습니다
   - **백업**: 백업 폴더, 두 번째 저장 위치, 자동 백업 시각(기본 18:00), 보관(최근 14일·3개월, 최대 90일), 사진 보관 기간(기본 90일). **백업 키 만들기**(아래 6장)
   - **개인정보**: 개인정보 보유기간(기본 3년), 접속기록 보관(2년 이상)
6. **사용자·이력**: 접수 담당자·팀장·수거팀·동 담당자 계정을 임시 비밀번호로 추가(첫 로그인 때 변경). 수거팀 계정은 반드시 팀을 연결합니다(그 팀 배정만 보임). 동 담당자 계정에는 담당 동을 한 개 이상 지정합니다. 동별 조회·접수·배정은 **동별 관리**에서 처리하며, 지정된 여러 동을 함께 또는 각각 선택할 수 있습니다([동별 관리 안내](동별-관리.md))
7. **수수료표**: 시행일·확인자 입력, 확인 필요 8행 중 확정된 행의 단가와 근거 입력 → [개정안 저장] → **다른 담당자**가 원문과 대조해 [승인]. 승인 전·시행일 전에는 적용되지 않습니다.
8. **오늘 현황 → 운영 준비 점검**(v0.13, 관리자에게만 보임): 수거팀·적재 용량, 휴대폰 지문 확인·팀 연결, 차고지·반입지 위치, 행정동, 주소 위치 자료 또는 승인키(주소 위치 자료가 있으면 ✓, 가져온 날짜도 표시), 자동 백업 키, 수수료표 시행일, 문의처, 관리자 임시 비밀번호 변경이 모두 ✓가 될 때까지 ✗ 항목의 [고치기 →]로 이동해 채웁니다. 모두 끝나면 상자가 사라집니다(9장 "운영 전 확인"과 같은 목록)
9. 화면 위 머리줄 **[도움말]**에 역할별 하루 순서와 예외 처리가 한 장으로 있습니다(이 매뉴얼 4·5장 요약)

### 2.1 주소 위치 자료(위치정보요약DB) 받기·넣기·갱신

이 자료가 있으면 접수 화면의 주소 찾기·[주소로 위치 찾기]가 이 PC 안에서 위치(건물 출입구)와 행정동을 채우고, 행안부 검색 결과를 골라도 좌표 승인키 없이 위치가 채워집니다. 모든 처리는 이 PC 안에서 하며 외부로 보내지 않습니다.

1. 행정안전부 **주소정보 누리집**(business.juso.go.kr)에서 주소 DB → **위치정보요약DB**로 갑니다(메뉴 이름은 누리집 개편 때 바뀔 수 있음).
2. 지역에서 **해당 시도**(동구청은 광주광역시)를 골라 내려받습니다. 행안부가 매월 새로 올립니다.
3. 내려받은 **압축 파일(.zip)을 풉니다.** PC 화면은 압축 파일을 읽지 못합니다(고르면 "먼저 풀라"는 안내). 안에 든 **.txt 파일**을 씁니다. 구분자(`|`·탭·쉼표)와 글자 인코딩(CP949·UTF-8)은 자동으로 알아보고, 머리글 줄이 없어도 됩니다(열은 값 모양으로 찾음 — 위치정보요약DB의 시군구코드·출입구일련번호·법정동코드·…·도로명코드·도로명·지하여부·건물본번·건물부번·건물명·…·관할행정동·X좌표·Y좌표).
4. PC에서 **설정 → 주소·외부 서비스 → 주소 위치 자료** → [파일 선택]으로 .txt 고르기 → 시군구 거르기는 **"동구"** 그대로 → **[미리보기]**: 찾은 열(`road_cd`(도로명코드)가 보이면 행안부 결과와 정확히 맞춤)·건수·표본 5곳의 좌표 → 표본이 지도에서 맞는 곳인지 확인 → **[이대로 가져오기]**. .txt가 여러 개면 하나씩.
5. 파일이 **40MB보다 크거나** 여러 개면 명령으로 넣습니다(서버를 켠 채로 됨). 폴더를 주면 그 안의 `*.txt`를 모두 읽습니다:
   `python pc/pc_tool.py import-addr <파일 또는 폴더> --region 동구 --preview` 로 열 배치·표본 확인 → `--preview` 없이 다시 실행
6. 카드 위 **"저장된 자료"**에 곳 수·시군구·가져온 날짜가 나옵니다. 식별 번호가 없는 곳 수가 보이면(예전 판에서 가져온 자료) 같은 파일을 다시 가져오면 채워집니다.
7. **갱신(월 1회 권장)**: 1~5를 되풀이합니다. 있던 주소는 그대로 두고 새 주소를 더하며 빠진 식별 번호(도로명코드·법정동코드)를 채웁니다. 같은 건물에 출입구가 여럿이면 출입구일련번호가 가장 작은 것 하나를 씁니다. **가져온 지 45일이 넘으면** 오늘 현황에 "주소 위치 자료 갱신" 안내가 뜹니다.

행안부 검색 결과를 고를 때 위치를 찾는 순서: ① 이 PC 자료에서 도로명코드·지하여부·건물본번·부번이 같은 건물 → ② (식별 번호 없는 예전 자료) 관할 구 안에서 도로명·건물번호 → ③ 지번(법정동·번지, 산 번지 제외) → ④ 그래도 없고 좌표 승인키가 있으면 행안부 좌표 API → ⑤ 없으면 "이 PC 주소 위치 자료에 없는 주소 — 지도에서 지정하세요"(자료를 최신으로 바꾸면 찾을 수 있음). 접수 화면에 "(위치: 이 PC 주소 위치 자료)" 또는 "(위치: 행안부 좌표)"가 함께 나옵니다.

여러 접수 PC에서 함께 쓰려면(LAN 모드) 정보화부서 승인 후 `python pc/pc_tool.py serve --lan --cert cert.pem --key key.pem --allow <업무 PC 대역>`으로 엽니다. HTTPS 전용이며 허용 대역 밖 PC는 연결되지 않습니다. DB를 공유 폴더에 두는 방식은 금지입니다.

### 배출표 사용 장수 자동 집계 (0.14.6)

휴대폰에서 수거 결과를 확정하고 PC **결과 가져오기**로 반영하면 실제 수거 1개당 1장으로 자동 계산합니다. **배출표 관리 → 사용 장수 자동 집계**에서 접수별·전체 누적 장수와 품목별 내역을 확인하고, 접수번호·행정동으로 조회하세요. 3개 중 1개만 수거했으면 1장입니다. 재전송·재방문은 중복 합산하지 않으며 미수거·확정 전 입력·미반영 충돌은 제외합니다. 번호별 입고·배부·사용 원장은 별도로 유지합니다. 자세한 기준은 [배출표 안내](보고서·배출표.md)를 참고하세요.

### PC 로그인 화면의 테마·글자 크기 (0.14.5)

화면 위의 **화면 테마**와 **글자 크기**는 계정별로 저장합니다. 같은 브라우저에서는 마지막으로 적용한 두 외형 값만 기억해 로그인 화면을 새로 열 때도 유지합니다. 업데이트 후 처음 한 번 로그인하면 현재 계정의 외형을 기억하며, 다른 계정의 설정을 덮어쓰지 않습니다. **자동(시스템)**은 시스템 테마 변경을 따릅니다. 브라우저 저장소를 차단한 경우 로그인 후 계정 외형은 적용되지만 다음 방문의 로그인 화면은 기본 외형으로 시작할 수 있습니다.

### VWorld 위치 참고 (0.14.4)

관리자가 **설정 → 주소·외부 서비스**에서 **VWorld API 키**와 **VWorld 참고 조회 사용**을 저장합니다. 등록 서비스 URL은 키 발급 시 등록한 값만 입력하고, 필요 여부는 발급 조건에 맞춥니다. **VWorld 연결 시험**은 고정 공공 건물 주소로 확인합니다. 키 원문은 저장 뒤 표시하지 않습니다.

전화 접수의 **배출 위치 → VWorld 위치 참고**에서 건물 주소와 도로명/지번 유형을 확인하고 **위치 조회**를 누릅니다. 건물 주소가 VWorld로 전송되고 상세 동호수·신청인 이름·연락처·메모는 제외합니다. 결과 출처는 **브이월드(국토교통부)**로 표시합니다.

결과는 조회 창에서만 참고하며 접수 주소·좌표·행정동·초안·QR에 반영하지 않습니다. 조회 실패 시 주소와 유형을 확인하고 다시 시도하거나 창을 닫습니다. 기존 로컬/행안부 검색과 지도 지정은 그대로 사용합니다. VWorld 결과의 업무 저장·휴대폰 전달은 제공기관의 허용 범위를 확인한 뒤 별도로 검토합니다.

## 3. 휴대폰 설치 (수거팀)

1. 업무 휴대폰 브라우저로 `https://lanian.github.io/donggu-waste/` 열기 → **설치**
   - Android(Chrome·Samsung 인터넷): 앱의 [앱 설치] 단추, 또는 브라우저 메뉴(⋮) → [앱 설치]/[홈 화면에 추가]. 메뉴에 [앱 열기]만 보이면 이미 설치된 것(홈 화면 아이콘만 지운 경우 앱은 남아 있음 → 앱 목록에서 열기)
   - 아이폰(Safari): 공유 단추(□↑) → [홈 화면에 추가]. **아이폰은 Safari와 홈 화면 앱이 자료를 따로 보관**하므로 반드시 설치한 앱에서 PIN 설정·기기 등록을 합니다
   - 이 앱은 브라우저 탭에서도 그대로 동작해서 설치 전에도 앱처럼 보입니다. 지금 어디서 실행 중인지는 설정 → **실행 위치**(브라우저 탭/설치한 앱)에서 확인
2. 앱 PIN(숫자 6자리 이상) 정하기
3. 사용 방식: **PC와 연결해서 사용**(권장) → [기기 등록] (2장 5번 '기기')
4. 설정
   - **화면**: 테마(자동/밝게/어둡게), 야외 고대비, 글자 크기(작게/보통/크게/아주 크게)
   - **잠금**: 잠금 시간 5·10·15분(기본 10분). 지원 기기면 **지문·얼굴 잠금 해제** 등록(PIN을 먼저 넣음, PIN도 계속 사용)
   - **작업자**: 개인폰을 사용하는 본인 이름 하나를 저장합니다. 이후 수거·연락·하차 기록에 자동으로 남으며 홈에서 다른 작업자를 고를 필요가 없습니다. 이름을 바꿔도 이전 기록의 작업자 이름은 유지됩니다. 이전에 여러 이름을 등록했다면 현재 선택된 이름을 사용합니다.
   - **길안내 앱**: 카카오맵(기본)/T맵/네이버지도/기본 지도 앱
   - **문자 문구**: 방문 안내 문구 확인·수정(다른 주민 정보가 들어가지 않게 검사)
   - **주소 검색**: 기관이 발급받은 도로명주소 검색 승인키·좌표 승인키 입력(없으면 주소는 직접 입력·지도 지정)
   - **지도**: [동구 지도 미리 받기] — 인터넷이 약한 곳 대비(최대 50MB)
   - **미전송 경고**: 1·3·6시간(기본 3시간)
5. **처음 쓰는 휴대폰은 설정 → [현장 점검]**: 설치·지문·주소 검색·길안내·카메라를 [시험]으로 눌러 보고 [결과 복사]로 운영 관리자에게 보냄
6. 앱 새 버전이 나오면 상단에 "새 버전이 있습니다 [업데이트]"가 뜹니다. 미전송 결과를 보낸 뒤 누르세요. 0.13.0부터는 잠겨 있거나 수량·기록·사진 저장이 남아 있으면 업데이트를 미루고 알려 줍니다(잠금을 풀고 저장이 끝난 뒤 다시 누름)
7. 기기 등록 뒤 첫 화면의 **처음 설정** 카드(작업자 · 길안내 앱 · 지도 받기 · 현장 점검)를 차례로 끝냅니다. 끝난 항목은 ✓, 모두 끝나면 사라집니다([나중에 (닫기)]로 숨길 수도 있음)
8. 첫 화면에 "자료 보존이 허락되지 않았습니다"가 뜨면 앱을 홈 화면에 설치한 뒤 [다시 요청]을 누릅니다(허락되지 않으면 저장 공간이 모자랄 때 브라우저가 보내지 않은 기록·사진을 지울 수 있음)

잠금: **설정 → 잠금 → 자동 잠금**에서 켜고 끕니다(0.14.15). 켜면 선택한 5·10·15분 동안 조작하지 않을 때 잠깁니다. 카메라·전화·문자·길안내 앱은 10분, 그 밖의 앱은 2분까지 자리를 비울 수 있습니다. 끄면 무조작·앱 복귀로 자동 잠그지 않으며, 첫 화면의 **잠금**과 앱 재실행 시 PIN·생체 인증은 그대로 사용할 수 있습니다. 다른 창에서 앱을 열 때의 중복 입력 방지도 유지합니다. 기기별 설정이며 저장 실패 시 이전 값을 유지합니다.

화면 맨 위에서 아래로 당길 때 브라우저가 새로고침하지 않도록 세로 스크롤 경계를 제어합니다(지원 브라우저). 일반 스크롤은 그대로 사용하며, 직접 새로고침하거나 앱을 다시 실행하면 PIN을 입력합니다.

잠그기 전에는 저장 중인 수량·기록·사진을 기다립니다. 저장하지 못한 사진은 "저장 대기 사진"으로 남습니다. 이 알림이 보이면 **앱을 닫지 말고** 잠금을 풀거나 **사진 다시 저장**을 누르세요.

## 4. 하루 업무

### 모바일 버튼과 화면

첫 화면의 **지금 할 일**은 다음 업무를 안내합니다. **자주 쓰는 기능**에서 접수 등록·날짜 찾기·수수료 계산 등을 두 열로 골라 사용할 수 있습니다. 목록의 검색·동·처리 상태는 기존처럼 유지됩니다.

수거 상세에서는 아래 **수거 결과 선택 ↓**로 결과 영역에 이동한 뒤 수거 결과를 선택해 저장합니다. 이 이동 버튼만 눌러서는 수거 기록이 저장되지 않습니다. **저장 중…**, **저장 다시 시도**, 저장 후 다음 지점 이동을 구분해 확인하세요. 수량을 수정한 뒤에는 수거 결과도 다시 저장합니다. 전화·길안내는 별도 보조 버튼입니다.

수량의 숫자를 누르면 **수량 직접 입력**을 엽니다. 허용 범위의 정수를 적고 **적용**하거나 **취소**하세요. 접수·품목 수량은 1~9999이며, 수거 수량은 이전 수거분보다 줄이거나 현장 수량보다 늘릴 수 없습니다. −/＋도 사용할 수 있습니다.

완료 결과를 저장한 뒤 수량·품목을 바꾸면 **결과 재확인**이 필요합니다. 홈에서 해당 접수로 돌아가 현재 수량에 맞는 결과를 저장한 뒤 다음 지점 이동·PC 전달을 진행하세요. 일부 수량을 입력하고 **전부 실음 · 수거 완료**를 누르면 바뀔 수량을 확인받습니다. 취소하면 기존 입력을 유지합니다.

접수 저장 중에는 입력과 저장 버튼이 잠깁니다. 실패하면 같은 입력·접수번호를 유지한 채 **저장 다시 시도**로 재시도합니다. 다른 화면에 다녀왔다면 **저장하던 접수로 돌아가기**를 사용하세요. **앱을 닫지 마세요** 경고는 실제 저장 성공까지 유지되며, 경고를 누르면 상세 내용을 볼 수 있습니다. 기록 보호가 필요하면 암호화 백업을 사용합니다.

**설정·정보** 상단에서 화면 → 잠금 → 작업자를 차례로 설정합니다. **아주 크게**와 **야외 고대비**를 사용할 수 있으며, 자동 잠금을 꺼도 앱 재실행 시 PIN은 유지됩니다.

### 빠른 수수료 계산 (PC·모바일, 0.14.14)

PC는 **오늘 현황·동별 관리**의 **빠른 수수료 계산** 또는 왼쪽 메뉴로, 모바일은 첫 화면의 같은 버튼으로 엽니다. 품목명·규격·초성으로 검색하거나 의자·매트리스·소파 등의 빠른 선택을 누릅니다. 규격별 단가와 부과 단위를 확인하고 **담을 수량**을 입력한 뒤 **+ 담기**로 추가하세요. 여러 품목을 연달아 담고 수량을 조절하면 **감면 전 합계**가 바로 바뀝니다. 개·쪽·세트는 각각 집계합니다.

**삭제**는 해당 품목, **계산 비우기**는 담은 전체 품목을 지웁니다. **계산 내용 복사**로 규격·수량·단가·합계와 요금표 버전을 복사하며, 자동 복사가 안 되면 표시된 내용을 선택해 복사합니다. 확인 대기 품목이 있으면 최종 숫자 합계 대신 **금액 확인 대기**와 확정 소계를 표시합니다. 실제 감면은 접수에서 별도로 처리하세요.

모바일은 받은 PC 요금표나 단독 모드 확정 단가를 사용합니다. 받은 표가 없으면 내장표 사용을 표시하고, 받은 표가 앱과 호환되지 않으면 업데이트 안내를 표시하며 계산을 막습니다. 미리 업데이트한 앱은 오프라인에서도 계산할 수 있습니다. 계산 내용은 현재 화면 세션에만 보관하며 PC 로그아웃·앱 재시작 뒤 보존을 위한 기능은 아닙니다. 계산만으로 접수·수거 기록이나 배출표 재고를 바꾸지 않습니다.

### 수거팀 (휴대폰)

**수량과 저장 상태(0.14.15):** 현장 수량과 누적 실은 수량의 단위를 확인하세요. 앞선 수거분은 보존하고 이번 추가분만 조절합니다. 큰 수량도 9999 범위에서 입력하며, 저장 실패 시에는 완료 안내 대신 재저장 안내를 확인합니다. 기록이 저장되기 전에는 완료·다음 지점 안내를 따르지 말고 기존 기록을 다시 저장하세요. 결과를 저장한 뒤 수량을 다시 수정했다면 수거 결과도 다시 선택해 저장하세요.

1. **시작**: 개인폰의 작업자 이름 확인(처음 한 번 설정) → [오늘 목록 받기] → 화면의 **수신 코드(R-)**를 PC 담당자에게 불러 줌 → 오늘 목록(진행 띠, 노선도형 순서, 동 표시, 반입지 하차 지점)
   - 첫 화면 맨 위에 "M/D 목록입니다 — 결과를 보내고 오늘 목록을 받으세요" 띠가 보이면 **어제 목록**입니다. 어제 결과를 먼저 보내고 오늘 목록을 받으세요. 어제 결과가 아직 PC에 반영되지 않았으면 [오늘 목록 받기]가 카메라를 켜기 전에 먼저 알려 줍니다(PC가 어제 결과를 가져온 뒤 만든 오늘 목록이면 그대로 받아지고 어제 결과도 저절로 확인됨)
   - 무엇을 어떤 순서로 하는지 헷갈리면 설정 → [현장 처리 순서]

2. **이동**: 지점의 [🧭 길안내] → 설정한 지도 앱이 그 좌표로 열림(지도 앱에는 좌표와 "N번 수거지"만 감). 돌아오면 앱이 잠겨 있지 않습니다(10분까지)
3. **도착**: [📍 도착] — 시각과(허용 시) 위치 기록
4. **연락**: [📞 전화] → 연락 결과 기록(통화 완료가 수거 완료로 바뀌지 않음), 통화로 약속한 재방문 날짜·시간. 필요하면 [✉ 문자]로 문구를 골라 문자 앱에서 보냄

6. **금액 고지**: 현장 추가 등으로 접수 때보다 금액이 늘면 주민에게 알리고 결과(동의·거부)를 기록. 거부하면 늘어난 품목은 미수거
7. **사진**(수거 전·후): 앱 안에만 암호화 저장, 갤러리에 남지 않음. **부재·배출 안 됨으로 미수거할 때는 사진 1장 이상 필수**(못 찍으면 이유 선택)
   - 사진의 **크게 보기**에서 전체 사진·대상 품목·촬영 시각을 확인합니다. **확대** 후 사진을 밀어 보고 **맞춤 보기**로 돌아오세요. 읽기에 실패하면 **사진 다시 불러오기**를 사용합니다. **사진 닫기**나 뒤로 가기로 닫으며, 잠그면 열린 사진도 닫힙니다. 크게 보기는 사진·수거 기록을 추가하지 않습니다.
8. **수거 결과**: 완료 / 일부 수거 / 미수거 / 확인 대기
9. 반입지에서: [🧭 길안내] → [하차 기록] — 시각·부피·중량
   - 부피·중량은 음수로 입력할 수 없고 둘 중 하나는 0보다 커야 합니다. 반입지 위치를 지정하러 다녀와도 입력을 유지합니다. 저장 실패 시 **저장 다시 시도**로 같은 하차를 저장하고, 저장된 작업을 다시 열었으면 **새 하차 기록**으로 다음 기록을 시작합니다.
   - **현장에서 새 요청·바뀐 내용**(v0.12): 주민이 새로 요청하거나 전화로 접수를 받으면 홈 위 [+ 접수 등록 (현장·전화)] → 접수 경로(현장·전화·방문) 고르기 → 저장. 현장 접수는 그 지점 화면으로 가서 바로 처리. 기기 등록 전에도 받아 둘 수 있고, PC로 보내는 것은 등록 뒤. 연락처·주소·날짜가 바뀌었으면 지점 화면 아래 [정정 요청], 주민이 취소하면 [취소 요청]. 휴대폰 목록은 바로 바뀌지 않고, 결과 보내기 때 PC로 가서 사무실이 확인합니다
   - 골목 사정 등으로 순서를 바꿔 다닐 때: 홈 [방문 순서 바꾸기](이 휴대폰만, 새 목록을 받으면 PC 순서로)
10. **중간에**: 홈에 미전송 경고가 뜨면(정한 시간이 넘거나 17시 이후) [결과 보내기]로 중간 결과를 보냄
   - 상세의 **메모 남기기**는 입력을 보존합니다. 저장 실패가 표시되면 **메모 저장 다시 시도**를 눌러 기존 메모를 다시 저장하세요. 이후 적은 새 메모는 이전 저장 응답이 돌아와도 지우지 않습니다.
11. **업무 끝**: [결과 보내기] → 결과 파일(.dgr)을 **승인된 업무 메일**로 전송. 메일이 안 되면 [PC 화면 카메라로 보내기 (QR)] → PC [결과 가져오기]의 [웹캠으로 읽기]
12. PC 담당자가 알려 준 **결과 반영 코드(D-)** 입력 → 반영 확인. 이때 그 접수들의 이름·연락처·주소가 휴대폰에서 자동으로 지워집니다(수거 기록은 남음)
13. [사진 파일 만들기](.dgp) → 보안 매체로 PC에 전달 → **사진 회수 코드(P-)** 입력 → 그 뒤에만 사진 삭제 가능
    - **코드는 대부분 넣지 않아도 됩니다(0.13.0)**: PC가 결과·사진을 가져온 뒤 만든 목록(같은 날 다시 보낸 목록이나 다음 날 목록)을 받으면 "결과 N건 반영 확인 · 사진 N장 회수 확인 — 코드 입력 필요 없음"이 뜨고 12·13번을 한 것과 같이 처리됩니다. 그날 마지막 근무일이라 다음 목록이 없거나 바로 정리해야 하면 코드를 넣습니다
    - 코드 칸을 헷갈려 결과 칸에 사진 회수 코드, 사진 칸에 결과 반영 코드를 넣으면 "아래 사진 칸(위 결과 칸)에 넣어 주세요", 수신 코드(R-)를 넣으면 "여기에 넣는 코드가 아닙니다"라고 알려 주고 받지 않습니다
14. 모두 확인되면 [오늘 자료 정리]. 사진·기록이 저장 중이면 정리할 수 없으며, 확인창을 연 뒤 새 기록이 생기거나 다른 업무로 이동하면 이전 확인으로 정리하지 않습니다. 새 기록의 PC 반영을 확인한 뒤 다시 정리하세요. 휴대폰을 초기화하는 등 백업에서 복원해야 할 때는 설정 → [안전용 암호화 백업] — 0.13.0부터 복원은 지금 휴대폰 기록과 **합쳐서**(기록 번호는 큰 쪽) PC에 있는 번호를 다시 쓰지 않습니다

### 접수 담당자 (PC, 오후)

**PC에서 직접 수거 입력(0.14.9)**: 접수 상세 또는 동별 접수 상세에서 **수거 처리**를 누릅니다. 실제 수거일을 확인하고 **이번에 추가로 수거한 개수**만 입력합니다. 이전 수거분은 이미 표시되므로 다시 더하지 마세요. **남은 수량 전부**로 일괄 입력할 수 있으며 일부 수거·미수거에는 사유를 적습니다. 저장하면 수량에 따라 상태를 정하고 해당 동의 배출표 번호 배정·재고 차감·월보·대장을 함께 반영합니다. 재고가 부족하면 수거는 저장하고 미배정 장수를 알립니다. 수납은 별도로 기록합니다. 품목 수정 중이면 먼저 수정 내용을 저장하세요. 다른 사람이 결과·배정을 바꾸면 최신 접수를 다시 열어 확인합니다.

**휴대폰에서 PC 입력 돕기**: 수거 상세의 **PC 입력 도움**은 전체 화면으로 접수번호·품목·이전 수거·이번 수거·남은 수량과 실제 결과일을 보여 줍니다. PC에서 같은 접수번호를 찾아 입력하세요. **전달 내용 복사**는 이름·전화번호·주소를 포함하지 않습니다. 복사가 지원되지 않으면 선택된 글을 길게 눌러 복사합니다. **접수 상세로**를 누르면 원래 상세로 돌아오며, 날짜·접수 찾기에서 들어온 경우 그 검색조건도 유지합니다. 화면을 열거나 복사해도 수거 기록은 추가되지 않습니다. '결과 미확정'은 실제 현장 상황을 별도로 확인해야 한다는 뜻입니다.

**팝업 개선(0.14.11)**: 동별 접수 등록·상세는 별도 작업 화면이며 **수거 처리**는 그 안에서 펼칩니다. **입력 접기**로 접어도 같은 화면에서는 수거일·수량·사유를 유지합니다. 저장 응답이 끊기면 같은 저장 버튼으로 반영 여부를 확인하세요. 저장 후 최신 내용 조회만 실패한 경우 **최신 내용 다시 불러오기**를 누르면 수거를 다시 저장하지 않고 조회만 재시도합니다. 취소·삭제·마감 확인과 인쇄·QR 창은 계속 사용합니다.

PC에서 추가 수거한 뒤 휴대폰 작업을 이어가려면 최신 앱과 새 목록을 받으세요. 새 목록은 PC의 누적 수거량에서 이어서 계산합니다. PC 입력 전의 옛 휴대폰 결과나 새 기준을 확인하지 못한 옛 앱 결과는 **충돌함**에서 검토하며 자동으로 PC 수량을 덮어쓰지 않습니다.

1. **결과 가져오기**: 받은 결과 파일(.dgr)·사진 파일(.dgp)을 **여러 개 한꺼번에** 고르거나 끌어 놓음(여러 팀 것을 섞어도 되고, 결과를 먼저·사진을 나중에 가져옴) → 파일마다 결과가 나오고 **결과 반영 코드(D-)**·**사진 회수 코드(P-)**가 생김
   - 사무실 계정은 결과 파일·웹캠 QR 반영 직후 **가져온 현장 내용 확인**에서 새 접수와 추가 품목·수량을 확인합니다. 이미 PC에 반영된 접수이므로 다시 등록하지 말고 **접수 확인**으로 여세요. 충돌·거부 기록은 별도 표시하며, 충돌은 **충돌함에서 확인**으로 판단합니다. 최근 가져오기의 **현장 내용 확인**으로 다시 열 수 있습니다. 목록 조회에 실패해도 반영 코드·가져오기 결과는 유지되므로 **다시 불러오기**만 누르세요.
   - **최근 가져오기** 표(v0.13): 화면을 닫았다 열어도 최근 가져오기의 팀·기기·시각·건수·코드를 다시 볼 수 있습니다. 읽는 법:
     - "휴대폰 입력 전"(노랑) → 수거팀에 코드를 불러 주고 휴대폰에 넣었으면 [휴대폰에 입력함]
     - "휴대폰 입력함" → 담당자가 [휴대폰에 입력함]을 누른 것
     - "휴대폰 확인됨(다음 목록)" → 그 뒤 그 휴대폰이 다음 목록을 받고 수신 코드(R-)까지 PC에 입력되어 **저절로** 확인된 것(코드를 따로 불러 줄 필요 없음)
     - 코드 칸이 "—"인 사진 가져오기 → 해시가 맞지 않는 사진이 있어 코드를 발급하지 않음(휴대폰에서 사진을 지우면 안 됨, 사진 파일을 다시 받음). 휴대폰 단독 방식 옮기기도 코드가 없음
   - 그래서 보통은 **다음 목록(같은 날 갱신본이나 다음 날 목록)을 보내면 코드를 따로 알려 주지 않아도** 됩니다. 수거팀이 그날 바로 [오늘 자료 정리]를 해야 할 때만 코드를 불러 줌
   - "순번 겹침(반영·확인만)"이 나오면 휴대폰을 백업에서 복원한 경우입니다. 기록은 반영됐고 확인만 하면 됩니다
2. **충돌함**: 다른 팀으로 옮겼거나 배정에서 뺀 건·취소된 접수의 결과, 현장 정정·취소 요청은 사유를 보고 반영 또는 거부. 같은 팀의 옛 목록(갱신본)으로 남긴 결과는 v0.13부터 충돌이 아니라 그대로 반영됩니다(충돌 사유 칸에 "이전 갱신본 … 반영" 메모). 목록을 보낸 뒤 접수를 고쳐 뺀 품목(또는 접수에 없는 품목 줄)의 수거 결과도 충돌함으로 옵니다: 반영할 줄이 없으므로 [거부]하고, 실제로 실어 갔으면 접수 품목을 고칩니다
   - **한꺼번에 처리(v0.13)**: 한 접수에 기록이 여러 개면 [이 접수 기록 모두 반영/거부], 한 가져오기에서 생긴 충돌이면 가져오기를 고르고 [이 가져오기 모두 반영/거부] → 판단 사유를 한 번 적음. 반영할 수 없는 기록(품목이 맞지 않는 등)은 건너뛰고 몇 건이 실패했는지 알려 주므로, 남은 건은 하나씩 봅니다
3. **접수 상세 → 현장 결과**: 도착·스티커 확인·금액 고지·증거 사진·작업자 확인. 현장 접수의 주소·동·품목을 고쳤으면 **수정 저장** 후 **확인 완료**를 누릅니다. 저장 실패 시 입력을 유지하므로 오류를 확인하고 재시도하세요. 저장 중 같은 접수를 다시 열면 완료될 때까지 입력·확인을 기다립니다. 사무실 확인은 단가 확정과 별개입니다. 표에 없어 금액 확인 대기인 품목은 **유사 품목 적용**에서 미리 채운 품목명·규격으로 검색한 뒤 적용 항목을 직접 선택합니다(근거·확인자 필수, 해제 가능).
   - 저장 도중 화면을 나갔다 돌아온 뒤 실패했다면 **내 값 다시 넣기**로 수정 내용·사유를 복구해 저장하세요. 수정이 필요 없으면 **버리기**로 보관한 내용을 정리한 뒤 사무실 확인을 진행합니다.
4. **접수 상세 → 수납 기록**: 결제 방법·영수번호와 함께 확인한 납부 기록(계산 금액 ≠ 수납 완료, 감면 뒤 **부과 금액**과 비교)
5. **세입·대사**(세외수입 납부 자료를 받는 날): 납부 자료 CSV → 미리보기(일치·금액 다름·부과번호 없음·중복 등) → 일치 행만 반영. 불일치는 개별 확인. 납부방법이 목록(현장 카드·현장 현금·가상계좌·무통장 입금·스티커 구매·기타)에 없으면 '기타'로 기록되고 미리보기 비고에 경고가 뜹니다(방법별 세입 합계를 볼 때 참고)
6. **환불**: 환불 화면에 자동으로 생긴 건(납부 뒤 취소·과납)과 일부 수거 차액을 확인 → [신청] → 팀장 결재 뒤 지급하면 [지급 기록](지급일·방법, 계좌번호는 적지 않고 "계좌 확인함"·끝 4자리만)
7. **일일 마감 기록**: 결과 미회수·재방문 후보·금액 확인 대기·수납 확인 필요·사진 미회수·충돌·스티커 문제·금액 고지 거부·증거 없는 미수거 확인, 하차 기록 확인 → [마감 기록]. "결과를 가져오지 않은 팀"(v0.13: 그날 목록을 보냈는데 그 뒤 그 휴대폰 결과 파일이 없음)이 빨갛게 나오면 먼저 그 팀 결과를 받으세요(마감을 막지는 않고 확인창에서 한 번 더 알림). 같은 요청이 두 번 가도 마감 회차는 하나만 생깁니다. 끝나지 않은 건은 **다음 업무일로 이월**되고 목록이 화면에 나옵니다. 이어서 팀장에게 확인을 요청
8. 마감 뒤에 접수를 고치면 사유를 적어야 하며, 다시 마감하면 새 **회차**가 생겨 팀장이 다시 확인합니다.

### 팀장 (PC)

1. **오늘 현황**: 팀별 진행, 동별 표, 처리할 일, **밀린 일**(마감 확인 대기·환불 결재 대기 — 가장 오래된 날짜도 표시) 확인. 위에 "예약 작업 확인 필요" 띠가 있으면 운영 관리자에게 알림
2. **마감 확인**(매일): 일일 마감에서 담당자가 기록한 회차의 요약·이월 목록을 보고 [마감 확인]. 마감을 기록한 사람은 확인할 수 없습니다. 확인하면 보유기간 지난 개인정보 파기와 자동 백업이 이어서 실행되고 결과가 화면에 나옵니다
3. **환불 결재**(수시): 환불 화면의 결재 대기 건을 보고 [승인] 또는 [반려](사유). 신청자는 결재할 수 없습니다
4. **접속기록 점검**(매월): 접속기록 화면에서 지난달 기록을 걸러 보고(많은 조회·업무 시간 밖 조회·출력·내보내기), [빠른 무결성 검사](지난 검사점 뒤 새 기록만, 몇 초 — 서버가 매일 자동으로도 함) 결과가 정상인지 확인 → 메모와 함께 [점검 완료]. 처음부터 끝까지 보는 전체 검사는 관리자가 [전체 무결성 검사]로(서버가 주 1회 자동으로도 함). **무결성 검사 실패면 즉시 정보보호 담당에 알림**
5. **월보**(매월): 통계·보고서에서 지난달 → [월보 출력](개인정보 없음)
6. 변경 이력 조회: 취소·수정·마감 후 수정 사유 점검

### 운영 관리자

- 매일: 오늘 현황 확인 — **운영 준비 점검**(✗가 있으면 고침), **예약 작업 경고 띠**("예약 작업 확인 필요: 개인정보 자동 파기: 3일 전" 등 → [진단 보기]), 밀린 일. 자동 백업 성공 여부(설정 → 백업의 마지막 백업 시각) 확인. 자동 백업을 아직 안 켰으면 [지금 백업](별도 백업 비밀번호) → 오른쪽 아래 진행 띠가 "끝"이 되면 [열어 확인]
- **예약 작업(v0.13)**: 서버가 켜져 있으면 매일 02:30(한국시간) 이후 처음, 늦게 켜졌으면 켜자마자 한 번 개인정보 자동 파기·사진 보관 기간 정리·환불 전체 점검·접속기록·백업 보관 정리·업데이트 사전 사본(`state/pre-migration/`)·복원 전 사본(`state/pc.db.before-restore-*`) 정리·빠른 무결성 검사를 하고, 일요일(또는 7일 넘게 없었으면)에는 전체 무결성 검사도 합니다. 그래서 파기·사진 정리를 손으로 할 일은 거의 없습니다. PC를 밤에 끄면 다음 날 켤 때 돌고, 그동안 화면이 조금 느릴 수 있습니다. 시각을 바꾸려면 [배포·운영 7.1](배포·운영.md)
- **백그라운드 작업 진행 띠**: 백업·백업 정리·개인정보 파기·사진 정리·전체 무결성 검사·환불 전체 점검은 누르면 바로 돌아오고 오른쪽 아래 띠에 "대기 중 → 건수/전체 → 끝"이 나옵니다. 그동안 다른 화면을 써도 됩니다. "실패"가 나오면 내용을 확인하고 다시 실행. 서버를 다시 켜면 띠에서 사라지므로 결과는 변경 이력·백업 목록에서 확인
- 매주: 사용자·변경 이력 점검(로그인 실패, 중지할 계정), 백업 두 번째 저장 위치 확인, 사용자·이력 화면 아래 **진단** 카드(DB·사진 크기, 남은 공간, 예약 작업 마지막 시각 — 오래되면 빨강)
- **시범 운영 중**: 정산·마감 → [시범 운영 비교]에서 기간·팀과 기존 방식(종이 대장 등)으로 같은 길이 기간에 센 수치(접수·누락·재방문·독촉·처리 일수·접수/마감 시간)를 저장 → 비교표(건수는 100건당, 좋아짐/나빠짐)와 CSV. 접수·마감 시간은 PC 화면에서 자동으로 잼(5초~2시간만)
- 매월: **주소 위치 자료 갱신**(2.1, 오늘 현황에 45일 안내가 뜨기 전에), 통계·보고서 집계 확인·CSV 내보내기(이름·연락처·주소 없음), 접속기록 점검(팀장과 함께, 필요하면 [전체 무결성 검사]), 개인정보 파기 대장 확인(매일 자동 파기가 500건씩 한 줄로 남음. 설정 → 개인정보 [미리보기]로 남은 대상이 없는지 보고, 있으면 [파기 실행] 또는 `python pc/pc_tool.py purge-pii --preview`), 환불 화면 [환불 전체 점검](밤마다 자동이지만 의심스러울 때)
- 행정동·한도·휴무일: 연초·조직 개편 때 갱신(공휴일·임시 휴무 미리 입력)
- 감면 사유: 조례가 바뀌면 설정 → 수수료·감면에서 고침(쓰인 사유는 지우지 말고 '사용 안 함'). 끝수 처리 단위(1원·10원)는 설정 → 기본의 **감면액 끝수** — 감면을 적용·바꿀 때의 단위가 접수에 저장되므로, 설정을 바꿔도 **이미 감면한 접수의 부과 금액·납부 상태는 그대로**이고 그 뒤에 감면하는 접수부터 새 단위가 적용됩니다(접수 상세 감면 카드에 '끝수 10원 미만 버림' 표시). 기존 접수에 새 단위를 쓰려면 그 접수의 감면을 다시 저장합니다
- 납부 방법·기한이 바뀌면 설정 → 기본의 **납부 안내**를 고침(접수증·주민 안내 문구에 바로 반영)
- 단독 방식으로 운영하던 휴대폰이 있으면: 그 휴대폰 백업(.dgb)을 보안 매체로 받아 [결과 가져오기 → 휴대폰 단독 방식 자료 옮기기]
- 수수료표가 바뀌면: 원문 HWP 변환 → 앱 새 버전 배포 → PC 수수료표 화면에서 시행일·확인 필요 행 개정·승인
- **적재 추정 점검**(월 1회 권장): 설정 → 수거팀·차량 → 적재량 보정의 [추정치 ↔ 하차 기록]에서 부피·중량 %를 봅니다. 70% 미만이나 130% 넘게 벗어나면 자주 쓰는 품목의 부피 보정값을 고칩니다. 하차 기록에 반입지 계근표 중량을 꼭 남기게 하세요(비교의 근거). 기준표 자체(`data/item_handling.json`)를 바꾸면 휴대폰 앱도 새 버전으로 배포
- **차량·근무 설정**: 팀마다 적재(m³)와 최대 적재 중량(kg, 차량 등록증), 설정 → 기본의 반입지 받는 시간·쉬는 시간 창·큰 짐 먼저 싣기

## 5. 예외 처리

| 상황 | 처리 |
| --- | --- |
| 휴대폰 분실 | 설정 → 기기 → [분실 처리]. 그 기기로는 목록을 보내지 않고 결과도 받지 않음. 오프라인 기기 원격 삭제는 불가 → 보안 담당 보고 |

| 휴대폰 고장·교체 | 새 휴대폰 등록 → 팀 연결 변경 → 목록 재전송. 옛 휴대폰의 미전송 결과는 복구 불가하므로 미전송 경고가 뜨면 중간 결과를 보냄 |

| 정정·취소 요청(v0.12) | 충돌함에 '현장 정정 요청'(지금 값 → 요청 값)·'현장 취소 요청'으로 나옴. 주민 확인 뒤 판단 사유를 적고 [반영](원본 수정·이전 내용은 버전, 또는 사유 코드로 취소) 또는 [거부]. 처리하면 그 요청 기록의 이름·연락처·주소는 지워짐 |
| 금액 확인 대기 | 0원으로 확정하지 않음. 수수료표 개정·승인 또는 유사 품목 적용 후 수납 기록 |
| 한도 초과·휴무일 | 경고만 함. 신청자와 [가장 빠른 가능일]로 다시 정하거나, 배정에서 [다른 날로 미루기](사유 코드) |
| 주소 확인 알림(휴대폰·PC) | '건물번호 없음', '형식 확인', '관할 밖', '주소칸에 전화번호' 등은 막지 않는 알림. 신청자에게 다시 확인하고, 맞으면 휴대폰은 [접수 저장]을 한 번 더 누름 |
| 동이 잘못 골라짐 | 접수 상세에서 동을 고치거나 목록에서 일괄 [동 지정](사유). 자주 틀리면 행정동의 주소 판별 낱말 보완 |
| 주민이 늘어난 금액 거부 | 휴대폰에서 '거부' 기록 → 늘어난 품목은 미수거. PC 마감 점검에 표시 |
| 스티커·필증 없음·불일치 | 그 품목을 미수거(사유 남음) 또는 수거로 정함. 마감 점검에 표시 |
| 부재·배출 안 됨 | 사진 1장 이상(또는 못 찍은 이유) 후 미수거. 증거 없는 미수거는 마감 점검에 표시 |
| 길안내 앱이 안 열림 | 설정에서 다른 지도 앱 또는 '기본 지도 앱'으로 바꿈. 좌표 없는 지점·반입지는 [길안내]를 누르면 "위치가 없습니다" → [지도에서 위치 정하기]. 반입지 좌표는 PC 설정(노선 계산 → 반입지 좌표)에 넣어 두면 목록에 함께 옴 |
| 주소 검색이 안 됨(휴대폰) | 승인키 확인, 인터넷 확인. 서버가 막으면 주소를 직접 적고 지도에서 위치 지정 |
| 납부 뒤 취소·과납 | 환불 화면에 자동으로 생김 → 신청 → 팀장 결재 → 지급 기록 |
| 대사 불일치 | 부과번호 없음·금액 다름은 반영하지 않음. 세외수입 담당과 확인 후 수납 기록에 직접 입력(사유) |
| 마감 후 결과가 늦게 옴 | 가져온 뒤 다시 [마감 기록] → 새 회차 → 팀장 재확인 |
| 접속기록 무결성 검사 실패 | 정보보호 담당에 즉시 보고. 백업·로그 보존, DB를 고치지 말 것 |
| 자동 백업 실패 | 설정 → 백업의 오류 확인(폴더·두 번째 위치 접근, 디스크 공간), [지금 자동 백업] 다시 실행 |
| 관할 밖 주소 경고 | 주소의 구 이름을 신청자에게 다시 확인. 관할이 아니면 안내 후 취소(사유 코드 '관할 밖') |
| 같은 품목을 현장에서 또 추가 | "기존 행에 더하기" 또는 "따로 한 줄 더" 선택. 기록은 지워지지 않음 |
| 주소 찾기에서 아무것도 안 나옴 | 접수 화면에 "주소 검색 자료가 아직 없습니다"가 보이면 설정 → 주소·외부 서비스에서 주소 위치 자료를 가져오거나(2.1) 행안부 승인키 입력. 그동안은 주소를 직접 적고 지도에서 위치 지정 |
| 행안부 결과를 골랐는데 "이 PC 주소 위치 자료에 없는 주소" | 새로 생긴 건물이거나 자료가 오래됨 → 지도에서 위치 지정. 주소 위치 자료를 최신으로 바꾸면(2.1) 찾을 수 있음. 자주 나오면 좌표 승인키(선택)를 넣는 것도 방법 |
| 위치를 못 찾음 | 도로명·건물번호·지번 확인(도로명 앞부분만 적으면 맞는 도로를 알려 줌 → 고르고 번호 이어 적기), 지도에서 직접 지정. 주소 자료 위치는 건물 출입구 기준 |
| 관리자 비밀번호 분실 | 이 PC의 업무용 Windows 계정으로 로그인해 `python pc/pc_tool.py reset-admin`(변경 이력에 남음). 이 계정에 로그인할 수 있는 사람은 누구나 할 수 있으므로 계정을 담당자 전용으로 |

## 6. 백업과 복구

- **자동 백업 준비(처음 한 번, 운영 관리자 + 키 보관자)**: 설정 → 백업 → 백업 비밀번호(12자 이상)를 넣고 [백업 키 만들기] → **개인키 파일(.pem)은 이때 한 번만 내려받을 수 있습니다.** 승인된 오프라인 매체 2곳에 보관하고, 비밀번호는 개인키와 다른 사람이 따로 보관합니다. PC에는 공개키만 남습니다
- 자동 백업은 PC 프로그램이 켜져 있는 동안 정한 시각(기본 18:00)에 하루 1회(늦게 켜졌으면 켜자마자), 그리고 팀장 마감 확인 때 만들어집니다. 두 번째 저장 위치를 정하면 복사 후 대조합니다. 백업 중에는 화면이 잠시 느릴 수 있습니다
- 보관: 자동 백업은 최근 14일(하루 1개)·최근 3개월(달마다 1개), 수동·자동 모두 90일 지나면 정리(설정에서 변경). 예전 백업에는 그때의 개인정보가 들어 있으므로 이 기간을 지킵니다
- 수동 백업: 설정 → [지금 백업] → 오른쪽 아래 진행 띠가 "끝"이 되면 파일 이름·크기가 나옴 → [열어 확인]. [지금 자동 백업]·[보관 기간 지난 백업 정리]도 같은 진행 띠로 끝을 알림(v0.13). 명령은 `python pc/pc_tool.py backup`(또는 `backup-auto`)
- 복구(업무 화면을 끄고):
  - 수동 백업: `python pc/pc_tool.py restore <파일.dgbak>`
  - 자동 백업: `python pc/pc_tool.py restore-auto <파일.dgabk> --key <개인키.pem>` → 개인키 보호 비밀번호 입력
  - 기존 DB는 지우지 않고 옆에 보관됩니다. 키 저장소를 쓸 수 없는 PC에서 DB 비밀번호를 손으로 넣을 때 지금 DB와 맞지 않으면 복원하지 않고 멈춥니다(틀린 키로 바꿔 넣지 않음). 분기 1회는 별도 PC에서 복원 시험
- 휴대폰 단독 방식은 휴대폰 [백업·복원]으로 매일 백업(24시간 지나면 경고)
- 옛 버전(v0.12 이하) 백업을 v0.13 프로그램에서 복원하면, 복원한 DB를 처음 열 때 아래 6.1의 DB 구조 바꾸기(사전 사본 포함)가 자동으로 일어납니다

### 6.1 PC 프로그램 업데이트 때 (v0.13부터)

절차는 [배포·운영 4장](배포·운영.md)(먼저 백업 → 멈춤 → `state/` 복사 → 코드 바꾸기 → 시작)을 따릅니다. v0.13에서 달라진 점:

- **자동 사전 백업**: 새 프로그램이 기존 DB를 처음 열 때, DB 구조를 바꾸기 전에 `pc/state/pre-migration/pc-v{이전}-to-v{새}-<날짜-시각>.db`(v0.12 이하 DB는 보통 `pc-v0-to-v3-…`, v0.13 시험판 DB는 `pc-v2-to-v3-…`)로 DB 파일을 그대로 복사해 둡니다(같은 DB 키로 암호화, 개인정보 포함). 구조 변경은 단계마다 한 번에 하고, 중간에 멈추면 그 단계가 통째로 되돌려져 다음 시작 때 다시 합니다. 그래도 **업데이트 전 수동 백업과 `state/` 복사는 그대로** 합니다
- **새 DB는 옛 프로그램으로 열리지 않음**: 프로그램보다 새 구조의 DB를 만나면 "DB 구조 버전(N)이 이 프로그램(M)보다 새것입니다"를 내고 멈춥니다(자료 보호). 옛 버전으로 되돌릴 때는 옛 코드와 함께 **업데이트 전 백업**(또는 배포·운영 4.2의 3번에서 복사한 `state/`)으로 복원합니다. v0.12 이하 프로그램에는 이 검사가 없으므로, v0.13으로 연 DB를 옛 프로그램으로 직접 열지 마세요
- 업데이트 뒤 확인: 사용자·이력 → **진단** 카드의 DB 구조 버전이 8, 오늘 현황에 예약 작업 경고 띠가 없는지(처음 하루는 "기록 없음"이 뜰 수 있음 — 02:30 뒤 예약 작업이 한 번 돌면 사라짐), 운영 준비 점검
- v0.12 이하에서 만든 DB는 사진·파기 뒤 빈 공간을 저절로 돌려주지 않습니다. DB 파일이 크면 업무 시간 밖에 서버를 끄고 `python pc/pc_tool.py vacuum`을 한 번(큰 DB는 몇 분) — 그 뒤로는 조금씩 저절로 줄어듭니다
- `pre-migration/` 사본(개인정보 포함)은 매일 예약 작업이 정리합니다: **가장 새 사본 1개는 늘 남기고**, 나머지는 새것부터 3개 안이면서 만든 지 30일 이내인 것만 남깁니다(지우면 변경 이력에 `backup / pre-migration PURGE`). 남은 개수·크기는 진단 카드의 "업데이트 사본". 업데이트가 잘 된 것을 확인했고 마지막 사본도 필요 없으면 서버를 멈춘 뒤 직접 지워도 됩니다

## 7. 보안 수칙

- PC 화면은 기본으로 이 PC 안에서만 열립니다. 원격 접속·공유 폴더에 DB를 두지 마세요. LAN 모드는 승인받은 경우에만
- 개인정보가 담긴 파일은 결과·사진 파일(암호화)뿐이며, 승인된 경로(업무 메일·보안 매체)로만 옮깁니다. 개인 메일·메신저·공용 클라우드 금지
- 출력물(접수증·배출 표지·배차표)과 내보내기는 접속기록에 남습니다. 배차표는 업무 후 파쇄
- 메모·하차 메모·충돌 사유·민원 내용에 불필요한 개인정보를 적지 마세요
- 감면·환불에 주민등록번호·증명번호·계좌번호를 적지 마세요
- 계정은 사람마다 따로, 공유 금지. 퇴직·전보 시 즉시 [중지]
- 외부로 나가는 요청: 바탕 지도 조각(넓은 범위), 휴대폰 주소 검색의 검색어·승인키(행정안전부), 휴대폰 지도 앱에 좌표와 "N번 수거지". **이름·연락처는 어디로도 나가지 않습니다.** 주소 검색칸에 이름·연락처를 적지 마세요(적으면 보내지 않음)
- 서버 로그(`pc/state/logs/server.log`)에는 경로 틀(ID 가림)·상태·사용자 아이디만 남습니다. 점검 때 개인정보가 보이면 개발 담당에 알립니다
- 자동 백업 개인키와 그 비밀번호는 서로 다른 사람이 보관하고, PC에 두지 않습니다
- 업데이트 때 생기는 `state/pre-migration/` DB 사본과 복원할 때 옆에 남는 `state/pc.db.before-restore-*`에도 그때의 개인정보가 들어 있습니다(둘 다 같은 규칙으로 매일 정리). 자료 폴더 밖으로 옮기지 마세요(30일·3개를 넘은 사본은 매일 예약 작업이 지우고, 가장 새 1개만 남음)
- 주민 안내 문구([안내 문구 복사])에는 이름·연락처·주소가 없지만, 보낼 때 받는 사람(연락처)을 잘못 고르지 않게 확인합니다
